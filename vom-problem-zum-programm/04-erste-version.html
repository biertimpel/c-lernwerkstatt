Eine erste vollständige Version bauen

Die erste Version soll klein sein, aber einen vollständigen Weg von der Eingabe bis zum Ergebnis bieten.

1. Ihre Planung umsetzen

Implementieren Sie Version 1 entsprechend Ihrer eigenen Anforderungen, Entwurfsskizze und Schnittstellen. Eine einzelne Messung muss von der Eingabe bis zur Gültigkeitsmeldung verarbeitet werden. Eine Statistik oder ein gewünschter Temperaturbereich gehören noch nicht dazu.

Entscheiden Sie selbst, in welchen Etappen Sie vorgehen. Notieren Sie vor jedem neuen Teil, woran Sie erkennen werden, dass er funktioniert. Sie können einen fachlichen Baustein zuerst mit festen Werten prüfen; stellen Sie anschließend aber auch den vollständigen Ablauf her.

Wenn sich eine Schnittstelle beim Implementieren als unpassend erweist, ändern Sie Ihren Plan bewusst. Notieren Sie den Grund und passen Sie betroffene Aufrufe und Tests an. Plan und Code müssen nicht von Anfang an perfekt sein, sollten aber denselben aktuellen Stand beschreiben.

Verwenden Sie keine komplette Musterlösung. Falls Sie feststecken, beschreiben Sie der Betreuung das gewünschte Verhalten, Ihren bisherigen Ansatz und die erste konkrete Unklarheit.

2. Technische Starthilfe

Startmaterial herunterladen (ZIP). Das Archiv enthält eine leere programm.c, ein fertiges Makefile und einen Eingabebaustein. Es gibt keine vorbereiteten fachlichen Funktionen oder Lücken, in die nur Vergleichsausdrücke eingesetzt werden müssen.

Entpacken Sie das Archiv und öffnen Sie dort ein Terminal. Ihre eigene Implementierung entsteht in programm.c; verwenden Sie nach dem Speichern:

make
./programm

Für Version 1 geben Sie eine ganze Zahl ein und bestätigen mit Enter. Beenden Sie einen Eingabestrom im Terminal unter Linux/macOS bei Bedarf mit Ctrl+D. Die technische Eingabevereinbarung lautet: eine ganze Zahl pro Zeile. Leerraum um die Zahl ist erlaubt, weitere Zeichen oder mehrere Zahlen in derselben Zeile nicht.

Den bereitgestellten Eingabebaustein verwenden

programm.c bindet bereits eingabe.h ein. Der Aufruf lese_ganzzahl() liefert ein int aus der nächsten Eingabezeile zurück. Sie können ihn einer selbst gewählten Variable zuweisen oder in einem eigenen Eingabebaustein kapseln.

Die Funktion bewertet keine Temperatur: Auch 99 wird als Zahl geliefert. Fehlt eine Zeile, ist sie zu lang, enthält sie keine einzelne ganze Zahl oder liegt die Zahl außerhalb des int-Bereichs, meldet die Funktion den technischen Fehler und beendet das Programm mit Status 1. Diese Vereinbarung ist absichtlich fest vorgegeben, damit Textverarbeitung nicht Ihre Entwurfsaufgabe verdrängt.

Das Makefile verbindet Ihre Datei mit eingabe.c. Für die Verwendung müssen Sie dessen interne Arrays, Pointer und Headertechnik noch nicht verstehen. Die Dateien sind Infrastruktur, keine Vorlage für die Zerlegung Ihres fachlichen Programms. Ihre eigenen Funktionen können zunächst vollständig in programm.c stehen.

3. Die erste Version nachweisen

Führen Sie Ihre zuvor notierten Tests durch. Prüfen Sie nicht nur, ob das Programm startet: Stimmen Wert, fachliches Urteil und Rückgabestatus? Kontrollieren Sie den Status unmittelbar nach dem Lauf mit echo $?.

Dokumentieren Sie Ihr Ausgabeformat. Die Aufgaben schreiben keine exakte Zeichenfolge vor; das Ergebnis muss für eine andere Person eindeutig lesbar sein. Beachten Sie weiterhin: Eine fachlich ungültige Zahl ist ein behandelter Fall mit Status 0. Ein technischer Eingabefehler führt zu Status 1.

Selbstkontrolle: Verhalten statt Funktionsnamen vergleichen

−40 und 80 sind gültig, −41 und 81 ungültig. Eine Eingabe wie abc darf nicht als Temperatur 0 weiterverarbeitet werden. Ihre Regeln funktionieren sowohl über den vollständigen Ablauf als auch bei gezielten Tests Ihrer selbst gewählten fachlichen Bausteine.

Lesen und bearbeiten Sie Compilerwarnungen. Verwenden Sie bei Abweichungen gezielte Diagnoseausgaben, entfernen oder kennzeichnen Sie diese aber vor dem abschließenden Vergleich. Sichern Sie den funktionierenden Stand, bevor Sie die nächste Erweiterung beginnen.

Ihr Ergebnis: Eine ausführbare Version 1, Tests mit tatsächlichen und erwarteten Ergebnissen sowie gegebenenfalls begründete Änderungen Ihres Entwurfs. Noch nicht alle späteren Anforderungen müssen implementiert sein.
