Eine Textdatei Zeile für Zeile lesen

Mit fgets eine Datei zeilenweise lesen, Zeilen zählen und Kommentare überspringen.

1. fgets nachschlagen

Eine Config besteht aus Zeilen, und jede Zeile ist eine eigene Angabe. Deshalb liest Ihr Programm die Datei Zeile für Zeile. Dafür gibt es die Funktion fgets. Schlagen Sie sie nach, wie im Kapitel „Manpages und Bibliotheksdokumentation“, und notieren Sie:

  1. In welcher Header-Datei steht die Funktion?
  2. Welche drei Parameter erhält sie?
  3. Wie viele Zeichen schreibt sie höchstens in das Array? Steht das Zeilenende '\n' mit darin?
  4. Was liefert sie, wenn das Dateiende erreicht ist oder ein Fehler auftritt?
Selbstkontrolle: Ihre Notizen

fgets steht in <stdio.h>. Sie erhält das Zeichen-Array, seine Größe in Bytes und die geöffnete Datei als FILE *. Sie liest höchstens Größe minus 1 Zeichen und hängt immer '\0' an. Sie hört am Zeilenende auf; das '\n' steht dann mit im Array. Ist die Zeile länger, liest sie nur den Anfang, und der Rest kommt beim nächsten Aufruf. Am Dateiende oder bei einem Fehler liefert sie NULL; welcher der beiden Fälle vorliegt, verraten feof und ferror.

2. Versuche mit wecker.txt

Im Startmaterial liegt die kleine Datei wecker.txt:

# Weckzeit für die Versuche auf den Seiten 1 und 2
stunde = 6

minute = 45

Diese Schleife liest sie Zeile für Zeile und gibt jede Zeile mit ihrer Nummer aus:

FILE *datei = fopen("wecker.txt", "r");
if (datei == NULL) {
    printf("wecker.txt nicht gefunden.\n");
    return 0;
}
char zeile[82];
int nummer = 0;
while (fgets(zeile, sizeof(zeile), datei) != NULL) {
    nummer++;
    printf("%d: %s", nummer, zeile);
}
fclose(datei);

Probieren Sie die Schleife in text_ausgeben aus. Starten Sie das Programm in dem Ordner, in dem wecker.txt liegt. Notieren Sie vor jedem Schritt, was Sie erwarten.

  1. Warum steht im printf kein \n? Was passiert mit der letzten Zeile, wenn die Datei nicht mit einem Zeilenende aufhört?
  2. Ändern Sie die Schleife so, dass Leerzeilen und Kommentarzeilen nicht ausgegeben werden. Ein Kommentar beginnt mit #, davor dürfen Leerzeichen stehen. Die Zeilennummern sollen trotzdem zur Datei passen.
  3. Verkleinern Sie das Array auf 8 Zeichen. Was ändert sich an der Ausgabe und an den Zeilennummern? Woran könnte Ihr Programm erkennen, dass eine Zeile nicht ganz in das Array gepasst hat?
  4. Benennen Sie wecker.txt vorübergehend um. Was passiert?
Hinweis: Leerzeilen und Kommentare erkennen

Überspringen Sie am Anfang der Zeile zuerst alle Leerzeichen und Tabulatoren. Welches Zeichen steht dann an der ersten Stelle, wenn die Zeile leer ist? Für Leerraum gibt es in <ctype.h> die Funktion isspace; sie zählt auch '\n' dazu.

Selbstkontrolle: Ihre Beobachtungen
  1. Das '\n' steht schon in zeile. Fehlt es in der letzten Zeile, endet die Ausgabe ohne Zeilenumbruch.
  2. Ausgegeben werden nur noch 2: stunde = 6 und 4: minute = 45. Die Nummer zählt jede gelesene Zeile, auch übersprungene.
  3. Mit 8 Zeichen liest fgets höchstens 7 Zeichen auf einmal. Längere Zeilen kommen in mehreren Stücken, und jedes Stück bekommt eine eigene Nummer. Die Nummern passen dann nicht mehr zur Datei. Erkennen lässt sich das daran, dass im Array kein '\n' steht, obwohl das Dateiende noch nicht erreicht ist.
  4. fopen liefert NULL, das Programm meldet „wecker.txt nicht gefunden.“ und liest nichts.
Welche Aussagen zu fgets stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die erste und die dritte Aussage stimmen. Der Rest einer zu langen Zeile geht nicht verloren, er kommt beim nächsten Aufruf. In 82 Zeichen passen 80 sichtbare Zeichen, das '\n' und das abschließende '\0'.

Ihr Ergebnis: Ihre Notizen zu fgets und eine Schleife, die eine Datei zeilenweise liest, Zeilen zählt und Leerzeilen und Kommentare überspringt.
