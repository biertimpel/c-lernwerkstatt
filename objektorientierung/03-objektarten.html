Objektarten mit Methoden

Daten und Verhalten einer Art in einer Struktur bündeln und Objekte über eine gemeinsame Schnittstelle ansprechen.

1. Art und Objekt

Im Spiel gibt es eine Tür, einen Tresor und, auf Seite 5, zwei Münzen. Die beiden Münzen sind zwei verschiedene Objekte: Jede hat ihre eigene Position und liegt oder liegt nicht. Sie gehören aber zur selben Art: Sie heißen gleich, sehen gleich aus und verhalten sich gleich. Man nennt ein einzelnes Objekt auch eine Instanz seiner Art.

Diese Trennung lässt sich in C direkt abbilden:

  • Eine Struktur für die Art enthält, was alle Objekte dieser Art gemeinsam haben: Name, Aussehen und Verhalten. Das Verhalten steht als Funktionspointer darin. Solche Funktionen nennt man Methoden. Jede Art gibt es genau einmal.
  • Eine Struktur für das Objekt enthält, was jedes Objekt für sich hat, und einen Pointer auf seine Art.
  • Wer ein Objekt benutzt, ruft die Methode über diesen Pointer auf und muss die Art nicht kennen.

Ein kleines Beispiel außerhalb des Spiels: Geräte, die man einschalten kann.

typedef struct Geraet Geraet;      /* den Namen schon bekannt machen */

typedef struct {
    const char *name;
    void (*einschalten)(Geraet *selbst);   /* Methode */
} Geraeteart;

struct Geraet {
    const Geraeteart *art;          /* auf welche Art zeigt dieses Gerät? */
    int zaehler;                    /* eigene Daten jedes Geräts */
};

static void lampe_einschalten(Geraet *selbst) {
    selbst->zaehler = 100;
    printf("Lampe leuchtet mit %d Prozent\n", selbst->zaehler);
}

static void klingel_einschalten(Geraet *selbst) {
    selbst->zaehler++;
    printf("Klingel laeutet zum %d. Mal\n", selbst->zaehler);
}

static const Geraeteart LAMPE = {"Lampe", lampe_einschalten};
static const Geraeteart KLINGEL = {"Klingel", klingel_einschalten};

/* in einer Funktion: */
Geraet geraete[] = {{&LAMPE, 0}, {&KLINGEL, 0}, {&KLINGEL, 5}};
for (size_t i = 0; i < 3; i++) {
    geraete[i].art->einschalten(&geraete[i]);
}
geraete[1].art->einschalten(&geraete[1]);

Einige Einzelheiten:

  • typedef struct Geraet Geraet; macht den Namen bekannt, bevor die Struktur vollständig beschrieben ist. Die Art braucht ihn schon für den Parameter ihrer Methode, das Gerät braucht umgekehrt die Art. Einen Strukturnamen hinter struct kennen Sie vom Eintrag der Liste aus dem Kapitel „Dynamischer Speicher und Listen“.
  • Jede Methode bekommt das Objekt, für das sie aufgerufen wird, als Parameter. Hier heißt er selbst. Über ihn erreicht die Methode die Daten genau dieses Objekts.
  • Die Arten sind static const: Es gibt jede nur einmal in dieser Datei, und niemand kann sie verändern. Auch die Methoden sind static; erreichbar sind sie nur über die Art. Das ist eine Form von Kapselung.

Hinweis: Eine Frage, die immer hilft

Fragen Sie bei jeder Eigenschaft: Kann sie für zwei Objekte derselben Art verschieden sein? Zwei Münzen können an verschiedenen Orten liegen. Zwei Türen könnten eine offen und eine geschlossen sein. Was für alle Objekte einer Art immer gleich ist, gehört zur Art.

Das Aussehen hängt teilweise vom Zustand ab: Eine offene Tür sieht anders aus als eine geschlossene. Die Art kann deshalb zwei Zeichen und zwei Piktogramme haben, oder eine Methode, die anhand des Objekts das passende liefert. Beides ist vertretbar. Ob die Figur ein Feld betreten darf, ist für alle Türen dieselbe Regel; das Ergebnis hängt aber davon ab, ob diese Tür offen ist. Selbstkontrolle: Mögliche Methoden

Zwei Stellen verlangen echtes Verhalten, das je nach Art anders ist: die Leertaste (aufnehmen, Tür mit Schlüssel öffnen, Beute aus dem Tresor nehmen) und die Bewegung (eine geschlossene Tür versperrt das Feld). Das Aussehen ist meist nur eine Angabe und kein Verhalten. Aufnehmen und Ablegen funktionieren für alle Gegenstände gleich; sie brauchen keine eigene Methode je Art, sondern nur die Angabe, dass ein Objekt ins Inventar kann.

Welche Aussagen zu Art und Objekt stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Richtig sind die erste, dritte und fünfte Aussage. Eine Art kann beliebig viele Objekte haben. Die Art kennt ihre Objekte nicht; welches Objekt gemeint ist, erfährt die Methode nur über ihren Parameter.

Vertiefung: Eigene Daten je Art durch Einbettung

In diesem Kapitel genügt eine gemeinsame Struktur für alle Objekte, auch wenn einzelne Felder nur für manche Arten Bedeutung haben, etwa „offen“ nur für Türen. Bei vielen Arten mit sehr verschiedenen Daten wird das unübersichtlich. Eine Alternative ist die Einbettung: Eine Struktur für eine bestimmte Art enthält als erstes Feld die gemeinsame Objektstruktur und danach ihre eigenen Felder.

typedef struct {
    Objekt basis;     /* muss das erste Feld sein */
    int code;         /* nur für diese Art */
} Zahlenschloss;

Ein Pointer auf ein Zahlenschloss lässt sich dann als Pointer auf ein Objekt weitergeben, weil C garantiert, dass das erste Feld am Anfang der Struktur liegt. Die Methode des Zahlenschlosses wandelt ihren Parameter zurück in einen Pointer auf Zahlenschloss. Das ist nur dann richtig, wenn das Objekt tatsächlich ein Zahlenschloss ist; sonst greift die Methode auf Speicher zu, der ihr nicht gehört. Diese Technik ist die Grundlage der Vererbung in Sprachen wie C++. Sie ist für Ihr Projekt nützlich, aber im Tresorraub nicht nötig.

Ihr Ergebnis: Sie können erklären, wie Art, Objekt und Methode zusammenhängen, und haben eine Aufteilung der Eigenschaften des Tresorraubs auf Art und Objekt.
