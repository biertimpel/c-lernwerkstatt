Funktionen als Werte

Mit Funktionspointern speichern, welche Funktion später aufgerufen werden soll.

1. Ein Pointer auf eine Funktion

Auch eine Funktion liegt im Speicher, im Bereich für den Programmcode, den Sie im Kapitel „Dynamischer Speicher und Listen“ kennengelernt haben. Sie hat also eine Adresse, und diese Adresse lässt sich in einer Variablen speichern. Über diese Variable können Sie die Funktion später aufrufen. Das Programm entscheidet dann zur Laufzeit, welche Funktion es aufruft.

int plus(int a, int b) { return a + b; }
int minus(int a, int b) { return a - b; }

int (*rechnung)(int a, int b);   /* Pointer auf eine Funktion mit zwei int, Ergebnis int */

rechnung = plus;                 /* ohne (): die Funktion selbst, nicht ihr Ergebnis */
printf("%d\n", rechnung(7, 2));
rechnung = minus;
printf("%d\n", rechnung(7, 2));

Lesen Sie die Deklaration von innen nach außen: rechnung ist ein Pointer (*rechnung) auf eine Funktion mit den Parametern (int a, int b), die int liefert. Die Klammern um *rechnung sind nötig. Ohne sie hieße die Zeile: eine Funktion rechnung, die einen int * liefert.

Weil diese Schreibweise schwer zu lesen ist, gibt man dem Typ meist mit typedef einen Namen:

typedef int (*Rechnung)(int a, int b);

Rechnung r = plus;

Probieren Sie in text_ausgeben aus. Notieren Sie vor jedem Schritt Ihre Erwartung.

  1. Übernehmen Sie das Beispiel. Was wird ausgegeben?
  2. Legen Sie ein Array Rechnung tabelle[] = {plus, minus}; an und rufen Sie beide Einträge in einer Schleife mit denselben Zahlen auf.
  3. Schreiben Sie versehentlich Rechnung r = plus(7, 2);. Was meldet der Compiler?
  4. Schreiben Sie eine Funktion double halb(double x) und weisen Sie sie r zu. Was meldet der Compiler?
  5. Was würde ein Aufruf über einen Funktionspointer bewirken, der NULL ist? Führen Sie diesen Versuch nicht aus, sondern überlegen Sie, wie Sie sich davor schützen.
Selbstkontrolle: Ihre Beobachtungen
  1. 9 und 5. Derselbe Aufruf rechnung(7, 2) führt je nach gespeicherter Adresse andere Funktionen aus.
  2. Die Schleife ruft nacheinander plus und minus auf. Ein Array von Funktionspointern ist eine Tabelle von Verhalten.
  3. Hier wird plus aufgerufen, und das Ergebnis 9 ist ein int, keine Funktion. GCC warnt makes pointer from integer without a cast [-Wint-conversion], Clang meldet einen Fehler.
  4. Die Signatur passt nicht. GCC warnt from incompatible pointer type, Clang meldet einen Fehler. Nur Funktionen mit genau passenden Parametern und passendem Ergebnis gehören in einen Funktionspointer.
  5. Das ist undefiniertes Verhalten, meist stürzt das Programm ab. Prüfen Sie einen Funktionspointer, der NULL sein darf, vor dem Aufruf, wie jeden anderen Pointer.

2. Funktionspointer im Spiel: die Piktogramme

Öffnen Sie piktogramme/piktogramme.h. Alle Funktionen, die ein Piktogramm zeichnen, haben dieselbe Signatur: Renderer, x, y und Skalierung, Ergebnis int. Sie passen also alle in denselben Funktionspointertyp.

  1. Legen Sie in tresorraub.c mit typedef einen Typ für einen Pointer auf eine solche Zeichenfunktion an.
  2. Zeichnen Sie probeweise in zeichne eine Reihe aus Schlüssel, Münze und Beute über dem Spielfeld, mit einem Array dieses Typs und einer Schleife. Ein Fehler beim Zeichnen soll wie bisher sofort zurückgegeben werden.
  3. Vergleichen Sie Ihre Schleife mit dem Zeichnen des Inventars in zeichne. Welche Fallunterscheidung ließe sich mit einem Funktionspointer einsparen, wenn jeder Eintrag sein Piktogramm schon kennen würde?
Hinweis: Wohin in y?

Das Spielfeld beginnt bei RAND_OBEN. Ein Piktogramm ist FELDGROESSE Pixel hoch. Über dem Spielfeld ist Platz, wenn die Reihe bei einem kleineren y beginnt.

Selbstkontrolle: Was Sie gesehen haben

Die Schleife ruft für jeden Eintrag des Arrays dieselbe Zeile auf und zeichnet trotzdem drei verschiedene Bilder. Das Inventar entscheidet dagegen bisher mit strcmp anhand des Namens, welche Funktion es aufruft. Würde jeder Eintrag einen Pointer auf seine Zeichenfunktion mitbringen, entfiele diese Kette. Entfernen Sie den Versuch danach wieder; der Vergleichslauf aus Seite 1 sollte wieder dasselbe zeigen wie vorher.

Gegeben ist typedef int (*Piktogramm)(SDL_Renderer *renderer, int x, int y, int skalierung);. Welche Zeilen sind richtig?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Richtig sind die erste, dritte und vierte Zeile. Die zweite ruft die Funktion auf und speichert ihr int-Ergebnis. zeichne_galerie erhält nur den Renderer und passt deshalb nicht zum Typ.

Ihr Ergebnis: Sie können Funktionspointer deklarieren, mit typedef benennen, zuweisen und aufrufen, und Sie haben einen Typ für die Zeichenfunktionen der Piktogramme.
