Lernstandscheck II – Licht aus

Erweitern Sie Ihren Tresorraub um einen Lichtschalter. Damit kann die Spielfigur vorübergehend das Licht ausschalten und an den Wächtern vorbeikommen. Anschließend geht das Licht automatisch wieder an.

Planen Sie zunächst, welche Daten und Programmteile Sie dafür ergänzen oder verändern müssen. Nutzen Sie die vorhandene Programmstruktur und setzen Sie die Erweiterung in den folgenden Schritten um.

1. Einen Lichtschalter einbauen

Ergänzen Sie einen Lichtschalter als neuen Objekttyp im vorhandenen Objektmodell. Die Spielfigur soll ihn über die bereits verwendete Interaktionsmöglichkeit betätigen können.

Für die Lichtmechanik gelten folgende Regeln.

  • Zu Beginn ist das Licht eingeschaltet. Die Wächter erkennen die Spielfigur nach den bisherigen Regeln.
  • Wird der Schalter betätigt, geht das Licht aus. Solange es ausgeschaltet ist, können die Wächter die Spielfigur nicht erkennen.
  • Der Lichtzustand muss im Spielfenster erkennbar sein. Auch bei ausgeschaltetem Licht soll das Spiel weiterhin bedienbar bleiben.
  • Die übrigen Spielregeln gelten weiterhin.

Für diesen ersten Zwischenstand darf das Licht nach dem Ausschalten dauerhaft ausgeschaltet bleiben.

2. Die Lichtmechanik im Spiel notwendig machen

Verändern Sie die Anordnung des Spielfelds mithilfe der Config. Platzieren Sie den Schlüssel und gegebenenfalls einen Wächter so, dass die Figur das Licht ausschalten muss, um den Schlüssel zu erreichen, ohne entdeckt zu werden.

Achten Sie darauf, dass der Schalter vorher erreichbar ist. Das vollständige Spiel soll mit der neuen Anordnung weiterhin lösbar sein.

Spielen Sie Ihren Entwurf durch und prüfen Sie, ob die Lichtmechanik tatsächlich benötigt wird. Passen Sie die Positionen bei Bedarf an.

3. Das Licht automatisch wieder einschalten

Erweitern Sie die Lichtmechanik um eine begrenzte Dauer. Nach dem Betätigen des Schalters beginnt die Zeit zu laufen. Sobald die Dauer abgelaufen ist, geht das Licht automatisch wieder an.

  • Die Dauer wird in Sekunden über die Config festgelegt.
  • Die Zeit läuft unabhängig von Tastendrücken weiter. Das Licht muss auch dann wieder angehen, wenn die Spielfigur stehen bleibt.
  • Während die Zeit läuft, bleibt das Spiel bedienbar.
  • Bei erneutem Betätigen des Schalters beginnt die eingestellte Dauer von vorn.
  • Sobald das Licht wieder eingeschaltet ist, erkennen die Wächter die Figur wieder. Steht sie dann in einem Erkennungsbereich, gilt die vorhandene Regel für die Entdeckung.
  • Prüfen Sie den eingelesenen Config-Wert. Behandeln Sie unzulässige Einstellungen entsprechend der vorhandenen Fehlerbehandlung.

Probieren Sie unterschiedliche Einstellungen aus. Wählen Sie eine Dauer, mit der Ihr Spiel lösbar bleibt und die begrenzte Dunkelheit eine Rolle bei der Planung des Weges spielt.

Hinweis zur Zeitsteuerung

Stellen Sie sich eine Stoppuhr vor. Beim Start merken Sie sich einen Zeitpunkt. Während das Spiel weiterläuft, prüfen Sie regelmäßig, wie viel Zeit seitdem vergangen ist. Sobald die eingestellte Dauer erreicht ist, führen Sie die gewünschte Aktion aus.

SDL2 bringt dafür SDL_GetTicks64() mit. Der Aufruf liefert die seit der Initialisierung von SDL vergangenen Millisekunden. Dafür benötigen Sie weder einen eigenen Thread noch einen Interrupt oder eine zusätzliche Bibliothek.

Die benötigten Werte merken

Für eine einfache Zeitschaltuhr brauchen Sie den Startzeitpunkt, die gewünschte Dauer und die Information, ob sie gerade läuft. Diese Werte müssen zwischen den Durchläufen der Spielschleife erhalten bleiben. Die folgenden Namen sind Beispiele.

Uint64 start_ms = 0;
Uint64 dauer_ms = 5000;
bool timer_laeuft = false;

Uint64 ist ein von SDL bereitgestellter Typ für nicht negative ganze Zahlen. Er passt zum Rückgabewert von SDL_GetTicks64(). bool kennen Sie aus <stdbool.h>; die SDL-Typen und die Zeitfunktion stehen über <SDL.h> zur Verfügung.

Die 5000 im Beispiel entsprechen fünf Sekunden. Für Ihr Spiel verwenden Sie die Dauer aus der Config. Sekunden rechnen Sie durch Multiplikation mit 1000 in Millisekunden um, beispielsweise mit (Uint64)dauer_sekunden * 1000. Die Umwandlung vor der Multiplikation lässt die Berechnung im größeren Ganzzahltyp stattfinden.

Beim Betätigen starten oder neu starten

start_ms = SDL_GetTicks64();
timer_laeuft = true;

Speichern Sie den Startzeitpunkt beim Betätigen des Schalters. Bei einer erneuten Betätigung wird er durch den neuen Zeitpunkt ersetzt. Setzen Sie ihn nicht bei jeder Zeitprüfung neu, sonst würde die eingestellte Dauer nie erreicht.

Während des Spiels den Ablauf prüfen

if (timer_laeuft
    && SDL_GetTicks64() - start_ms >= dauer_ms) {
    timer_laeuft = false;
    /* Hier die Aktion nach Ablauf ausführen. */
}

Die Differenz aus aktuellem Zeitpunkt und Startzeitpunkt ist die verstrichene Zeit. Verwenden Sie >=, weil die Spielschleife nicht genau in der Millisekunde des Ablaufs prüfen muss.

Diese Prüfung gehört in den regelmäßig ausgeführten Teil der Spiellogik vor der Darstellung. Sie muss bei jedem Durchlauf der Spielschleife erreicht werden, auch ohne Tastendruck. Eine Prüfung ausschließlich in der Tastaturverarbeitung genügt dafür nicht. Nach Ablauf schalten Sie das Licht wieder ein und prüfen die Erkennung durch die Wächter.

Warten Sie die Dauer nicht mit einer eigenen Warteschleife oder einem langen SDL_Delay ab. Das würde die Verarbeitung von Eingaben und die Darstellung in dieser Zeit anhalten. Die Spielschleife soll weiterarbeiten und bei jedem Durchlauf nur kurz prüfen, ob die Zeit bereits abgelaufen ist.

Die Dokumentation von SDL_GetTicks64 enthält die Signatur und die Beschreibung des Rückgabewerts. Die für diese Aufgabe benötigten Schritte stehen vollständig in diesem Hinweis.

Die Erweiterung überprüfen

Überlegen Sie sich geeignete Prüfsituationen für die einzelnen Teile Ihrer Erweiterung. Halten Sie jeweils kurz fest, welches Verhalten Sie erwarten und was Sie tatsächlich beobachten.

Berücksichtigen Sie dabei den Schalter, die Erkennung durch Wächter, das automatische Wiedereinschalten und unterschiedliche Config-Einstellungen. Prüfen Sie außerdem einen vollständigen Spielablauf vom Start bis zur erfolgreichen Flucht.

Halten Sie kurz fest, welche Programmteile Sie verändert haben und wie diese zusammenarbeiten.
