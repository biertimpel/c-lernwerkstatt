Speicher anfordern und freigeben

Mit malloc und free arbeiten und Speicherfehler sichtbar machen.

1. In der Dokumentation nachschlagen

Dynamischen Speicher fordern Sie mit malloc an und geben ihn mit free wieder frei. Beide Funktionen sind neu für Sie. Schlagen Sie sie nach, wie Sie es im Kapitel „Manpages und Bibliotheksdokumentation“ geübt haben. Beide stehen auf derselben Manpage zu malloc. Notieren Sie:

  • In welcher Header-Datei stehen die Funktionen?
  • Was gibt man malloc als Parameter mit, und in welcher Einheit?
  • Was liefert malloc bei Erfolg, was bei einem Fehler?
  • Welchen Inhalt hat der neue Speicher?
  • Was passiert bei free(NULL)? Was gilt für den Speicher nach free?
Selbstkontrolle: Ihre Notizen

Beide Funktionen stehen in <stdlib.h>. malloc erhält die gewünschte Größe in Bytes und liefert einen Pointer auf den neuen Speicher. Kann kein Speicher reserviert werden, liefert sie NULL. Der neue Speicher ist nicht initialisiert, er enthält also unbestimmte Werte. free gibt einen von malloc gelieferten Bereich frei. free(NULL) tut nichts. Nach free darf der Bereich nicht mehr benutzt und nicht ein zweites Mal freigegeben werden.

2. Das Grundmuster

Das folgende Beispiel verwendet den Typ Uhrzeit aus dem Kapitel „Datenstrukturen“. Es zeigt die vier Schritte, die bei dynamischem Speicher immer gleich sind:

Uhrzeit *wecker = malloc(sizeof(*wecker));   /* 1. anfordern */
if (wecker == NULL) {                         /* 2. Erfolg prüfen */
    printf("Kein Speicher mehr frei.\n");
    return -1;
}
wecker->stunde = 6;                           /* 3. benutzen */
wecker->minute = 45;
printf("%d:%02d\n", wecker->stunde, wecker->minute);
free(wecker);                                 /* 4. freigeben */
wecker = NULL;
  • Anfordern: sizeof(*wecker) ist die Größe des Objekts, auf das wecker zeigt. Das funktioniert wie sizeof(zuege[0]) im Kapitel „Datenstrukturen“: Ändern Sie später den Typ von wecker, passt sich die Größe von selbst an.
  • Erfolg prüfen: Erst wenn feststeht, dass malloc nicht NULL geliefert hat, dürfen Sie den Speicher benutzen.
  • Benutzen: Über den Pointer erreichen Sie die Felder mit ->, wie im Kapitel „Pointer und Datenaustausch“.
  • Freigeben: free gibt den Speicher zurück. Danach zeigt wecker zwar noch auf die alte Adresse, aber dort liegt nichts mehr, was Ihnen gehört. Mit wecker = NULL machen Sie das sichtbar.

Probieren Sie das Beispiel in text_ausgeben aus. Übernehmen Sie dafür die Typdefinition von Uhrzeit aus „Datenstrukturen“ in Ihre tresorraub.c, oberhalb von text_ausgeben, und binden Sie <stdlib.h> ein, falls das noch nicht geschehen ist. Fordern Sie danach auf dieselbe Weise ein Array mit fünf int-Werten an, füllen Sie es und geben Sie es wieder frei. Wie berechnen Sie die Größe, die Sie malloc übergeben?

Welche Aussagen zum Grundmuster stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die erste und dritte Aussage stimmen. Der Inhalt von neuem Speicher ist unbestimmt. Nach free ist jeder Zugriff undefiniertes Verhalten, unabhängig davon, was das Programm danach tut.

3. Versuche: Speicherfehler sichtbar machen

Bauen Sie in Ihr Beispiel nacheinander vier typische Fehler ein. Notieren Sie jeweils vorher, was Sie erwarten. Führen Sie jeden Versuch zuerst normal aus und dann mit dem Prüfwerkzeug für Ihr System. Die Befehle stehen in der README des Startmaterials.

  1. Zugriff nach dem Freigeben: Geben Sie wecker->stunde nach free(wecker) aus, ohne wecker = NULL.
  2. Doppelt freigeben: Rufen Sie free(wecker) zweimal hintereinander auf.
  3. Freigeben vergessen: Lassen Sie free(wecker) ganz weg.
  4. Reihenfolge vertauscht: Schreiben Sie wecker = NULL; vor free(wecker); statt danach. Sieht das nach einem Fehler aus?

Entfernen Sie die Fehler danach wieder.

Selbstkontrolle: Was die Werkzeuge melden

Ohne Prüfwerkzeug läuft der erste Versuch oft ohne jede Meldung durch und gibt eine beliebige Zahl aus. Der zweite kann abstürzen oder unauffällig bleiben, der dritte fällt gar nicht auf. Der AddressSanitizer meldet beim ersten Versuch „heap-use-after-free“ und beim zweiten einen „double-free“, jeweils mit der Zeile im Quelltext. Den dritten Fehler meldet unter Linux der LeakSanitizer mit „detected memory leaks“, unter macOS das Werkzeug leaks.

Der vierte Versuch sieht harmlos aus und läuft ohne Absturz und ohne Compilerwarnung. Trotzdem ist es derselbe Fehler wie der dritte: Nach wecker = NULL kennt das Programm die Adresse des Speichers nicht mehr. free(wecker) ist dann free(NULL) und tut nichts. Der Speicher bleibt belegt, und niemand kann ihn mehr freigeben. Das Prüfwerkzeug meldet ein Speicherleck. Merken Sie sich deshalb: Erst freigeben, solange Sie die Adresse noch haben, dann den Pointer auf NULL setzen.

Welche Aussagen zu Speicherfehlern stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die erste und dritte Aussage stimmen. Das Betriebssystem holt den Speicher erst beim Programmende zurück. Bei einem lange laufenden Programm, das immer wieder Speicher anfordert, wächst der Verbrauch bis dahin immer weiter. Ein Zugriff über NULL bricht das Programm in der Regel sofort ab, statt unbemerkt falsche Werte zu liefern.

4. Aufgabe: Einen Inventareintrag anlegen

Das Inventar soll mit dem Spiel mitwachsen und wieder schrumpfen. Statt eines Arrays mit fester Länge bekommt deshalb jeder Gegenstand im Inventar einen eigenen kleinen Speicherblock auf dem Heap. Diesen Block nennen wir einen Eintrag. Er wird angefordert, wenn die Figur den Gegenstand aufnimmt, und freigegeben, wenn der Gegenstand das Inventar wieder verlässt.

Auf dieser Seite schreiben Sie nur das Anlegen eines einzelnen Eintrags. Wie mehrere Einträge zu einem Inventar zusammenhängen, lernen Sie auf Seite 3. Dort bekommt der Eintrag dafür ein weiteres Feld. Für den Anfang genügt der Name des Gegenstands, wie er in INVENTAR.md steht.

  1. Definieren Sie einen Strukturtyp für einen Eintrag. Wie groß wählen Sie das Zeichen-Array für den Namen?
  2. Entwerfen Sie eine Funktion, die zu einem Namen einen neuen Eintrag auf dem Heap anlegt und einen Pointer darauf zurückgibt. Kann sie keinen Eintrag anlegen, liefert sie NULL.
  3. Der Name soll mit snprintf in den Eintrag kopiert werden, wie im Kapitel „Datenstrukturen“. Ist der Name zu lang, liefert die Funktion ebenfalls NULL.
  4. Schreiben Sie in den Vertrag der Funktion, wer den neuen Eintrag später freigeben muss.

Testen Sie in text_ausgeben: einen Eintrag anlegen, ausgeben und freigeben, sowie einen zu langen Namen. Prüfen Sie beide Fälle mit dem Prüfwerkzeug.

Denkhilfe: Der Fehlerpfad bei zu langem Namen

In welcher Reihenfolge passieren malloc und snprintf? Wenn der Name nicht passt, ist der Speicher dann schon angefordert? Wer gibt ihn frei, wenn die Funktion NULL liefert und der Aufrufer deshalb gar keinen Pointer darauf bekommt?

Selbstkontrolle: Erwartete Ergebnisse

Der angelegte Eintrag enthält den Namen, und nach dem Freigeben meldet das Prüfwerkzeug nichts. Bei einem zu langen Namen muss Ihre Funktion den bereits angeforderten Speicher selbst freigeben, bevor sie NULL liefert. Sonst meldet das Prüfwerkzeug ein Speicherleck, denn kein Aufrufer kann diesen Speicher mehr erreichen. Im Vertrag steht: Bei Erfolg besitzt der Aufrufer den Eintrag und muss ihn freigeben. Bei NULL ist nichts freizugeben.
