Eine verkettete Liste

Einzeln angeforderte Einträge über Pointer zu einer Reihe verbinden.

1. Die Idee

Ein Array liegt als ein zusammenhängender Block im Speicher. Seine Größe steht fest, sobald es angelegt ist. Eine verkettete Liste besteht dagegen aus einzelnen Knoten, die jeweils für sich mit malloc angefordert werden. Jeder Knoten enthält seine Daten und einen Pointer auf den nächsten Knoten. Ein Zug aus Waggons ist ein gutes Bild: Jeder Waggon ist an den nächsten gekoppelt.

zug
 │
 ▼
┌────┬───┐    ┌────┬───┐    ┌────┬──────┐
│ 12 │ ●─┼──▶ │  7 │ ●─┼──▶ │ 31 │ NULL │
└────┴───┘    └────┴───┘    └────┴──────┘
  • Die Variable zug zeigt auf den ersten Knoten, den Kopf der Liste.
  • Der Pointer des letzten Knotens ist NULL. Daran erkennt man das Ende.
  • Eine leere Liste hat keinen Knoten. Dann ist schon der Kopf NULL.

Ein Knotentyp enthält einen Pointer auf seinen eigenen Typ. Dafür braucht die Struktur einen Namen hinter struct, wie im Abschnitt „Mit und ohne typedef“ der Seite Strukturen angekündigt:

typedef struct Waggon {
    int nummer;
    struct Waggon *naechster;
} Waggon;

Innerhalb der geschweiften Klammern ist der Name Waggon aus dem typedef noch nicht bekannt, denn er entsteht erst in der letzten Zeile. Deshalb steht dort struct Waggon *.

Auf Papier

Zeichnen Sie wie oben eine leere Liste, eine Liste mit einem Waggon und eine mit zwei Waggons. Zeichnen Sie dann, wie ein neuer Waggon vorne angehängt wird. Welche Pointer ändern sich? In welcher Reihenfolge müssen sie geändert werden, damit kein Waggon verloren geht?

Selbstkontrolle: Vorne anhängen

Zwei Pointer ändern sich: der Pointer des neuen Knotens und der Kopf. Zuerst muss der neue Knoten auf den bisherigen Kopf zeigen. Erst danach darf der Kopf auf den neuen Knoten zeigen. In umgekehrter Reihenfolge ist der Zugang zur bisherigen Liste verloren, sobald der Kopf umgesetzt ist. Bei einer leeren Liste zeigt der neue Knoten auf NULL, und das gleiche Vorgehen funktioniert ohne Sonderfall.

Welche Aussagen zu verketteten Listen stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die ersten beiden Aussagen stimmen. Jeder Knoten wird einzeln angefordert und kann irgendwo auf dem Heap liegen. Nur die Pointer verbinden sie. Der Name aus dem typedef ist erst nach der schließenden Klammer bekannt.

2. Eine Liste durchlaufen

Um alle Knoten zu besuchen, folgen Sie den Pointern vom Kopf bis NULL. Für den Zug sieht das so aus:

for (const Waggon *w = zug; w != NULL; w = w->naechster) {
    printf("Waggon %d\n", w->nummer);
}
  • w beginnt beim Kopf.
  • Die Schleife läuft, solange w auf einen Knoten zeigt. Bei einer leeren Liste läuft sie gar nicht.
  • Nach jedem Durchgang rückt w zum nächsten Knoten vor.
  • Das const zeigt wie im Kapitel „Pointer und Datenaustausch“ an, dass die Schleife die Knoten nur liest.

Überlegen Sie, bevor Sie weiterlesen: Wie würden Sie mit diesem Muster die Waggons zählen? Wie würden Sie prüfen, ob ein Waggon mit einer bestimmten Nummer dabei ist, und wann können Sie die Suche abbrechen?

Welche Aussagen zum Durchlaufen stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die erste und dritte Aussage stimmen. Mit w->naechster != NULL würde der letzte Knoten übersprungen, und bei einer leeren Liste würde schon die erste Prüfung über NULL zugreifen. sizeof kennt nur die Größe eines Pointers oder eines Knotens, nicht die Zahl der Knoten. Die Länge einer Liste muss man zählen.

3. Aufgabe: Gegenstände aufnehmen

Bauen Sie Ihr Inventar als verkettete Liste. Die Regeln stehen in INVENTAR.md.

  1. Erweitern Sie Ihren Eintragstyp von Seite 2 um einen Pointer auf den nächsten Eintrag.
  2. Legen Sie fest, wo der Kopf der Liste gespeichert wird. Eine Möglichkeit ist eine eigene Struktur für das Inventar, die den Kopf enthält.
  3. Entwerfen Sie Funktionen, die die Anzahl der Einträge liefern, prüfen, ob ein Gegenstand im Inventar ist, und das Inventar als Text ausgeben.
  4. Entwerfen Sie eine Funktion, die einen Gegenstand vorne aufnimmt. Sie verwendet Ihre Funktion von Seite 2 und beachtet alle Regeln: kein Gegenstand doppelt, höchstens drei Einträge. Bei Ablehnung und auch dann, wenn kein Speicher zu bekommen ist, bleibt das Inventar unverändert. Ihr Rückgabewert muss diese Fälle unterscheiden. Wie, legen Sie im Vertrag fest.

Die Funktion zum Aufnehmen ändert den Kopf. Sie braucht deshalb Zugriff auf die Variable des Aufrufers, nicht auf eine Kopie. Wie das geht, wissen Sie aus dem Kapitel „Pointer und Datenaustausch“.

Prüfen Sie Ihre Funktionen mindestens mit dieser Folge. Ergänzen Sie die erwarteten Ergebnisse, bevor Sie das Programm ausführen. Für die Regel „höchstens drei Einträge“ brauchen Sie einen vierten Namen. Zum Testen dürfen Sie einen erfundenen verwenden, zum Beispiel Kompass.

Denkhilfe: In welcher Reihenfolge prüfen?

Lohnt es sich, Speicher anzufordern, bevor feststeht, dass der Gegenstand überhaupt aufgenommen werden darf? Was müssten Sie sonst bei einer Ablehnung zusätzlich tun?

Selbstkontrolle: Erwartete Ergebnisse

Zu Beginn ist das Inventar leer. Schlüssel und Beute werden aufgenommen, das Inventar ist dann „Beute, Schluessel“. Der zweite Schlüssel wird abgelehnt, das Inventar bleibt unverändert. Nach der Münze lautet es „Muenze, Beute, Schluessel“. Der Kompass wird abgelehnt, weil das Inventar voll ist. Am Ende enthält es drei Einträge. Das Prüfwerkzeug darf nach dem Programmende noch nicht verbrauchten Speicher melden, solange Sie das Aufräumen von Seite 4 noch nicht geschrieben haben.

Ein neuer Eintrag neu soll vorne in die Liste. Welche Aussagen stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die erste und dritte Aussage stimmen. In der falschen Reihenfolge zeigt neu am Ende auf sich selbst, und die bisherige Liste ist nicht mehr erreichbar. Bei einer leeren Liste ist der bisherige Kopf NULL, der neue Eintrag wird damit automatisch zum letzten Knoten.

Zum Nachdenken: Liste oder drei bool-Werte?

Ihr Spielstand stellt das Inventar bisher mit drei bool-Werten dar, einen je Gegenstand. Für genau drei feste Gegenstände ist das einfacher. Auf Seite 5 ersetzen Sie die drei Werte trotzdem durch Ihre Liste. Überlegen Sie: Was müssten Sie bei beiden Darstellungen ändern, wenn es zwanzig Gegenstandsarten gäbe, ein Gegenstand mehrfach vorkommen dürfte oder die Reihenfolge des Aufnehmens wichtig wäre?
