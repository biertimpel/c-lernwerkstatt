Ein Programm auf Header und Quelldateien verteilen

Einen fertigen Rechner in zwei Quelldateien und einen gemeinsamen Header aufteilen.

1. Eine gemeinsame Schnittstelle

Im Kapitel „Manpages“ haben Sie bereits mit mehreren Dateien gearbeitet: Ihre Funktion zeichne stand in zeichnung.c, aufgerufen wurde sie aber von main in programm.c. Damit das klappt, bindet programm.c die Datei zeichnung.h ein. Auf dieser Seite lernen Sie, wie dieses Zusammenspiel funktioniert, und bauen es selbst.

Eine Funktionsdeklaration macht eine Funktion bekannt. Sie nennt den Rückgabetyp, den Namen und die Parameter und endet mit einem Semikolon:

int addiere(int a, int b);

Die Funktionsdefinition enthält zusätzlich den Funktionskörper, also den Code, der beim Aufruf ausgeführt wird:

int addiere(int a, int b) {
    return a + b;
}

Rückgabetyp, Name und Parametertypen zusammen nennt man die Signatur einer Funktion. Die Signatur von addiere lautet: Rückgabetyp int, Name addiere, zwei Parameter vom Typ int. Wer eine Funktion aufrufen will, muss nur ihre Signatur kennen, nicht ihren Funktionskörper.

Mehrere Quelldateien können dieselbe Funktion verwenden. Damit die Deklaration nur an einer Stelle gepflegt werden muss, steht sie in einer gemeinsamen Header-Datei. C-Header haben üblicherweise die Endung .h.

DateiInhalt
calc.hDeklarationen der Rechenfunktionen
calc.cDefinitionen der Rechenfunktionen
main.cmain, ruft die Funktionen auf und gibt die Ergebnisse aus

Der Header beschreibt die Schnittstelle: Welche Funktionen stehen zur Verfügung, und wie werden sie aufgerufen? Solange die Signatur gleich bleibt, können Sie die Berechnung in calc.c verändern, ohne die Aufrufe in main.c anzupassen. An diese Arbeit mit Schnittstellen knüpft später das Kapitel „Objektorientierung in C“ an.

Welche Aussagen über int addiere(int a, int b); stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die erste und die dritte Aussage stimmen. Die Zeile endet mit einem Semikolon und hat keinen Funktionskörper. Sie macht nur die Signatur bekannt, wie gerechnet wird, steht erst in der Definition. Die Definitionen gehören in calc.c, in den Header gehören die Deklarationen.

2. Einen Header einbinden

Mit der folgenden Anweisung binden Sie Ihren eigenen Header ein:

#include "calc.h"

Vor der eigentlichen Übersetzung verarbeitet der Präprozessor solche Anweisungen. Vereinfacht gesagt fügt er den Inhalt des Headers an dieser Stelle ein. Die Deklarationen sind damit in der Quelldatei bekannt.

Sowohl main.c als auch calc.c binden den Header ein. In main.c prüft der Compiler damit jeden Aufruf gegen die Signatur. In calc.c prüft er, ob die Definitionen zu den Deklarationen passen. Weicht zum Beispiel ein Parametertyp ab, meldet er einen Fehler.

Für eigene Header verwenden Sie Anführungszeichen. Dann sucht der Präprozessor zuerst im Ordner der Quelldatei. Bibliotheksheader kennen Sie mit spitzen Klammern; sie werden in den Verzeichnissen des Systems gesucht:

#include <stdio.h>

stdio.h stellt unter anderem die Deklaration von printf bereit. Die Definition stammt aus der C-Bibliothek, die beim Bauen automatisch dazukommt.

3. Mehrfaches Einbinden verhindern

Ein Header kann während der Übersetzung einer Quelldatei mehrfach eingebunden werden, ohne dass Sie das direkt sehen. Das passiert, wenn ein Header selbst einen anderen Header einbindet. Bindet zum Beispiel statistik.h den Header calc.h ein und main.c beide, dann landet der Inhalt von calc.h zweimal in main.c.

Ein Include-Schutz sorgt dafür, dass der Inhalt eines Headers während der Übersetzung einer Quelldatei nur einmal verarbeitet wird:

#ifndef CALC_H
#define CALC_H

/* Hier stehen die Deklarationen. */

#endif
  • #ifndef CALC_H prüft, ob die Kennzeichnung CALC_H noch nicht definiert ist.
  • #define CALC_H setzt diese Kennzeichnung.
  • #endif beendet den geschützten Abschnitt.

Beim ersten Einbinden ist CALC_H noch unbekannt, der Inhalt wird verarbeitet und die Kennzeichnung gesetzt. Bei jedem weiteren Einbinden in dieselbe Quelldatei wird der Abschnitt übersprungen. Die Kennzeichnung ist keine Variable des laufenden Programms; sie existiert nur, während der Präprozessor eine Quelldatei verarbeitet. Die nächste Quelldatei beginnt deshalb wieder ohne sie und kann den Header ebenfalls einbinden.

Ob doppeltes Einbinden schadet, hängt vom Inhalt ab. Was das bedeutet, probieren Sie nach der Aufgabe aus.

4. Aufgabe: Den Rechner aufteilen

Der kleine Rechner ist bereits vollständig programmiert. Laden Sie das Startmaterial herunter und entpacken Sie es in einen eigenen Arbeitsordner. Es enthält diese main.c:

#include <stdio.h>

int addiere(int a, int b) {
    return a + b;
}

int multipliziere(int a, int b) {
    return a * b;
}

int main(void) {
    int a = 4;
    int b = 7;
    int summe = addiere(a, b);
    int produkt = multipliziere(a, b);

    printf("Summe: %d\n", summe);
    printf("Produkt: %d\n", produkt);

    return 0;
}
  1. Legen Sie im selben Ordner calc.h und calc.c an.
  2. Verschieben Sie die Definitionen von addiere und multipliziere nach calc.c.
  3. Schreiben Sie die passenden Deklarationen in calc.h und ergänzen Sie den Include-Schutz.
  4. Binden Sie calc.h in beiden Quelldateien ein.
  5. Übersetzen und starten Sie das aufgeteilte Programm. Prüfen Sie, ob weiterhin dieselben Ergebnisse ausgegeben werden.
gcc -std=c17 -Wall -Wextra main.c calc.c -o rechner
./rechner

Beide Quelldateien stehen im selben Befehl. -o rechner benennt die erzeugte Programmdatei; unter Windows (MSYS2) heißt sie rechner.exe, Sie starten sie trotzdem mit ./rechner. -std=c17 -Wall -Wextra kennen Sie aus den Makefiles der vorigen Kapitel: Sie legen den C-Standard fest und schalten die wichtigen Warnungen ein. Was beim Bauen genau geschieht, verfolgen Sie auf der nächsten Seite.

Hinweis: Deklaration und Definition zuordnen

Die Deklaration endet nach der Parameterliste mit einem Semikolon. Die Definition enthält zusätzlich den Funktionskörper. Die Berechnungen selbst müssen Sie nicht verändern.

Hinweis: Die Dateien verbinden

Beide Quelldateien verwenden #include "calc.h". Die Definitionen stehen in calc.c, und diese Datei geben Sie im Übersetzungsbefehl an. Binden Sie keine .c-Datei mit #include ein.

Hinweis: Der Compiler kennt eine Funktion nicht

Meldet GCC implicit declaration of function 'addiere' oder Clang call to undeclared function 'addiere', fehlt in dieser Quelldatei die Zeile #include "calc.h". Prüfen Sie auch, ob sie vor dem ersten Aufruf steht.

Selbstkontrolle: Eine mögliche Aufteilung

calc.h

#ifndef CALC_H
#define CALC_H

int addiere(int a, int b);
int multipliziere(int a, int b);

#endif

calc.c

#include "calc.h"

int addiere(int a, int b) {
    return a + b;
}

int multipliziere(int a, int b) {
    return a * b;
}

main.c

#include <stdio.h>
#include "calc.h"

int main(void) {
    int a = 4;
    int b = 7;
    int summe = addiere(a, b);
    int produkt = multipliziere(a, b);

    printf("Summe: %d\n", summe);
    printf("Produkt: %d\n", produkt);

    return 0;
}

Erwartete Ausgabe, wie vor der Aufteilung:

Summe: 11
Produkt: 28

Ihr Ergebnis: Der Rechner besteht aus zwei Quelldateien und einem gemeinsamen Header und liefert dieselben Ergebnisse wie vorher.

5. Versuch: Wann der Include-Schutz nötig ist

Arbeiten Sie mit Ihrer Lösung der Aufgabe. Notieren Sie vor jedem Schritt, was Sie erwarten.

  1. Entfernen Sie in calc.h vorübergehend die drei Zeilen des Include-Schutzes. Schreiben Sie in main.c die Zeile #include "calc.h" ein zweites Mal und übersetzen Sie. Was meldet der Compiler?
  2. Kopieren Sie die folgenden Zeilen in calc.h und übersetzen Sie erneut. Sie legen einen neuen Datentyp Punkt an, der zwei Zahlen zusammenfasst. Solche Strukturen lernen Sie erst im nächsten Kapitel „Datenstrukturen“ kennen. Wie sie funktionieren, müssen Sie hier noch nicht verstehen. Für den Versuch genügt: Diese Zeilen definieren einen Typ, und Typen stehen später oft in Headern. 
    typedef struct {
    int x;
    int y;
} Punkt;
  3. Stellen Sie den Include-Schutz wieder her und übersetzen Sie noch einmal. Entfernen Sie danach die zweite Include-Zeile und die Struktur.
Welche Beobachtungen treffen zu?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die erste, zweite und vierte Aussage stimmen. Dieselbe Funktion darf mehrfach deklariert werden, solange die Signatur gleich ist. Ein Typ darf in einer Quelldatei aber nur einmal definiert werden. GCC meldet conflicting types for 'Punkt', Clang typedef redefinition with different types. Der Include-Schutz wirkt nur innerhalb der Übersetzung einer Quelldatei. calc.c wird getrennt übersetzt und bindet den Header deshalb ganz normal ein.

Verwenden Sie den Include-Schutz deshalb in jedem eigenen Header, auch wenn er zunächst nur Funktionsdeklarationen enthält.
