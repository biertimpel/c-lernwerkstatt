Den Build mit einem Makefile ausführen

Bekannte Übersetzungsbefehle mit make ausführen und die Aufteilung im Spielgerüst wiedererkennen.

1. Befehle und Abhängigkeiten festhalten

Mit mehreren Quelldateien gehören mehrere Befehle zum Bauen. Ein Makefile hält fest, welche Dateien voneinander abhängen und mit welchen Befehlen sie erzeugt werden. Makefiles haben Sie seit Block 1 verwendet; jetzt sehen Sie, wie sie aufgebaut sind.

Eine Regel besteht aus einem Ziel, seinen Voraussetzungen und einem Befehl:

main.o: main.c calc.h
	gcc -c main.c -o main.o

Links vom Doppelpunkt steht das Ziel, rechts davon die Voraussetzungen. Die Befehlszeile darunter muss mit einem Tabulator beginnen, nicht mit Leerzeichen.

make vergleicht die Änderungszeiten der Dateien. Fehlt die Zieldatei oder ist eine Voraussetzung neuer als das Ziel, führt make den Befehl aus. Sonst verwendet es das vorhandene Ziel weiter. Übersetzen und linken müssen weiterhin gcc und der Linker; make entscheidet nur, welche Befehle nötig sind.

2. Aufgabe: Den Rechner mit make bauen

Laden Sie das vorbereitete Makefile in den Ordner Ihres Rechners. Die Datei heißt Makefile, ohne Endung. Ihr Inhalt:

rechner: main.o calc.o
	gcc main.o calc.o -o rechner

main.o: main.c calc.h
	gcc -c main.c -o main.o

calc.o: calc.c calc.h
	gcc -c calc.c -o calc.o

Rufen Sie nur make auf, bearbeitet es das erste Ziel im Makefile, hier rechner. Dafür prüft es zuerst dessen Voraussetzungen, die Objektdateien, und deren Voraussetzungen. Ein anderes Ziel nennen Sie beim Aufruf dahinter: make calc.o erzeugt nur calc.o, falls nötig, und linkt nicht. Nach diesem Muster funktioniert auch make clean, das Ihnen in den Makefiles der Spielkapitel begegnet: clean ist dort ein eigenes Ziel, dessen Befehl die erzeugten Dateien löscht. Das Makefile ist bewusst schlicht gehalten. Die Makefiles der Spielkapitel ergänzen die Warnoptionen über eine Variable CFLAGS.

  1. Ordnen Sie in der Regel für main.o Ziel, Voraussetzungen und Befehl zu.
  2. Entfernen Sie die erzeugten Dateien mit rm main.o calc.o rechner (unter Windows rechner.exe). Führen Sie make und danach ./rechner aus.
  3. Rufen Sie gleich danach erneut make auf. Wird noch einmal übersetzt oder gelinkt?
  4. Ändern Sie in calc.c die Funktion addiere wie unten gezeigt. Die Berechnung bleibt gleich. Rufen Sie make auf und vergleichen Sie die ausgeführten Befehle. 
    int addiere(int a, int b) {
    int ergebnis = a + b;
    return ergebnis;
}
  5. Fügen Sie innerhalb des Include-Schutzes von calc.h einen kurzen Kommentar hinzu, speichern Sie und rufen Sie erneut make auf. Erklären Sie den Unterschied zum vorherigen Durchlauf anhand der Voraussetzungen.
Hinweis: make meldet missing separator

Eine Befehlszeile beginnt mit Leerzeichen statt mit einem Tabulator. Das heruntergeladene Makefile enthält die Tabulatoren bereits. Manche Editoren ersetzen Tabulatoren beim Speichern durch Leerzeichen; prüfen Sie dann die Einstellungen Ihres Editors.

Hinweis: Änderungen verfolgen

Suchen Sie den Namen der geänderten Datei rechts von einem Doppelpunkt. Welche Ziele hängen direkt von ihr ab? Welche weiteren Ziele brauchen wiederum diese Ziele?

Auch ein geänderter Kommentar löst hier einen Build aus. make vergleicht nur Änderungszeiten und eingetragene Abhängigkeiten. Ob sich das Verhalten des Programms geändert hat, beurteilt es nicht.

Selbstkontrolle: Vollständige Lösung des Rechners

Mögliche Lösung herunterladen: Header, beide Quelldateien und Makefile. Vergleichen Sie erst, nachdem Sie die Aufgaben selbst bearbeitet haben.

Sie ändern nur main.c und rufen make auf. Welche Befehle führt make aus?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die erste und die dritte Aussage stimmen. main.c ist Voraussetzung von main.o, also wird main.o neu übersetzt. Weil main.o danach neuer ist als rechner, wird neu gelinkt. calc.o hängt nicht von main.c ab und bleibt, wie es ist.

Ihr Ergebnis: Sie bauen den Rechner mit make und erklären, welche Schritte nach einer Änderung nötig sind.

3. Abschluss: Die Aufteilung im Spielgerüst wiedererkennen

Laden Sie das Spielgerüst herunter und entpacken Sie es. Es ist das Startmaterial des nächsten Kapitels „Datenstrukturen“. Mit demselben Gerüst arbeiten Sie im ganzen Tresorraub-Spiel von Block 2. Für diese Aufgabe genügt das Lesen; orientieren Sie sich an Dateinamen, Include-Anweisungen und Funktionsnamen.

  1. In welcher Datei steht main?
  2. In welcher Datei entwickeln Sie Ihren eigenen Code?
  3. Öffnen Sie tresorraub.h. Welche Funktionen deklariert der Header? Wer ruft sie auf, und wer definiert sie?
  4. Welche Aufgabe hat der Include-Schutz in tresorraub.h, und welche Header bindet tresorraub.h selbst ein?
  5. Woran erkennen Sie im Makefile, welche Quelldateien zum Programm gehören?

Vergleichen Sie die Aufgaben von main.c, calc.c und calc.h mit den entsprechenden Dateien des Spielgerüsts.

Hinweis: Im Spielgerüst orientieren

Suchen Sie nach main, text_ausgeben und zeichne. Im Makefile stehen die Quelldateien in der Variablen QUELLEN. Das Makefile folgt derselben Grundidee wie Ihres, verwendet aber Variablen wie CC und CFLAGS und bindet zusätzlich die SDL2-Bibliothek ein.

DateiAufgabeEntspricht beim Rechner

tresorraub.h deklariert sechs Funktionen: text_ausgeben, spiel_starten, taste_gedrueckt, zeichne, spiel_status und aufraeumen. Das Gerüst in programm.c ruft sie auf, definiert werden sie in tresorraub.c. Der Header bindet SDL.h und stddef.h ein, weil die Signaturen Typen aus diesen Headern verwenden. Der Include-Schutz TRESORRAUB_H verhindert, dass der Inhalt in einer Quelldatei doppelt verarbeitet wird.

tresorraub.h bleibt in allen folgenden Kapiteln gleich. In „Datenstrukturen“ schreiben Sie text_ausgeben und zeichne; die übrigen Funktionen stehen in tresorraub.c zunächst als Platzhalter und kommen in späteren Kapiteln dazu. Die Piktogramme sind eine weitere Quelldatei mit eigenem Header: piktogramme/piktogramme.c und piktogramme/piktogramme.h.
