Vom Quelltext zum ausführbaren Programm

Objektdateien erzeugen, die Arbeit des Linkers verfolgen und den späteren Funktionsaufruf davon unterscheiden.

1. Vom Quelltext zum Programm

Der Präprozessor verarbeitet die eingebundenen Header. Anschließend wird jede Quelldatei übersetzt. Dabei erzeugen Compiler und Assembler eine Objektdatei mit der Endung .o. Sie enthält bereits Maschinencode, Daten und Informationen für das spätere Verbinden.

AusgangspunktZwischenprodukt
main.c mit eingebundenen Deklarationenmain.o
calc.c mit eingebundenen Deklarationencalc.o

Der Linker verbindet die Objektdateien und die benötigten Bibliotheken zum ausführbaren Programm rechner. Ein einzelner Aufruf von gcc kann diese Schritte gemeinsam anstoßen.

2. Was der Linker verbindet

In main.o befindet sich bereits übersetzter Code für den Aufruf von addiere. Die Implementierung der Funktion steht in calc.o. Der Linker ordnet Code und Daten im fertigen Programm an und passt Verweise so an, dass der Aufruf zur passenden Implementierung führt.

Ein gewöhnlicher Funktionsaufruf wechselt auch im fertigen Programm zum Funktionscode und kehrt danach zur Fortsetzung des Aufrufers zurück. Dabei wird keine andere .c-Datei geöffnet. Der Prozessor arbeitet an Stellen im geladenen Programm.

Ein geordneter Programmablauf darf Sprünge enthalten. Das kennen Sie bereits von Schleifen. Die Aufteilung auf Quelldateien organisiert die Erstellung des Programms.

Vereinfachter C-Ausschnitt nur für die Addition. Die Kästen stehen für bereits übersetzten Code, nicht für während der Ausführung geöffnete Quelldateien.

Das Einfügen des Funktionscodes an einer Aufrufstelle heißt Inlining. Es ist eine mögliche Compileroptimierung. Für die Grafik betrachten wir einen gewöhnlichen Aufruf ohne diese Optimierung.

3. Aufgabe B

Verwenden Sie Ihren aufgeteilten Rechner aus Aufgabe A. Arbeiten Sie im Terminal in dessen Ordner.

  1. Übersetzen Sie die beiden Quelldateien einzeln mit den folgenden Befehlen. Prüfen Sie, welche Dateien zusätzlich entstanden sind.
gcc -c main.c -o main.o
gcc -c calc.c -o calc.o

Mit -c endet der Aufruf nach der Herstellung der Objektdatei. Es wird noch kein ausführbares Programm gelinkt. -o benennt die jeweilige Ausgabedatei.

  1. Verbinden Sie die Objektdateien und starten Sie das Programm:
gcc main.o calc.o -o rechner
./rechner
  1. Gehen Sie die Grafik durch. Erklären Sie, welche Schritte vor dem Programmstart stattfinden und welche erst während der Ausführung.
  2. Öffnen Sie main.c und anschließend rechner in einem Texteditor. Schließen Sie beide ohne Änderungen. Mit nano verwenden Sie nacheinander die folgenden Aufrufe und schließen jeweils mit Strg + X.
nano main.c
nano rechner

Wenn Ihr Editor auf eine Binärdatei hinweist und sie nicht als Text öffnet, halten Sie diese Beobachtung fest.

  1. Beantworten Sie: Welche Dateien sind Quelltext, welche Zwischenprodukte und welche das ausführbare Programm? Warum reicht main.o beim Linken nicht aus? Welche Aufgabe hatte calc.h, obwohl die Datei im Link-Befehl nicht vorkommt?

Ihr Ergebnis: Sie können die Dateien und die Schritte zwischen ihnen zuordnen.

4. Warum sieht die Programmdatei im Texteditor merkwürdig aus?

Alle Dateien bestehen aus Bytes. In einer Quelldatei stellen diese Bytes lesbaren Programmtext dar. Eine ausführbare Datei enthält dagegen unter anderem Maschinenbefehle, Daten und Verwaltungsinformationen.

Ein Texteditor versucht, die Bytes als Text zu deuten. Deshalb erscheinen ungewöhnliche Zeichen. Manche Textstücke bleiben lesbar, beispielsweise unsere Ausgabemeldungen. ./rechner startet das Programm. nano rechner öffnet seine Datei als vermeintlichen Text.

5. Variablen über Dateigrenzen: extern und static

Bisher teilen sich Ihre Quelldateien nur Funktionen. Auch eine globale Variable, also eine Variable außerhalb aller Funktionen, kann von mehreren Quelldateien verwendet werden. Dafür gilt dieselbe Unterscheidung wie bei Funktionen:

  • Die Definition legt die Variable an. Sie steht in genau einer Quelldatei, zum Beispiel in calc.c: int anzahl_rechnungen = 0;
  • Die Deklaration sagt nur: Diese Variable gibt es irgendwo im Programm. Dafür steht das Wort extern davor. Die Deklaration gehört in den Header, zum Beispiel in calc.h: extern int anzahl_rechnungen;

Jede Quelldatei, die calc.h einbindet, kann die Variable dann verwenden. Beim Übersetzen von main.c kennt der Compiler nur die Deklaration. Erst der Linker verbindet den Namen mit der einen Definition aus calc.o, genau wie bei einem Funktionsaufruf.

Ausprobieren

Arbeiten Sie in einer Kopie Ihres Rechner-Ordners, damit Ihre Lösung für Aufgabe C unverändert bleibt.

  1. Der Rechner soll zählen, wie viele Rechnungen er ausgeführt hat. Definieren Sie dafür in calc.c die Variable anzahl_rechnungen mit dem Anfangswert 0 und erhöhen Sie sie in addiere und multipliziere um eins. Deklarieren Sie die Variable mit extern in calc.h. Geben Sie ihren Wert am Ende von main aus.
  2. Verschieben Sie die Definition int anzahl_rechnungen = 0; aus calc.c in calc.h und ersetzen Sie damit die extern-Deklaration. Übersetzen Sie erneut. Welcher Schritt meldet einen Fehler, der Compiler oder der Linker? Warum hilft der Include-Schutz hier nicht?
  3. Stellen Sie den Zustand aus Schritt 1 wieder her und löschen Sie nur die Definition in calc.c. Was meldet der Linker jetzt?
Selbstkontrolle: Was Sie beobachten

Schritt 1 gibt zusätzlich Rechnungen: 2 aus.

In Schritt 2 übersetzt der Compiler beide Quelldateien ohne Fehler. Der Linker bricht ab, unter Linux mit multiple definition of `anzahl_rechnungen', unter macOS mit duplicate symbol. Beide Quelldateien binden den Header ein, also enthalten main.o und calc.o jeweils eine eigene Definition. Der Include-Schutz verhindert das nicht, denn er wirkt nur innerhalb der Übersetzung einer einzelnen Quelldatei.

In Schritt 3 meldet der Linker undefined reference to `anzahl_rechnungen' (macOS: Undefined symbols). Die Deklaration verspricht eine Variable, aber keine Objektdatei enthält ihre Definition. Das entspricht einer Funktion, die zwar im Header deklariert, aber nirgends definiert ist.

Merken Sie sich: In einen Header gehören Deklarationen, also extern-Variablen und Funktionsköpfe. Definitionen gehören in eine .c-Datei.

Das Gegenstück: static

Steht static vor einer globalen Variablen, ist sie nur in ihrer eigenen Quelldatei sichtbar. Der Linker verbindet sie mit keiner anderen Datei. Eine andere Quelldatei kann sie nicht verwenden, auch nicht mit einer extern-Deklaration. Zwei Quelldateien dürfen sogar jeweils eine eigene static-Variable mit demselben Namen haben, ohne dass sie sich stören. Dasselbe gilt für Funktionen: Eine static-Funktion ist eine Hilfsfunktion, die nur ihre eigene Datei verwendet. Ihre Deklaration gehört deshalb nicht in den Header.

Globale Variablen, die alle Quelldateien verändern können, machen Fehler schwer auffindbar: Ändert sich ein Wert unerwartet, kommt jede Datei als Ursache infrage. Verwenden Sie deshalb möglichst Parameter und Rückgabewerte. Braucht ein Programmteil einen Zustand, der während des ganzen Programmlaufs erhalten bleibt, legen Sie ihn als static-Variable in der Datei an, die für ihn zuständig ist. Andere Dateien erreichen ihn dann nur über die Funktionen dieser Datei. Im Kapitel „Pointer und Datenaustausch“ legen Sie so den Spielstand des Tresorraub-Spiels an. Mit extern teilen Sie eine Variable nur, wenn mehrere Dateien sie wirklich direkt brauchen.

Hinweise

Beim Linken fehlt eine Funktion

Prüfen Sie, ob Sie beide Objektdateien angegeben haben. Der Header stellte die Deklarationen beim Übersetzen bereit. Die Implementierungen müssen ebenfalls Teil des Programms sein.

Aufruf und Rückkehr unterscheiden

Beim Bauen wird das Ziel des Aufrufs verbunden. Erst beim Ausführen wechselt der Ablauf zur Funktion. Nach der Rückkehr erhält die Variable summe den Rückgabewert.

Was wird wann verbunden?

Der Header wurde bereits bei der Übersetzung verarbeitet. Er stellte die Deklarationen bereit, mit denen der Compiler Aufrufe und Definitionen prüfen konnte. main.o enthält Verweise auf unsere Rechenfunktionen, deren Implementierungen aus calc.o benötigt werden. Der Linker verbindet die Teile. Beim späteren Funktionsaufruf wird zur Funktion und wieder zurück gewechselt.
