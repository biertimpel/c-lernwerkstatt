Werte und Speicheradressen untersuchen

Lesen und schreiben Sie über Pointer und unterscheiden Sie Werte von Adressen.

1. Eine Adresse speichern und benutzen

Eine Variable hat einen Wert und liegt an einer Adresse im Speicher. Mit &var erhalten Sie die Adresse von var. Ein Pointer kann diese Adresse speichern. Man sagt: Der Pointer zeigt auf die Variable. Sie ist sein Ziel.

int var = 10;
int *p = &var;     // p speichert die Adresse von var
int vorher = *p;   // Wert am Ziel lesen
*p = 20;           // Wert am Ziel schreiben

In der Deklaration int *p gehört das Sternchen zum Pointertyp. Im Ausdruck *p bedeutet es: auf das Ziel zugreifen.

Vorhersagen und ausprobieren

Schreiben Sie die Versuche in text_ausgeben und starten Sie mit ./programm --text. Notieren Sie vor jedem Schritt, was Sie erwarten.

  1. Legen Sie int var = 10; und int *p = &var; an. Was zeigen die Ausgaben von var und *p? Geben Sie beide Werte aus. Vergleichen Sie anschließend die Adressen p und &var.
  2. Schreiben Sie *p = 20;. Welchen Wert hat var jetzt? Geben Sie var erneut aus und erklären Sie die Änderung.
Hinweis: Eine Adresse ausgeben

Verwenden Sie printf("%p\n", (void *)p);. Der Platzhalter %p erwartet einen Pointer vom Typ void *. Vergleichen Sie Adressen aus demselben Programmlauf, denn bei jedem Start können sie anders aussehen.

Selbstkontrolle: Werte und Adressen

var und *p liefern beide 10. p und &var ergeben dieselbe Adresse, denn p enthält genau die Adresse von var. Nach *p = 20; hat var den Wert 20: Die Zuweisung über den Pointer schreibt in das Ziel, also in var selbst.

Freiwillige Vertiefung: Ein Pointer auf einen Pointer

Auch p ist eine Variable und hat eine eigene Adresse. Ein weiterer Pointer kann deshalb auf p zeigen: int **pp = &p;. Dann liefert *pp den Pointer p und **pp den Wert von var. Für die weiteren Aufgaben dieses Kapitels brauchen Sie das nicht.

Ergänzen Sie int **pp = &p; und geben Sie **pp aus. Auf welche Variable zeigt pp direkt? Über welche beiden Schritte gelangen Sie zum Wert?

Selbstkontrolle: Pointer auf einen Pointer

pp zeigt direkt auf p. Der erste Schritt *pp führt zu p, der zweite zum Ziel von p, also zu var. Nach *p = 20; liefert **pp deshalb 20.

2. Rückblick: Arrays und Zeichenketten

Im Kapitel „Datenstrukturen“ sind Ihnen zwei Dinge begegnet, die dort noch nicht erklärt wurden. Mit Pointern können Sie beide jetzt verstehen.

Warum eine Funktion die Länge eines Arrays nicht kennt

Erinnern Sie sich an die Seite „Strukturen“: Übergeben Sie einer Funktion eine Struktur, bekommt die Funktion eine Kopie mit allen Feldern. Bei einem Array ist das anders. C kopiert beim Aufruf nicht das ganze Array, sondern übergibt nur die Adresse des ersten Elements. Der Parameter int werte[] sieht zwar aus wie ein Array, ist aber in Wahrheit ein Pointer. Sie könnten genauso int *werte schreiben.

Das erklärt die Beobachtung aus „Datenstrukturen“:

void zeige_groesse(int werte[]) {
    printf("in der Funktion: %zu\n", sizeof(werte));   
}

int zuege[5] = {41, 60, 37, 52, 61};
printf("beim Aufrufer: %zu\n", sizeof(zuege));         
zeige_groesse(zuege);

Probieren Sie das Beispiel in text_ausgeben aus. Was meldet der Compiler? Verlängern Sie danach das Array auf zehn Elemente und vergleichen Sie beide Ausgaben erneut. Kreuzen Sie an, was Sie beobachten.

Welche Beobachtungen treffen zu?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die erste und dritte Aussage stimmen. Beim Aufrufer wächst der Wert mit der Länge des Arrays, in der Funktion nicht. Deshalb liefert die Division in der Funktion nicht die Anzahl der Elemente, sondern auf üblichen Systemen immer 2. Warum das so ist, steht im nächsten Absatz.

Die Erklärung: Beim Aufrufer ist zuege das ganze Array, 5 Elemente zu je 4 Bytes, zusammen 20 Bytes. In der Funktion ist werte dagegen nur ein Pointer. sizeof(werte) misst deshalb die Größe eines Pointers, auf üblichen Systemen 8 Bytes, egal wie lang das Array ist. Die Zahl der Elemente steckt in einem Pointer nicht drin. Darauf weisen auch die Warnungen von GCC und Clang hin.

Die Funktion erfährt die Länge also nur, wenn Sie sie als eigenen Parameter mitgeben, etwa als size_t anzahl. Berechnen Sie sie dort, wo das ganze Array vorliegt: beim Aufrufer.

Weil die Funktion die Adresse des Originals bekommt, gilt außerdem: Mit werte[0] = 99; verändert sie das Array des Aufrufers, nicht eine Kopie. Bei Strukturen ist das, wie Sie wissen, anders. Wie Sie dasselbe für eine Struktur erreichen, lernen Sie auf den nächsten Seiten.

Für Interessierte: Zweidimensionale Arrays übergeben

Auch bei einem zweidimensionalen Array wie dem Grundriss bekommt die Funktion nur die Adresse des Anfangs, hier der ersten Zeile. Um die Zeile y zu finden, muss sie aber wissen, wie lang eine Zeile ist. Deshalb darf im Parameter nur die Zeilenzahl fehlen, die Spaltenzahl muss dastehen: char feld[][BREITE + 1]. Die Zahl der Zeilen geben Sie wie bei einem eindimensionalen Array bei Bedarf als eigenen Parameter mit.

Warum == zwei gleiche Texte für verschieden hält

Im Kapitel „Datenstrukturen“ haben Sie zwei Zeichen-Arrays mit == verglichen. Wiederholen Sie den Versuch jetzt mit Ihrem Wissen über Adressen:

char a[] = "Beute";
char b[] = "Beute";
printf("%d\n", a == b);
printf("%d\n", strcmp(a, b));

Probieren Sie das Beispiel in text_ausgeben aus. Was meldet der Compiler? Geben Sie zusätzlich die Adressen von a und b mit %p aus, wie in Abschnitt 1. Ändern Sie danach den Inhalt von b in "Muenze" und vergleichen Sie erneut. Kreuzen Sie an, was Sie beobachten.

Welche Beobachtungen treffen zu?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die ersten beiden Aussagen stimmen. a == b liefert immer 0, egal was in den Arrays steht. strcmp liefert bei gleichem Inhalt 0 und erst bei verschiedenem Inhalt einen anderen Wert. Warum das so ist, steht im nächsten Absatz.

Die Erklärung: Für Zeichenketten gilt dieselbe Regel wie für Arrays als Parameter. Steht ein Zeichen-Array in einem Vergleich mit ==, verwendet C nicht den Text, sondern die Adresse seines ersten Zeichens.

  • a und b sind zwei getrennte Arrays, also zwei getrennte Speicherbereiche mit verschiedenen Adressen. Dass sie dieselben Zeichen enthalten, spielt für == keine Rolle.
  • a == b vergleicht deshalb nur die beiden Adressen. Die sind immer verschieden, das Ergebnis ist immer 0. Darauf weisen auch die Warnungen von GCC und Clang hin.
  • strcmp(a, b) geht dagegen Zeichen für Zeichen bis zum Nullzeichen vor und vergleicht die Inhalte. Sind sie gleich, liefert die Funktion 0.

Das ist die Erklärung für die Selbstkontrolle „Vergleich mit == und strcmp“ aus „Datenstrukturen“: Dort stand, dass == prüft, ob beide Seiten dieselbe Stelle im Speicher bezeichnen. Diese Stelle ist die Adresse, die Sie gerade mit %p ausgegeben haben.
