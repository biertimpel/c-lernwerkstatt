Einen bestehenden Spielzustand verändern

Schreiben Sie die Spiellogik für einen Schritt der Figur: das Zielfeld prüfen und den Spielstand über einen Pointer ändern.

1. Lesen, NULL und Lebensdauer

Nur lesen mit const

Über einen Pointer kann eine Funktion den Spielstand des Aufrufers verändern. Das haben Sie auf Seite 2 genutzt. Viele Funktionen sollen den Spielstand aber nur lesen, zum Beispiel die Statuszeile oder das Zeichnen des Spielfelds. Sie könnten den Spielstand dafür als Wert übergeben, dann bekäme die Funktion aber jedes Mal eine Kopie des ganzen Spielstands. Besser ist ein Pointer, bei dem Sie festlegen, dass über ihn nur gelesen werden darf.

Dafür gibt es const. Auf der Seite Funktionen haben Sie damit eine Variable festgelegt, die sich nicht mehr verändern lässt. Vor einem Pointer-Parameter bedeutet const: Über diesen Pointer darf die Funktion das Ziel nur lesen, nicht verändern.

void zug_zaehlen_original(Spielstand *p);       /* darf den Spielstand verändern */
int spielstand_lesen(const Spielstand *p, …);   /* darf ihn nur lesen */

Steht in einer Funktion mit const Spielstand *p trotzdem eine Zuweisung wie p->zuege = 5;, bricht der Compiler mit einem Fehler ab. Das hat zwei Vorteile: Wer nur den Funktionskopf liest, sieht sofort, dass die Funktion den Spielstand nicht verändert. Und wenn Sie sich in der Funktion versehentlich doch verschreiben, fällt das schon beim Übersetzen auf.

NULL und Lebensdauer

Ein Pointer muss nicht immer auf etwas zeigen. Der besondere Wert NULL bedeutet: Dieser Pointer zeigt auf nichts. Eine Funktion kann zum Beispiel NULL bekommen, wenn der Aufrufer gerade keinen Spielstand hat. Im Kapitel „Dynamischer Speicher“ begegnet Ihnen NULL noch häufiger.

Über einen NULL-Pointer dürfen Sie nicht zugreifen. Ein Ausdruck wie p->zuege mit p == NULL bringt das Programm in der Regel sofort zum Absturz. Kann eine Funktion NULL bekommen, prüft sie das deshalb vor dem ersten Zugriff und reagiert passend. Ein Beispiel, das nichts mit dem Spiel zu tun hat:

void uhrzeit_ausgeben(const Uhrzeit *u) {
    if (u == NULL) {
        printf("Keine Uhrzeit vorhanden.\n");
        return;
    }
    printf("%d:%02d\n", u->stunde, u->minute);
}

Eine zweite Gefahr erkennt diese Prüfung nicht. Ein Pointer ist nur so lange brauchbar, wie sein Ziel existiert. Zeigt ein Pointer zum Beispiel auf eine lokale Variable einer Funktion, gibt es diese Variable nach dem return nicht mehr. Der Pointer enthält aber weiterhin ihre alte Adresse. Er ist also nicht NULL, und trotzdem darf nicht mehr über ihn zugegriffen werden. Einen Versuch dazu machen Sie im Kapitel „Dynamischer Speicher“.

Für das Spiel heißt das: Im Fenster muss der Spielstand so lange existieren wie das ganze Programm. Er wird einmal angelegt und nicht nach jedem Tastendruck neu. Wie Sie eine solche Variable anlegen, lernen Sie auf Seite 4. Die Tasteneingabe verändert sie dann über einen Pointer, Zeichnen und Statuszeile lesen sie über einen const-Pointer.

Eine Funktion hat den Kopf int spielstand_lesen(const Spielstand *p, char ziel[], size_t groesse). Welche Aussagen stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die ersten drei Aussagen stimmen. const erlaubt über p nur das Lesen; eine Zuweisung meldet der Compiler als Fehler. Ein Zugriff über einen NULL-Pointer bringt das Programm in der Regel zum Absturz, deshalb gehört die Prüfung vor den ersten Zugriff. Ein Pointer auf eine lokale Variable behält nach dem return die alte Adresse. Er ist nicht NULL, darf aber trotzdem nicht mehr benutzt werden. Eine NULL-Prüfung erkennt diesen Fehler nicht.

2. Aufgabe: Einen Schritt der Figur ausführen

Schreiben Sie figur_bewegen. Die Funktion erhält einen Spielstand * und die Änderung der x- und y-Koordinate als int. Sie gibt als bool zurück, ob der Schritt ausgeführt wurde. Übergeben Sie jeweils einen der vier Schritte zu einem benachbarten Feld.

In dieser Aufgabe geht es nur um die Spiellogik: Darf die Figur das Zielfeld betreten, und wie verändert sich dann der Spielstand? Sie rufen figur_bewegen dafür im Textmodus direkt auf und prüfen die Ergebnisse. Fenster und Tastatur brauchen Sie hier noch nicht.

  • Prüfen Sie den Pointer auf NULL, bevor Sie auf ein Feld zugreifen.
  • Bestimmen Sie das Zielfeld und prüfen Sie Spielfeldgrenzen und Wände mit Ihren vorhandenen Abfragen. Prüfen Sie auch, ob das Zielfeld die Tür ist und sie laut Spielstand verschlossen ist. Die Tür startet wie in „Datenstrukturen“ verschlossen und blockiert die Bewegung.
  • Ändern Sie nur bei einer erfolgreichen Bewegung Position und Zugzahl und geben Sie true zurück. Andernfalls geben Sie false zurück.
  • Erlaubt sind nur die vier Schritte zu einem benachbarten Feld: (1, 0), (-1, 0), (0, 1) und (0, -1). Jede andere Änderung, etwa (2, 0) oder (1, 1), ist ungültig. Die Funktion verändert dann nichts und gibt false zurück.
Hinweis: Das Zielfeld prüfen

Berechnen Sie die Zielkoordinaten zunächst in einer eigenen Variable. Prüfen Sie die Grenzen vor einem Zugriff auf das Spielfeld-Array. Solange das Ziel nicht feststeht, müssen Sie weder Position noch Zugzahl im Spielstand ändern.

Passen Sie die Funktion für die Statuszeile an (im Startmaterial spielstand_lesen). Sie soll den Spielstand über const Spielstand * lesen und die bekannte Statuszeile füllen. Passen Sie die Aufrufe an den neuen Parametertyp an. Rufen Sie Bewegung und Status im Textmodus mit der Adresse desselben Spielstands auf. Probieren Sie auch einen Aufruf der Bewegungsfunktion mit NULL.

Ergänzen Sie eigene Testfälle mit erwarteten Ergebnissen, mindestens für:

  • die verschlossene Tür und die geöffnete Tür. Sie müssen die Figur dafür nicht hinlaufen lassen: Setzen Sie im Test die Position der Figur direkt auf ein Feld neben der Tür und das Feld für den Türzustand auf den gewünschten Wert.
  • einen ungültigen Schritt, etwa (2, 0) oder (1, 1),
  • einen Aufruf mit NULL statt eines Spielstands.
Selbstkontrolle: Erwartete Ergebnisse

Die vorgegebene Folge:

Steht die Figur auf (5, 3) und ist die Tür verschlossen, liefert ein Schritt nach rechts false. Position und Zugzahl bleiben gleich. Ist die Tür offen, gelangt die Figur auf das Türfeld (6, 3), und die Zugzahl steigt um eins. Ein ungültiger Schritt liefert false und verändert nichts. Ein Aufruf mit NULL liefert false, ohne auf einen Spielstand zuzugreifen.

Ausblick: Auf Seite 4 schließen Sie die fertige Funktion figur_bewegen an Tastatur und Anzeige an. Dann ruft ein Tastendruck die Funktion auf, und das Fenster zeigt den veränderten Spielstand.
