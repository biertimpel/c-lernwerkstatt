Spiellogik an Tastatur und Anzeige anschließen

Mehrere Funktionen arbeiten über Pointer mit demselben Spielstand: Die Tastatur verändert ihn, Bild und Statuszeile lesen ihn.

1. Ein Spielstand für das ganze Programm

Bisher haben Sie den Spielstand in einer Funktion angelegt, zum Beispiel in text_ausgeben. Das ist eine lokale Variable: Sie existiert nur, solange die Funktion läuft. Für das Spiel im Fenster reicht das nicht. Das Gerüst ruft Ihre Funktionen immer wieder auf: taste_gedrueckt bei jedem Tastendruck, zeichne für jedes Bild. Ein lokaler Spielstand in taste_gedrueckt würde bei jedem Aufruf neu angelegt, die vorige Bewegung wäre verloren. In main können Sie ihn auch nicht anlegen, denn main steht in programm.c, und die Funktionen bekommen vom Gerüst keinen Spielstand übergeben.

Die Lösung ist eine Variable außerhalb aller Funktionen. Solche globalen Variablen kennen Sie von den Seiten Lokale und globale Variablen und Funktionen. Eine globale Variable existiert während des ganzen Programmlaufs: Sie wird beim Programmstart angelegt und erst am Programmende freigegeben. Alle Funktionen, die in der Datei unterhalb ihrer Deklaration stehen, können sie verwenden.

#include <stdio.h>

static int aufrufe;   /* außerhalb aller Funktionen */

void zaehlen(void) {
    aufrufe++;
    printf("Aufruf Nummer %d\n", aufrufe);
}

int main(void) {
    zaehlen();
    zaehlen();
    zaehlen();
    return 0;
}

Vorhersagen und ausprobieren: Was gibt das Programm aus? Verschieben Sie danach die Deklaration als int aufrufe = 0; an den Anfang von zaehlen. Was ändert sich, und warum?

Zwei Eigenschaften globaler Variablen brauchen Sie für das Spiel:

  • Anfangswert: Eine globale Variable ohne Anfangswert beginnt mit 0. Bei einer Struktur sind alle Felder 0 beziehungsweise false. Ihr Wert ist also nie zufällig, anders als bei einer lokalen Variablen ohne Anfangswert. Ein Anfangswert, den Sie selbst angeben, muss aber schon beim Übersetzen feststehen. static Spielstand spielstand = startzustand(); bricht deshalb mit initializer element is not constant ab, denn ein Funktionsaufruf findet erst während des Programmlaufs statt. Legen Sie die Variable daher ohne Anfangswert an und weisen Sie ihr in spiel_starten den Startzustand zu. Das Gerüst ruft spiel_starten einmal auf, bevor es Tasten verarbeitet und das erste Bild zeichnet.
  • Das Wort static: Aus der Lektion Header und Quelldateien kennen Sie zwei Möglichkeiten für eine globale Variable. Ohne static kann jede andere Quelldatei sie über eine extern-Deklaration verwenden. Mit static ist sie nur in ihrer eigenen Datei sichtbar. Dieselbe Bedeutung hat static vor GRUNDRISS und vor der Funktion statuszeile im Startmaterial. Vor einer lokalen Variablen innerhalb einer Funktion hat static eine andere Bedeutung, die Sie in diesem Kapitel nicht brauchen.

Warum hier static und nicht extern?

Mit extern in tresorraub.h könnte auch programm.c den Spielstand direkt verwenden. Für das Spiel ist static trotzdem die bessere Wahl:

  • Der Spielstand gehört zu tresorraub.c. Dort stehen alle Funktionen, die ihn lesen oder verändern. Das Gerüst braucht ihn nicht selbst. Es ruft nur die Funktionen auf, die in tresorraub.h stehen.
  • Die Spielregeln lassen sich nicht umgehen. Die Figur bewegt sich nur über figur_bewegen, und diese Funktion prüft Wände und Tür und zählt die Züge. Mit extern könnte jede Datei die Position direkt verändern, an allen Prüfungen vorbei. Ändert sich der Spielstand unerwartet, wissen Sie mit static: Die Ursache steht in tresorraub.c.
  • Das Gerüst passt zu jedem Spielstand. In tresorraub.h kommt der Typ Spielstand gar nicht vor. Für eine extern-Deklaration müsste die Strukturdefinition in den Header wandern, und programm.c hinge davon ab, wie Sie Ihren Spielstand aufgebaut haben. So aber funktioniert dasselbe Gerüst für alle Lösungen, egal wie Ihre Felder heißen.
In tresorraub.c steht außerhalb aller Funktionen static Spielstand spielstand;. Welche Aussagen stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die ersten beiden Aussagen stimmen. Weil die Variable außerhalb aller Funktionen steht, existiert sie während des ganzen Programmlaufs und wird nicht bei Funktionsaufrufen neu angelegt. Ohne eigenen Anfangswert beginnt sie mit lauter Nullen, also zum Beispiel an der Position (0, 0) mit 0 Zügen. Zufällig ist das nicht. Den richtigen Startzustand bekommt sie erst in spiel_starten. static beschränkt die Sichtbarkeit auf tresorraub.c.

2. Aufgabe: Tastatur, Bild und Statuszeile verbinden

Auf Seite 3 haben Sie die Spiellogik geschrieben und im Textmodus getestet. Neue Bewegungslogik kommt hier nicht hinzu. Neu ist, dass das Gerüst drei Ihrer Funktionen aufruft, die alle mit demselben Spielstand arbeiten:

  • taste_gedrueckt verändert ihn über einen Pointer, indem sie figur_bewegen aufruft.
  • zeichne liest ihn über einen const-Pointer, um das Spielfeld darzustellen.
  • spiel_status liest ihn über einen const-Pointer, um die Statuszeile im Fenstertitel zu füllen.

Dafür brauchen Sie genau einen Spielstand, der während des ganzen Programms existiert, wie in Abschnitt 1 beschrieben. Die Funktionsköpfe gibt das Gerüst in tresorraub.h vor. Die Rümpfe in tresorraub.c sind bisher Platzhalter, die Sie jetzt selbst schreiben. Wie bei zeichne melden die Funktionen mit ihrem Rückgabewert, ob alles geklappt hat: 0 bei Erfolg, ein negativer Wert bei einem Fehler, nach dem das Spiel nicht weiterlaufen kann. Das Gerüst beendet das Programm dann. In diesem Kapitel kann ein solcher Fehler nur bei der Statuszeile auftreten, wenn sie nicht in das Zeichenarray passt.

  1. Legen Sie in tresorraub.c eine static-Variable für den laufenden Spielstand an. Schreiben Sie den Rumpf von spiel_starten so, dass die Funktion dieser Variablen den Startzustand zuweist und 0 zurückgibt.
  2. Das Gerüst ruft taste_gedrueckt bei jedem Tastendruck auf und übergibt den Code der gedrückten Taste. Schreiben Sie den Rumpf so, dass jede Pfeiltaste figur_bewegen mit der Adresse des laufenden Spielstands und der passenden Richtung aufruft. Andere Tasten verändern nichts. Die Funktion gibt 0 zurück.
  3. Zeichnen Sie die Figur aus dem laufenden Spielstand. Falls zeichne bisher für jedes Bild einen neuen Startzustand angelegt hat, verwenden Sie stattdessen den vorhandenen Zustand. Zum Anzeigen muss der Spielstand nur gelesen werden. Stellen Sie deshalb die Funktionen, die ihn zum Zeichnen und Ausgeben erhalten, wie auf Seite 3 auf const Spielstand * um. Im Startmaterial sind das feld_zeichnen, feldzeichen und spielfeld_ausgeben. Passen Sie die Aufrufe an, auch im Textmodus.
  4. Ersetzen Sie den Platzhalter in spiel_status: Die Funktion ruft Ihre Lesefunktion von Seite 3 mit der Adresse desselben Spielstands auf und gibt deren Rückgabewert zurück. Daran erkennt das Gerüst, ob die Statuszeile in das Zeichenarray gepasst hat. Es zeigt sie dann im Fenstertitel an.
  5. Starten Sie das Programm im Fenster und bewegen Sie die Figur mehrere Felder weit. Prüfen Sie dabei, was neu ist: Bleibt die Figur nach einem Schritt auf dem neuen Feld, oder springt sie zurück? Zeigen Bild und Fenstertitel nach jedem Tastendruck dieselbe Position und Zugzahl? Laufen Sie auch gegen eine Wand: Ändert sich der Titel dann?
Hinweis: Wo Variable und Funktionen stehen müssen

Der Compiler liest die Datei von oben nach unten. Legen Sie die Variable deshalb unterhalb der Typdefinition von Spielstand an und oberhalb der ersten Funktion, die sie verwendet. Dasselbe gilt für figur_bewegen: Die Funktion muss oberhalb von taste_gedrueckt und text_ausgeben stehen. Sonst meldet der Compiler eine nicht deklarierte Funktion: GCC mit implicit declaration of function, je nach Version als Warnung oder als Fehler, Clang mit dem Fehler call to undeclared function.

Hinweis: Pfeiltasten zuordnen

Die Tastencodes heißen SDLK_LEFT, SDLK_RIGHT, SDLK_UP und SDLK_DOWN. Im Spielfeld wächst x nach rechts und y nach unten. Wenn die Figur nach einem Schritt zurückspringt, suchen Sie nach einem Aufruf der Startzustandsfunktion in zeichne.

Selbstkontrolle: Was Sie im Fenster sehen

Nach jedem erfolgreichen Schritt bleibt die Figur auf dem neuen Feld, und der Fenstertitel zeigt dieselbe Position wie das Bild sowie eine um eins höhere Zugzahl. Läuft die Figur gegen eine Wand, ändern sich weder Bild noch Titel. Von (5, 3) aus führt ein Schritt nach rechts zur verschlossenen Tür bei (6, 3). Auch dann bleibt die Figur stehen, und die Zugzahl bleibt gleich.

Warum darf zeichne nicht bei jedem Bild einen neuen Startzustand anlegen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die ersten beiden Aussagen stimmen. Ein Startzustand, den zeichne selbst anlegt, ist eine eigene lokale Variable. Die static-Variable bleibt dabei unverändert, nur wird sie nicht angezeigt. Die Figur scheint deshalb nach jedem Schritt zurückzuspringen, obwohl sich der eigentliche Spielstand verändert hat. Zum Anzeigen genügt Lesen, also ein const-Pointer.

Ihr Ergebnis: Die Figur bewegt sich mit den Pfeiltasten durch das Spielfeld, Wände und die verschlossene Tür blockieren die Bewegung. Tastatur, Bild und Statuszeile arbeiten mit demselben Spielstand: Bild und Fenstertitel zeigen nach jedem Tastendruck dieselbe Position und Zugzahl.
