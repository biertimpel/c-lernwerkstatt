Lernziele

  • Fehler beim Übersetzen, falsche Ergebnisse und erkannte ungültige Werte unterscheiden.
  • Vereinbarte Fehlercodes prüfen und an den Aufrufer weitergeben.
  • Fehlercodes, Fehlermeldungen und zusätzliche Ausgaben zur Fehlersuche unterscheiden.
  • Parameter und Rückgabewerte mit gezielten Ausgaben verfolgen.
  • Geeignete Testfälle wählen und eine gefundene Ursache korrigieren und überprüfen.

Theorie und Hintergrund

Ihr Bestellrechner liefert für die bisherigen Beispiele passende Ergebnisse. Was passiert aber, wenn eine Anzahl für die Bestellung nicht sinnvoll ist? Und wie finden Sie heraus, warum das Programm trotz erfolgreicher Übersetzung einen falschen Preis ausgibt?

Solche Fragen gehören zum Debugging: Sie beobachten einen Fehler, untersuchen seine Ursache und überprüfen anschließend Ihre Korrektur. Fehler können sich unterschiedlich zeigen:

BeispielMöglicher Umgang
Der Compiler meldet eine fehlende Klammer.Lesen Sie die erste Fehlermeldung mit Zeilennummer. Prüfen Sie auch die direkt vorhergehende Anweisung.
Eine ungültige Anzahl wird an eine Funktion übergeben.Die Funktion erkennt den ungültigen Wert und meldet ihn über einen vereinbarten Rückgabewert.
Das Programm berechnet einen falschen Preis.Vergleichen Sie erwartete und tatsächliche Werte und untersuchen Sie die beteiligten Funktionsaufrufe.

Fehler gezielt untersuchen

Ein Debugger ist ein Werkzeug, mit dem Sie ein laufendes Programm anhalten, die gespeicherten Werte ansehen und den Programmablauf schrittweise verfolgen können. So können Sie beobachten, nach welcher Anweisung ein Wert erstmals von Ihrer Erwartung abweicht.

In dieser Aufgabe machen Sie solche Beobachtungen zunächst mit gezielten printf-Ausgaben. Sie überlegen, welche Ursache zum beobachteten Verhalten passen könnte und welche Ausgabe diese Vermutung überprüft. Damit üben Sie, Fehler einzugrenzen. Diese Überlegungen helfen Ihnen später auch dabei, im Debugger sinnvolle Haltepunkte zu setzen und die passenden Variablen zu untersuchen.

Debugger und Diagnoseausgaben sind zwei Werkzeuge für die Fehlersuche. Für beide brauchen Sie eine Vorstellung davon, welches Verhalten Sie erwarten. Hier arbeiten Sie mit printf-Ausgaben.

Was ist hier ein Wert?

Mit einem Wert meinen wir hier die konkrete Zahl, die eine Variable gerade enthält oder die eine Berechnung liefert. 10.2 ist ein einzelner Zahlenwert. Die Ziffern sind keine getrennten Werte. Im Fließtext schreiben wir dafür auch 10,2.

Eine Bestellung mit der Anzahl 3 und dem Einzelpreis 10.20 hat zwei Eingabewerte. Der daraus berechnete Warenwert 30.60 ist ein weiterer Wert.

Fehler über Rückgabewerte melden

Fehlerbehandlung ist von der Suche nach der Ursache zu unterscheiden: Eine Funktion kann während ihrer Ausführung zum Beispiel ungültige Eingabedaten erkennen. Der aufrufende Programmteil muss dann erfahren, dass kein gültiges Ergebnis berechnet werden konnte.

Eine Konvention vieler C-Schnittstellen ist, einen erkannten Fehler durch einen dafür vorgesehenen Rückgabewert zu signalisieren. Die Bedeutung des Rückgabewerts gehört zur Schnittstelle der jeweiligen Funktion. Der Aufrufer muss ihn prüfen und passend reagieren. Es gibt keinen einzelnen Fehlerwert und keinen Rückgabetyp, der für alle C-Funktionen gilt. Für unsere Funktionen vereinbaren wir deshalb jetzt eigene Fehlercodes.

Fehlercode, Fehlermeldung und Diagnoseausgabe

MittelAufgabeBeispiel
FehlercodeEin Wert informiert den aufrufenden Programmteil darüber, dass eine Funktion einen Fehler erkannt hat.return -1;
FehlermeldungEine Ausgabe informiert die Person vor dem Bildschirm über einen erkannten Fehler.printf("Ungueltige Anzahl.\n");
Diagnoseausgabe zur FehlersucheEine zusätzliche Ausgabe zeigt Werte, um eine Ursache einzugrenzen. Sie kann auch bei einem gültigen Ablauf erscheinen.printf("[DEBUG] anzahl=%d\n", anzahl);

Ein Fehlercode erscheint nicht automatisch auf dem Bildschirm. Eine Fehlermeldung verändert umgekehrt nicht von selbst den Programmablauf. Dazu müssen Sie im Code entscheiden, wie es weitergeht. Die zusätzlichen Diagnoseausgaben dienen Ihrer Fehlersuche. Wenn das Programm nach Ihren Tests das gewünschte Verhalten zeigt, entfernen Sie diese Ausgaben vor der Fertigstellung oder kommentieren sie aus. Die regulären Ergebnisausgaben, Fehlerprüfungen und Fehlermeldungen bleiben erhalten.

Die Bedeutung eines Rückgabewerts vereinbaren

Unsere Berechnungsfunktionen liefern bei Erfolg einen Preis ab 0.00 zurück. Die Werte -1 und -2 verwenden wir als Fehlercodes. So lässt sich ein Fehler von einem gültigen Preis unterscheiden. Ein Preis von 0.00 bleibt ein mögliches gültiges Ergebnis.

Der Rückgabetyp bleibt double, weil diese Funktionen außerdem Preise mit Nachkommastellen zurückgeben. Bei return -1; wird die Zahl -1 passend zu diesem Rückgabetyp umgewandelt. Eine andere Funktion könnte stattdessen einen int-Wert zurückgeben, der nur Erfolg oder eine bestimmte Fehlerart meldet. Für unsere Aufgabe bleiben wir bei der bestehenden Preisrückgabe.

Dies ist eine Vereinbarung für unsere Funktionen. Andere C-Funktionen können andere Bedeutungen verwenden. scanf zählt beispielsweise die erfolgreich eingelesenen und zugewiesenen Werte. Beim Einlesen eines einzelnen Werts erwarten Sie dort 1.

Mit return einen Fehler weitergeben

Erkennt die Warenwertfunktion ungültige Bestelldaten, beendet sie ihren Aufruf mit einem Fehlercode. Danach läuft die aufrufende Preisfunktion weiter. Diese muss das Ergebnis prüfen, bevor sie Lieferkosten oder Rabatt berechnet. Bei einem Fehler gibt sie eine Fehlermeldung aus und liefert denselben Fehlercode an ihren eigenen Aufrufer zurück.

Schließlich erhält main das Ergebnis der Preisfunktion. Wenn main einen Fehler erkennt, gibt es eine Meldung aus und beendet das Programm mit return 1;. Bei erfolgreichem Ablauf steht am Ende return 0;. Diese beiden Werte melden dem aufrufenden System, ob das Programm erfolgreich war. Sie werden nicht automatisch als Text ausgegeben.

Entscheidend ist, in welcher Funktion return steht: In einer Berechnungsfunktion führt es zurück zum Aufrufer. In main beendet es hier das Programm. Das bekannte break beendet dagegen eine Schleife und setzt die Ausführung hinter dieser Schleife fort.

Werte sichtbar machen

Eine Fehlermeldung zeigt zunächst, wo ein Problem erkannt wurde. Die Ursache kann früher liegen, etwa bei einem Funktionsaufruf mit einem falschen Argument. Geben Sie zur Untersuchung gezielt die übergebenen Werte und die Ergebnisse aus. Benennen Sie in jeder Diagnoseausgabe die Funktion und die Bedeutung des Werts.

Vergleichen Sie bei einem konkreten Testfall zuerst das erwartete und das tatsächliche Ergebnis. Verfolgen Sie dann mit diesen Ausgaben, an welcher Stelle die erste Abweichung auftritt. Korrigieren Sie eine Ursache und führen Sie denselben Test nach erneutem Übersetzen noch einmal aus. Anschließend prüfen Sie weitere selbst gewählte Fälle.

Aufgaben

a) Fehlerprüfungen ergänzen

Ergänzen Sie Ihr eigenes Programm um Fehlerprüfungen. Sie können Ihre Tastatureingabe mit scanf weiterverwenden oder feste Ausgangswerte in main nutzen.

Die Warenwertfunktion erhält weiterhin Anzahl und Einzelpreis als Parameter. Prüfen Sie zuerst die Anzahl und danach den Einzelpreis:

BedingungRückgabewert
Anzahl ist null oder negativ.Fehlercode -1
Einzelpreis ist negativ.Fehlercode -2
Beide Werte sind gültig.Warenwert aus Anzahl × Einzelpreis
  1. Ergänzen Sie die Prüfungen und Rückgaben in der Warenwertfunktion.
  2. Prüfen Sie in beiden Preisfunktionen den Rückgabewert der Warenwertfunktion. Geben Sie bei einem Fehler eine Fehlermeldung aus und liefern Sie denselben Fehlercode sofort zurück. Rechnen Sie in diesem Fall nicht weiter.
  3. Prüfen Sie in main unmittelbar nach jedem Aufruf einer Preisfunktion deren Ergebnis. Bei einem Fehler geben Sie eine Meldung aus und beenden das Programm mit return 1;.
  4. Rufen Sie die reguläre Ausgabefunktion nur auf, wenn beide Berechnungen erfolgreich waren.
  5. Falls Sie scanf verwenden, prüfen Sie zusätzlich, ob jeweils ein Wert eingelesen wurde. Bei fehlgeschlagenem Einlesen soll das Programm eine Meldung ausgeben und mit return 1; enden, bevor die Berechnungen aufgerufen werden.

b) Die Fehlerbehandlung selbst testen

Wählen Sie passende gültige und ungültige Bestelldaten. Berücksichtigen Sie auch die Grenzen der erlaubten Werte. Notieren Sie vor jedem Start, welchen Rückgabewert und welche Ausgabe Sie erwarten.

Führen Sie mindestens einen Test für jede vereinbarte Fehlersituation durch. Bei ungültigen Bestellungen sollen Fehlermeldungen erscheinen und die Berechnung abbrechen. Reguläre Preiszeilen sollen dann nicht ausgegeben werden. Prüfen Sie außerdem, ob ein gültiger Preis von 0.00 möglich bleibt.

Geben Sie Ihre Testwerte über scanf ein oder ändern Sie die festen Werte in main. Nach Änderungen am Quelltext übersetzen Sie erneut. Bewahren Sie Ihre Testfälle für die nächste Aufgabe auf.

c) Drei vorbereitete Fehler finden

Verwenden Sie jetzt die unter „Materialien“ verlinkte Fehlerfassung für Aufgabe c. Öffnen Sie sie in einem eigenen Ordner. Sie enthält bereits Fehlerprüfungen und Fehlermeldungen und lässt sich übersetzen. Trotzdem sind drei Fehler eingebaut.

  1. Starten Sie zunächst mit den vorhandenen Bestelldaten und vergleichen Sie das Verhalten mit Ihrer Erwartung.
  2. Ergänzen Sie Diagnoseausgaben für die Parameter einer Funktion und die Rückgabewerte ihrer Aufrufe. Verfolgen Sie die Bestelldaten von main bis zur Warenwertberechnung. An welcher Stelle weicht ein Wert erstmals von Ihrer Erwartung ab?
  3. Korrigieren Sie eine gefundene Ursache und wiederholen Sie denselben Test. Prüfen Sie danach auch die berechneten Preise.
  4. Untersuchen Sie die Fassung mit Ihren selbst gewählten Testfällen aus Aufgabe b. Finden Sie alle drei Fehler und prüfen Sie nach jeder Korrektur erneut.

Sie können auch hier eine bereits umgesetzte Tastatureingabe verwenden. Wählen Sie bei einem erneuten Test dieselben Eingaben.

Halten Sie zu jedem Fehler fest, wo die Ursache lag, welche Ausgabe bei der Suche geholfen hat und mit welchem Test Sie die Korrektur überprüft haben.

Zum Abschluss: Wenn Ihre Korrekturen die selbst gewählten Tests bestehen, entfernen Sie die zusätzlichen Diagnoseausgaben oder kommentieren Sie sie aus. Lassen Sie die regulären Preiszeilen, Fehlerprüfungen und Fehlermeldungen bestehen. Übersetzen und testen Sie diese abschließende Fassung erneut.

Hinweise

Zu a: Einen ungültigen Wert melden

Die Warenwertfunktion kann einen Fehler über einen Rückgabewert melden:

if (anzahl <= 0) {
    return -1;
}

Ergänzen Sie danach die Prüfung des Einzelpreises. Die normale Berechnung folgt erst hinter den Prüfungen.

Zu a: Einen Fehlercode weitergeben

Nach dem Aufruf der Warenwertfunktion prüfen Sie das Ergebnis, bevor Sie damit weiterrechnen:

double warenwert = berechne_warenwert(anzahl, einzelpreis);
if (warenwert < 0.0) {
    printf("Warenwertberechnung meldet Fehlercode %.0f.\n", warenwert);
    return warenwert;
}

printf zeigt die Fehlermeldung an. return beendet den Aufruf und liefert den Fehlercode zurück. Erst hinter dieser Prüfung berechnen Sie den endgültigen Preis.

Zu a: In main auf den Fehler reagieren

Prüfen Sie den Rückgabewert unmittelbar nach dem Aufruf:

double lieferpreis = berechne_lieferpreis(anzahl, einzelpreis);
if (lieferpreis < 0.0) {
    printf("Die Lieferpreisberechnung meldet einen Fehler.\n");
    return 1;
}

Gehen Sie für den Abholpreis entsprechend vor. Die Ausgabefunktion erhält nur erfolgreich berechnete Preise.

Zu a mit scanf: Erfolgreiches Einlesen prüfen

Wenn Sie einen einzelnen Wert einlesen wollen, muss scanf den Wert 1 zurückgeben:

if (scanf("%d", &anzahl) != 1) {
    printf("Die Anzahl konnte nicht gelesen werden.\n");
    return 1;
}

Prüfen Sie den Einzelpreis entsprechend. Testen Sie etwa auch eine Buchstabeneingabe. Erfolgreiches Einlesen und ein sinnvoller Zahlenwert sind verschiedene Prüfungen: Eine negative Zahl kann erfolgreich eingelesen und erst von Ihrer Berechnungsfunktion abgelehnt werden.

Zu b: Den Programmabschluss prüfen

Ihre IDE zeigt gegebenenfalls den Abschlussstatus an. Im Linux-/Unix-Terminal können Sie ihn direkt nach dem Programmstart abfragen:

./programm
echo $?

Bei Erfolg erwarten Sie 0 und bei einem erkannten Fehler 1. Führen Sie zwischen diesen beiden Befehlen keinen anderen Befehl aus.

Zu c: Eine gezielte Diagnoseausgabe

Geben Sie beispielsweise am Anfang einer Funktion ihre Parameter aus:

printf("[DEBUG Lieferpreis] anzahl=%d, einzelpreis=%.2f\n",
       anzahl, einzelpreis);

Vergleichen Sie diese Werte mit denen, die in der aufgerufenen Warenwertfunktion ankommen. Untersuchen Sie anschließend auch deren Rückgabewert. Eine solche Ausgabe dokumentiert Werte unabhängig davon, ob schon ein Fehler erkannt wurde.

Zu c: Wenn die erste Korrektur noch nicht reicht

Prüfen Sie nach der Weitergabe der Argumente auch die Berechnung des Rabatts und die Bedingungen für gültige Eingaben. Wählen Sie Testfälle, bei denen eine kleine Änderung eines Werts das erwartete Verhalten verändert.

Ein möglicher Satz von Testfällen enthält eine normale Bestellung, eine negative Anzahl, die Anzahl null, einen negativen Einzelpreis und einen gültigen Einzelpreis null.

Die Stelle, an der ein Fehler erkannt wird, muss nicht seine Ursache enthalten. Hier erkennt die Warenwertfunktion den negativen Preis korrekt. Der falsche Wert entsteht bereits beim Aufruf.

Mögliche korrigierte Lösung mit Diagnoseausgaben

Vergleichen Sie nach einem eigenen Versuch. Andere sinnvolle Lösungen sind möglich.

#include <stdio.h>

const double lieferkosten = 2.50;

double berechne_warenwert(int anzahl, double einzelpreis) {
    printf("[DEBUG Warenwert] anzahl=%d, einzelpreis=%.2f\n", anzahl, einzelpreis);
    if (anzahl <= 0) {
        return -1;
    }
    if (einzelpreis < 0.0) {
        return -2;
    }
    double warenwert = anzahl * einzelpreis;
    printf("[DEBUG Warenwert] Ergebnis=%.2f\n", warenwert);
    return warenwert;
}

double berechne_lieferpreis(int anzahl, double einzelpreis) {
    printf("[DEBUG Lieferpreis] anzahl=%d, einzelpreis=%.2f\n", anzahl, einzelpreis);
    double warenwert = berechne_warenwert(anzahl, einzelpreis);
    printf("[DEBUG Lieferpreis] Rueckgabe der Warenwertberechnung=%.2f\n", warenwert);
    if (warenwert < 0.0) {
        printf("[FEHLER Lieferpreis] Warenwertberechnung meldet Fehlercode %.0f\n", warenwert);
        return warenwert;
    }
    return warenwert + lieferkosten;
}

double berechne_abholpreis(int anzahl, double einzelpreis) {
    printf("[DEBUG Abholpreis] anzahl=%d, einzelpreis=%.2f\n", anzahl, einzelpreis);
    double warenwert = berechne_warenwert(anzahl, einzelpreis);
    printf("[DEBUG Abholpreis] Rueckgabe der Warenwertberechnung=%.2f\n", warenwert);
    if (warenwert < 0.0) {
        printf("[FEHLER Abholpreis] Warenwertberechnung meldet Fehlercode %.0f\n", warenwert);
        return warenwert;
    }
    return warenwert * 0.90;
}

void gib_preise_aus(double lieferpreis, double abholpreis) {
    printf("Lieferpreis: %.2f Euro\n", lieferpreis);
    printf("Abholpreis: %.2f Euro\n", abholpreis);
}

int main(void) {
    int anzahl = 3;
    double einzelpreis = 9.50;

    double lieferpreis = berechne_lieferpreis(anzahl, einzelpreis);
    if (lieferpreis < 0.0) {
        printf("Abbruch: Lieferpreis konnte nicht berechnet werden (%.0f).\n", lieferpreis);
        return 1;
    }

    double abholpreis = berechne_abholpreis(anzahl, einzelpreis);
    if (abholpreis < 0.0) {
        printf("Abbruch: Abholpreis konnte nicht berechnet werden (%.0f).\n", abholpreis);
        return 1;
    }

    gib_preise_aus(lieferpreis, abholpreis);
    return 0;
}

    double einzelpreis = 0.0;
