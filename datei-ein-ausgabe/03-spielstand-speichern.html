Den aktuellen Spielstand speichern

Die aktuellen Spieldaten auslesen und mit F5 in spielstand.txt schreiben.

Theorie und Hintergrund

Speichern liest den laufenden Spielstand

Die Speicherfunktion bekommt den Spielstand und einen Dateinamen. Sie liest die Werte aus dem Spielstand und schreibt sie mit fprintf in die Datei. Dabei verändert sie weder die Position der Figur noch die Zugzahl oder das Inventar.

Aus dem Pointer-Kapitel kennen Sie einen Pointerparameter für den Zugriff auf eine vorhandene Struktur. Mit const Spielstand *s legen Sie fest, dass die Felder der Struktur über s nur gelesen werden sollen. Beispielsweise lässt sich s->zuege auslesen; eine Zuweisung an s->zuege erlaubt der Compiler nicht. Dafür ist keine Kopie des gesamten Spielstands nötig.

Auch beim Durchlaufen der Liste sollen die vorhandenen Einträge unverändert bleiben. Verwenden Sie dafür einen Pointer auf const Eintrag. const an der äußeren Struktur schützt allerdings nicht automatisch alle Einträge, auf die deren Pointer zeigen. Die Speicherfunktion muss auch diese Einträge ausschließlich lesen.

Die Inventarliste als Text ausgeben

Schreiben Sie zunächst die Anzahl der Einträge. Danach gehen Sie vom ersten Eintrag über naechster bis zum Listenende und geben jeden Namen aus. Am Listenende steht NULL. Die Datei enthält die Namen in genau derselben Reihenfolge, in der Sie die Liste durchlaufen haben.

Die feste Reihenfolge der Datenzeilen aus FORMAT.md ist die gemeinsame Vereinbarung mit der Ladefunktion. Die Ausgabe auf dem Bildschirm und der Inhalt der Speicherdatei sind unterschiedliche Ausgaben. Eine Meldung wie „Spielstand gespeichert“ gehört ins Terminal. In die Datei gehören die vereinbarten Datenzeilen.

Fehler melden und die Dateiverbindung schließen

Ihre Speicherfunktion gibt einen Wert zurück, an dem der Aufrufer Erfolg und Fehlschlag erkennt. Legen Sie diesen Vertrag vor der Implementierung fest. Erfolg dürfen Sie erst melden, wenn sowohl die Ausgaben als auch fclose erfolgreich waren.

Scheitert bereits fopen, gibt es keine geöffnete Verbindung. Scheitert dagegen eine spätere Ausgabe, ist die Verbindung weiterhin offen. Merken Sie sich den Fehler, schließen Sie die Verbindung und melden Sie anschließend den Fehlschlag. Würden Sie vorher mit return abbrechen, bliebe die geöffnete Verbindung in Ihrem laufenden Spiel bestehen.

Ein fehlgeschlagener Speicherversuch kann eine unvollständige Datei hinterlassen. Im Modus "w" wurde ein alter Dateiinhalt bereits beim Öffnen entfernt. Der laufende Spielstand im Arbeitsspeicher bleibt beim Speichern unverändert.

F5 mit Ihrer Funktion verbinden

Die Funktion taste_gedrueckt verarbeitet bereits die Pfeiltasten, die Leertaste und L. Ergänzen Sie dort F5. Der entsprechende Tastenwert heißt SDLK_F5. In diesem Fall rufen Sie Ihre Speicherfunktion mit dem laufenden Spielstand auf. Verwenden Sie dafür denselben Spielstand, den Bewegung und Anzeige verwenden.

Unterscheiden Sie die Rückgaben der beiden Funktionen. Ihre Speicherfunktion meldet, ob das Speichern gelang. taste_gedrueckt meldet dem vorbereiteten Programmgerüst, ob das Spiel weiterlaufen kann. Gibt taste_gedrueckt einen negativen Wert zurück, beendet das Gerüst das Programm. Eine nicht beschreibbare Datei soll hier aber nur eine Meldung auslösen. Nach dieser Meldung kann taste_gedrueckt weiterhin 0 zurückgeben.

F5 konnte die Datei nicht öffnen. Der laufende Spielstand ist weiterhin gültig. Welche Aussagen stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die Speicherfunktion meldet den Dateifehler an taste_gedrueckt. Diese Funktion kann ihn im Terminal anzeigen und mit 0 zurückkehren, damit das Spiel weiterläuft.

Aufgabe: Den aktuellen Spielstand speichern

  1. Entwerfen Sie eine Funktion zum Speichern. Legen Sie ihre Parameter und den Rückgabewert für Erfolg und Fehlschlag fest. Die übergebenen Spieldaten sollen unverändert bleiben.
  2. Implementieren Sie die Ausgabe im vereinbarten Format. Berücksichtigen Sie alle Inventareinträge und die Positionen und Zustände der Gegenstände. Prüfen Sie Öffnen, jede Ausgabe und Schließen.
  3. Legen Sie für einen ersten Versuch in text_ausgeben einen lokalen Spielstand mit startzustand an. Rufen Sie damit Ihre Speicherfunktion auf. Übersetzen und starten Sie mit ./programm --text. Öffnen Sie anschließend die erzeugte Datei im Texteditor und vergleichen Sie sie mit dem Format.
  4. Ergänzen Sie in taste_gedrueckt den Fall SDLK_F5. Er soll den laufenden Spielstand in spielstand.txt speichern und im Terminal Erfolg oder Fehlschlag melden.
  5. Starten Sie das Spielfenster. Bewegen Sie die Figur, nehmen Sie einen Gegenstand auf und speichern Sie mit F5. Vergleichen Sie die gespeicherten Werte mit dem Spiel. Kontrollieren Sie auch, dass F5 keinen Zug verbraucht.
Hinweis: Funktionsaufruf bei F5

Der laufende Spielstand ist als static-Variable in tresorraub.c vorhanden. Übergeben Sie Ihrer Speicherfunktion dessen Adresse. Der Tastendruck soll keinen neuen Startzustand erzeugen.

Selbstkontrolle: Gespeicherter Zustand

Position, Zugzahl, Türzustand und Gegenstände stimmen mit dem Zeitpunkt des Tastendrucks überein. Das Inventar steht in Listenreihenfolge in der Datei. Eine weitere Betätigung von F5 ohne Zustandsänderung schreibt dieselben Daten.
