Eine erste Datei schreiben

Mit C-Code eine Textdatei erzeugen, ergänzen und das Ergebnis im Texteditor überprüfen.

1. Dateien im Programm und im Texteditor

Eine Textdatei enthält Zeichen, die Sie in einem Texteditor lesen können. Ihr C-Programm kann eine solche Datei selbst anlegen, beschreiben und wieder lesen. Es verwendet dafür Funktionen aus <stdio.h>.

Unterscheiden Sie den Zugriff des Programms von der Nutzung des Texteditors. Wenn Ihr Programm fopen aufruft, richtet die C-Bibliothek den Dateizugriff für das laufende Programm ein. Es öffnet sich dadurch kein Editorfenster. Wenn Sie anschließend die Datei im Texteditor öffnen, sehen Sie sich unabhängig davon das gespeicherte Ergebnis an.

2. Eine Dateiverbindung öffnen: fopen

FILE *datei = fopen("notiz.txt", "w");

Der erste Parameter ist der Dateiname. Der zweite Parameter legt fest, ob das Programm die Datei lesen oder beschreiben möchte. Er heißt Öffnungsmodus.

ModusBedeutungVerhalten beim Öffnen
"w"write: schreibenExistiert die Datei noch nicht, wird sie angelegt. Existiert sie bereits, wird ihr bisheriger Inhalt bei erfolgreichem Öffnen gelöscht. Neue Ausgaben beginnen in einer leeren Datei.
"a"append: anhängenExistiert die Datei noch nicht, wird sie angelegt. Ein vorhandener Inhalt bleibt erhalten; jede Ausgabe wird am Ende angehängt.
"r"read: lesenDie Datei muss bereits vorhanden sein. Ihr Inhalt bleibt erhalten. Das Lesen beginnt am Dateianfang.

Daneben gibt es Modi mit +, die Lesen und Schreiben verbinden, und den Zusatz b für Binärdateien. Beide brauchen Sie in diesem Kapitel nicht; die Manpage von fopen beschreibt sie.

Bei Erfolg liefert fopen einen Pointer. Bei einem Fehler liefert die Funktion NULL, etwa wenn das Verzeichnis nicht existiert oder der Zugriff nicht erlaubt ist. Prüfen Sie dieses Ergebnis, bevor Sie über datei lesen, schreiben oder schließen.

3. Was bedeutet FILE *? Was ist ein Stream?

Die C-Bibliothek organisiert Ein- und Ausgaben als Datenstrom, auf Englisch Stream. Daten werden darüber nacheinander gelesen oder geschrieben. Bei unserem Dateizugriff stellt dieser Datenstrom die Verbindung zwischen dem Programm und der Textdatei her. Im Folgenden sprechen wir dafür von einer Dateiverbindung.

Zu dieser Verbindung verwaltet die Bibliothek Informationen, zum Beispiel die aktuelle Lese- oder Schreibposition und aufgetretene Fehler. Dafür stellt sie den Typ FILE bereit. Die Variable datei aus dem Beispiel hat den Typ FILE * und speichert die Adresse dieses Verwaltungsobjekts, wie Sie es aus dem Kapitel „Pointer und Datenaustausch“ kennen.

Das Ziel des Pointers ist also weder der gespeicherte Text noch die Datei auf dem Datenträger. Sie bearbeiten die Felder des FILE-Objekts auch nicht selbst. Stattdessen übergeben Sie den Pointer an Dateifunktionen. Die folgende Abbildung zeigt einen erfolgreichen Ablauf.

4. Text schreiben: fprintf

Sie kennen printf für Ausgaben im Terminal. fprintf verwendet dieselben Platzhalter, erhält aber als ersten Parameter die Dateiverbindung.

int geschrieben = fprintf(datei, "Messwert: %d\n", wert);

Die Zeichen und der Wert von wert werden in die geöffnete Datei ausgegeben. \n beendet die Textzeile. Der Rückgabewert ist bei Erfolg die Anzahl der ausgegebenen Zeichen. Ein negativer Rückgabewert meldet einen Schreibfehler.

Drei Verbindungen sind schon offen

Jedes C-Programm startet mit drei geöffneten Streams, die <stdio.h> als Variablen vom Typ FILE * bereitstellt:

  • stdout: die normale Ausgabe. printf(…) ist dasselbe wie fprintf(stdout, …).
  • stderr: die Ausgabe für Fehlermeldungen. Sie erscheint ebenfalls im Terminal, ist aber ein eigener Kanal.
  • stdin: die Eingabe von der Tastatur. Aus ihr liest scanf.

Diese drei Streams öffnen und schließen Sie nicht selbst. Fehlermeldungen schreiben Sie ab jetzt mit fprintf(stderr, …). Warum sich das lohnt, zeigt ein Versuch: Leiten Sie die Ausgabe Ihres Programms mit ./programm --text > ausgabe.txt in eine Datei um. Was nach stdout geht, landet in der Datei; was nach stderr geht, sehen Sie weiterhin im Terminal.

5. Puffer und Abschluss: fclose

Eine Ausgabe muss nicht sofort in der Datei ankommen. Die Bibliothek kann die Zeichen zunächst in einem Puffer sammeln. Ein Puffer ist hier ein vorübergehender Speicherbereich im Arbeitsspeicher. Mehrere kleine Ausgaben können dadurch gemeinsam weitergeschrieben werden.

Beim Aufruf von fclose(datei) versucht die Bibliothek, die noch im Ausgabepuffer liegenden Zeichen in die Datei zu schreiben. Anschließend wird die Dateiverbindung geschlossen und ihre Verwaltung freigegeben. Deshalb kann noch beim Schließen ein Schreibfehler auftreten, obwohl fprintf zuvor keinen Fehler gemeldet hat. Prüfen Sie also auch den Rückgabewert von fclose. Dabei bedeutet 0 Erfolg, EOF einen Fehler. EOF ist ein in <stdio.h> definierter Wert.

Nach jedem erfolgreichen fopen muss Ihr Programm die Verbindung durch einen Aufruf von fclose schließen. Ein Schreibfehler schließt sie nicht automatisch. Kehren Sie in diesem Fall sofort aus Ihrer Funktion zurück, ohne zu schließen, bleibt die Verbindung offen. Planen Sie den Fehlerfall deshalb so, dass auch dann fclose erreicht wird.

Nach fclose darf dieser Pointer nicht mehr für Dateizugriffe verwendet werden. Rufen Sie fclose für dieselbe Verbindung auch nach einer Fehlermeldung nicht erneut auf. Geschlossen wird der Zugang des Programms zur Datei. Die gespeicherte Datei bleibt vorhanden und kann später erneut geöffnet werden.

Erklärung anzeigen

"w" beginnt mit einer leeren Datei; ergänzen würde erst "a". Liefert fopen NULL, wurde keine Verbindung geöffnet. Liefert fopen einen gültigen Pointer, muss diese Verbindung nach dem Schreiben geschlossen werden.

6. Den Grund eines Fehlers melden: perror

Liefert fopen NULL, möchte man wissen, warum: Fehlt die Datei, fehlt ein Verzeichnis, fehlt die Berechtigung? Die Bibliothek hinterlegt den Grund in der Variablen errno aus <errno.h>. Die Funktion perror aus <stdio.h> schreibt einen eigenen Text und die Beschreibung dieses Grundes nach stderr:

FILE *datei = fopen("fehlt.txt", "r");
if (datei == NULL) {
    perror("fehlt.txt");   /* zum Beispiel: fehlt.txt: No such file or directory */
}

Rufen Sie perror direkt nach dem fehlgeschlagenen Aufruf auf. Jeder weitere Bibliotheksaufruf, auch ein printf, darf errno verändern; danach beschreibt der Wert womöglich einen ganz anderen Fehler.

Zum Nachschlagen, wie im Kapitel „Manpages und Bibliotheksdokumentation“: fopen, fprintf, fclose, stdin, stdout, stderr und perror.

7. Aufgabe: Eine erste Datei schreiben

Bearbeiten Sie die Funktion text_ausgeben in tresorraub.c aus dem Startmaterial. Die Datei notiz.txt soll Ihr Programm erzeugen; legen Sie sie nicht von Hand im Texteditor an.

  1. Legen Sie in text_ausgeben eine ganze Zahl mit dem Wert 7 an. Lassen Sie das Programm notiz.txt mit fopen im Modus "w" öffnen.
  2. Lassen Sie das Programm mit fprintf die Zeile Messwert: 7 ausgeben und danach die Verbindung mit fclose schließen. Prüfen Sie die Rückgabewerte aller drei Dateifunktionen. Bei einem Fehler soll eine verständliche Meldung auf stderr erscheinen; bei fopen mit dem Grund über perror.
  3. Übersetzen Sie im Ordner des Startmaterials mit make und starten Sie mit ./programm --text.
  4. Öffnen Sie erst nach diesem Programmlauf die erzeugte notiz.txt im Texteditor. Welchen Inhalt hat sie? Schließen Sie sie anschließend wieder.
  5. Ändern Sie die Zahl auf 9, übersetzen und starten Sie erneut. Wurde die alte Zeile ergänzt oder ersetzt? Begründen Sie die Beobachtung mit dem Öffnungsmodus.
  6. Ändern Sie den Modus auf "a" und starten Sie das Programm zweimal. Was steht jetzt in der Datei?
  7. Lassen Sie das Öffnen absichtlich scheitern, indem Sie als Dateinamen fehlt/notiz.txt verwenden; den Ordner fehlt gibt es nicht. Welche Meldung erscheint? Leiten Sie die Ausgabe wie in Abschnitt 4 in eine Datei um: Wo erscheint die Meldung jetzt?
Hinweis: Wo entsteht die Datei?

Ein relativer Dateiname wie notiz.txt bezieht sich auf das Arbeitsverzeichnis des laufenden Programms. Starten Sie es im Ordner des Startmaterials, entsteht die Datei dort. Das Arbeitsverzeichnis muss nicht der Ordner sein, in dem die Quelldatei liegt.

Hinweis: Den Fehlerfall so planen, dass fclose erreicht wird

Merken Sie sich einen Fehler beim Schreiben in einer Variablen, statt sofort zurückzukehren. Schließen Sie danach in jedem Fall und melden Sie erst dann, ob alles geklappt hat. Nur wenn schon fopen scheitert, gibt es nichts zu schließen.

Selbstkontrolle: Ergebnis
  • Nach dem ersten Lauf enthält notiz.txt die Zeile Messwert: 7, nach dem zweiten nur Messwert: 9. Bereits das erfolgreiche Öffnen mit "w" entfernt den alten Inhalt.
  • Mit "a" steht die Zeile Messwert: 9 nach zwei Läufen dreimal in der Datei: einmal vom letzten Lauf mit "w" und zweimal angehängt.
  • Mit fehlt/notiz.txt erscheint zum Beispiel fehlt/notiz.txt: No such file or directory. Weil perror nach stderr schreibt, steht die Meldung auch bei umgeleiteter Ausgabe im Terminal.
  • Ihr Code prüft fopen auf NULL und kehrt dann ohne fclose zurück. Er prüft die Rückgabe von fprintf auf einen negativen Wert und die von fclose auf EOF bzw. ungleich 0. Nach einem Fehler bei fprintf wird trotzdem genau einmal fclose aufgerufen.

Ihr Ergebnis: Ein Programm, das eine Textdatei schreibt oder ergänzt, alle Rückgabewerte prüft und Fehler mit Grund auf stderr meldet.
