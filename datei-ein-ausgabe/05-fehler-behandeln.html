Fehlende und ungültige Dateien behandeln

Dateifehler und ungültige Spieldaten erkennen, ohne den bisherigen Spielstand zu verlieren.

Theorie und Hintergrund

Lesbar bedeutet noch nicht gültig

Eine Datei kann sich öffnen lassen und trotzdem keinen gültigen Spielstand enthalten. Prüfen Sie, ob das Programm auf die Datei zugreifen konnte, ob der gelesene Text zum Format passt und ob die Werte einen möglichen Spielzustand beschreiben.

FehlerartBeispielReaktion des Programms
DateizugriffDie Datei fehlt oder ein Leseaufruf schlägt fehl.Ladeversuch abbrechen und eine verständliche Meldung ausgeben.
DateiformatEin Kennwort fehlt, die Version stimmt nicht oder nach der Inventaranzahl fehlen Namen.Die unvollständigen oder anders aufgebauten Daten ablehnen.
SpielwerteDie Figur steht in einer Wand oder die Münze liegt zugleich auf dem Feld und im Inventar.Den widersprüchlichen Zustand ablehnen.

Bei allen drei Fehlerarten bleibt der bisherige Spielstand erhalten. Eventuell für den Versuch neu angelegte Listeneinträge werden freigegeben. Eine zuvor erfolgreich geöffnete Dateiverbindung wird geschlossen.

Die bekannten Spielregeln beim Laden anwenden

Die Ladefunktion darf sich nicht darauf verlassen, dass eine Datei ausschließlich von Ihrer Speicherfunktion geschrieben wurde. Eine Person kann den Text im Editor verändern oder versehentlich Teile löschen.

Prüfen Sie Positionen zunächst gegen die Spielfeldgrenzen, bevor Sie damit auf das Raster zugreifen. Die Figur darf nicht in einer Wand oder in der verschlossenen Tür stehen. Zugzahlen dürfen nicht negativ sein. Die Zustandswerte für Ja/Nein-Angaben sind ausschließlich 0 oder 1.

Prüfen Sie auch, ob die Daten zueinander passen. Eine Münze ist entweder im Inventar oder liegt auf dem Spielfeld. Sie darf nicht an beiden Stellen zugleich vorkommen. Die Beute ist entweder noch im Tresor, im Inventar oder abgelegt. Eine geöffnete Tür bedeutet, dass der Schlüssel verbraucht wurde. Alle Regeln finden Sie gesammelt in FORMAT.md.

Fehler gezielt ausprobieren

Für eine Fehlerprüfung verändern Sie immer nur einen Punkt an einer gültigen Beispieldatei. Dann wissen Sie, welche Bedingung das Programm erkennen soll. Notieren Sie vor dem Laden den bisherigen Spielstand und das erwartete Ergebnis.

Nach einem abgelehnten Ladeversuch reicht eine Fehlermeldung allein nicht als Beleg. Prüfen Sie zusätzlich, ob Position, Zugzahl und Inventar unverändert sind und ob Sie weiterspielen können. Laden Sie danach auch wieder eine gültige Datei. So erkennen Sie, ob die Fehlerbehandlung die weitere Benutzung beeinträchtigt.

Welche Prüfungen braucht eine Ladefunktion?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Dateizugriff, Format und Spielregeln müssen getrennt geprüft werden. Erfolgreiches Öffnen sagt noch nichts über den Inhalt aus.

Aufgabe: Fehlende und ungültige Dateien behandeln

Die Dateien im Ordner beispiele/ sind für diese Aufgabe vorbereitet. Verändern Sie diese Originale nicht; verwenden Sie für eigene Änderungen eine Kopie.

  1. Prüfen Sie zuerst die gültigen Dateien start.txt, inventar.txt und abgelegt.txt. Rufen Sie dafür Ihre Ladefunktion im Textmodus mit dem jeweiligen Dateinamen auf. Vergleichen Sie den geladenen Zustand mit dem Dateiinhalt.
  2. Versuchen Sie eine nicht vorhandene Datei zu laden. Überprüfen Sie die Fehlermeldung und den Erhalt des bisherigen Spielstands.
  3. Laden Sie nacheinander die vorbereiteten ungültigen Dateien. Notieren Sie vor jedem Versuch, welche Bedingung verletzt wird. Kontrollieren Sie danach, dass das Laden abgelehnt wurde und der bisherige Zustand vollständig erhalten ist.
  4. Prüfen Sie einen Ladefehler auch im Spielfenster. Legen Sie eine Kopie einer ungültigen Beispieldatei unter dem Namen spielstand.txt im Arbeitsverzeichnis ab und drücken Sie F9. Können Sie nach der Meldung mit demselben Spielstand weiterspielen?
  5. Laden Sie wiederholt unterschiedliche gültige und ungültige Dateien. Prüfen Sie mit den im Speicher-Kapitel verwendeten Werkzeugen auf vergessene und doppelte Freigaben. Beenden Sie das Programm auch einmal mit gefülltem, geladenem Inventar. aufraeumen muss dessen Einträge freigeben.

Selbstkontrolle: Erwartete Ergebnisse

start.txt, inventar.txt und abgelegt.txt werden angenommen. Die Dateien mit ungueltig- im Namen werden abgelehnt. Jede Ablehnung lässt den bisherigen Spielstand erhalten. abgelegt.txt ergibt Position (5, 3), 24 Züge, eine offene Tür und ein leeres Inventar. Die Beute liegt auf (5, 2), die Münze auf (5, 4).
