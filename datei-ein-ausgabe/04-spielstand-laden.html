Einen Spielstand wiederherstellen

Den gespeicherten Fortschritt einlesen und den laufenden Spielstand nach erfolgreicher Prüfung ersetzen.

Theorie und Hintergrund

Aus Text wieder Werte lesen: fscanf

Zum Laden öffnen Sie die Datei mit fopen im Modus "r". Danach liest Ihr Programm den Dateiinhalt. Die Datei muss dafür nicht im Texteditor geöffnet sein.

fscanf arbeitet ähnlich wie das bekannte scanf. Als ersten Parameter erhält es zusätzlich die Dateiverbindung. Die weiteren Parameter geben das Format und die Ziele für die gelesenen Werte an. Die Ziele übergeben Sie wie bei scanf als Adressen.

int gelesen = fscanf(datei, "%d", &wert);

Für eine einzelne Zahl erwarten Sie den Rückgabewert 1. Er bedeutet, dass genau ein Wert erfolgreich zugewiesen wurde. Steht dort ein Wort statt einer Zahl, kann die Funktion 0 liefern. Ist schon vor der ersten Zuweisung das Dateiende erreicht oder ein Lesefehler aufgetreten, liefert sie EOF. Nur nach der erwarteten Anzahl erfolgreicher Zuweisungen dürfen Sie mit den gelesenen Werten weiterarbeiten.

Für Wörter verwenden Sie %s mit einer Längenbegrenzung. Bei einem Array mit 16 Zeichen lässt %15s Platz für höchstens 15 gelesene Zeichen und das abschließende Nullzeichen.

char wort[16];
int gelesen = fscanf(datei, "%15s", wort);

Das Array übergeben Sie hier ohne zusätzliches &, wie im Pointer-Kapitel behandelt. %s überspringt zunächst Leerzeichen und Zeilenumbrüche und liest dann bis zum nächsten Leerraum. Jeder erfolgreiche Leseaufruf setzt die Position in der Datei weiter. Der nächste Aufruf liest dort weiter. Kennwörter wie FIGUR vergleichen Sie nach dem Einlesen mit strcmp.

Zahlen aus einer veränderten Datei prüfen

Eine Speicherdatei kann von Hand verändert worden sein. Die Prüfung „eine Zahl gelesen“ genügt deshalb nicht immer. Insbesondere lässt sich eine Zahl, die gar nicht in int passt, mit %d nicht zuverlässig abfangen. Für solche Dateien lesen Sie die Zahl zuerst als begrenztes Wort ein und wandeln dieses danach mit strtol um.

strtol aus <stdlib.h> wandelt einen Text in eine Zahl vom Typ long um. Die 10 steht für das Dezimalsystem. Über den zweiten Parameter schreibt die Funktion in den Pointer ende, wo die erkannte Zahl im Text endet. Damit sie den Pointer ende verändern kann, erhält sie dessen Adresse &ende.

char text[] = "12";
char *ende;
errno = 0;
long zahl = strtol(text, &ende, 10);

errno aus <errno.h> ist eine Fehleranzeige der Bibliothek. Vor diesem Aufruf setzen Sie sie auf 0. Ist die Zahl selbst für long zu groß oder zu klein, meldet strtol dort ERANGE. Prüfen Sie nach dem Umwandeln die folgenden Bedingungen.

  • ende != text: Mindestens eine Ziffer wurde verarbeitet.
  • *ende == '\0': Das ganze Wort war eine Zahl. Bei 12abc zeigt ende auf das a; dieses Wort wird abgelehnt.
  • errno != ERANGE: Der Wertebereich von long wurde nicht überschritten.
  • Die Zahl liegt zwischen INT_MIN und INT_MAX aus <limits.h>, bevor sie als int gespeichert wird.

Erst danach prüfen Sie die Spielregel für den Wert, etwa „Zugzahl nicht negativ“ oder „Türzustand ist 0 oder 1“. Die Prüfung des Datentyps und die Prüfung der Spielregel sind zwei verschiedene Schritte.

Den bisherigen Spielstand erhalten

Angenommen, eine Datei enthält zunächst eine gültige Position und danach einen unzulässigen Inventarnamen. Würden Sie beim Lesen sofort den laufenden Spielstand ändern, wäre dessen Position bereits überschrieben, obwohl Sie die Datei anschließend ablehnen müssen.

Legen Sie deshalb einen zweiten Spielstand nur für den Ladeversuch an, zunächst mit dem bekannten Startzustand und leerem Inventar. Tragen Sie die gelesenen Werte dort ein. Der laufende Spielstand bleibt in dieser Zeit unverändert.

Kopieren Sie dafür nicht einfach den laufenden Spielstand mit einer Strukturzuweisung. Diese würde zwar den Pointer auf den ersten Inventareintrag kopieren, aber keine neuen Einträge anlegen. Beide Strukturen würden dieselbe Liste verwenden. Änderungen oder Freigaben an dieser Liste würden dann auch das bisherige Spiel betreffen.

Erzeugen Sie für das geladene Inventar eigene Einträge mit den vorhandenen Inventarfunktionen. Auch die Reihenfolge muss erhalten bleiben. Die bisherige Aufnahmefunktion fügt vorne ein. Wenn Sie zuerst Beute und danach Muenze aufnehmen, steht anschließend Muenze vor Beute. Berücksichtigen Sie das beim Wiederaufbau.

Einen Ladeversuch abschließen

Prüfen Sie zuerst die gesamte Datei und den neu aufgebauten Spielstand. Auch der Abschluss ENDE muss vorhanden sein. ferror(datei) zeigt an, ob beim Lesen ein Dateifehler aufgetreten ist. Ein Wert ungleich 0 meldet einen Fehler. Schließen Sie anschließend die Verbindung mit fclose und prüfen Sie dessen Ergebnis.

Bei einem Fehler geben Sie ausschließlich die Inventareinträge frei, die Sie für diesen Ladeversuch neu angelegt haben. Der bisherige Spielstand einschließlich seines Inventars bleibt erhalten.

Bei Erfolg geben Sie das bisherige Inventar frei und ersetzen Sie den bisherigen Spielstand durch den neu aufgebauten. Dessen Einträge gehören jetzt dem laufenden Spiel. Sie dürfen sie anschließend nicht noch einmal als vorübergehende Daten des Ladeversuchs freigeben.

Ein Ladeversuch hat einen neuen Inventareintrag angelegt. Dann schlägt das Anlegen des zweiten fehl. Was ist richtig?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Nur die für den fehlgeschlagenen Versuch neu angelegten Einträge werden freigegeben. Eine Zuweisung von NULL allein gibt keinen mit malloc angeforderten Speicher frei.

Zum Nachschlagen: fscanf, strtol und ferror.

Aufgabe: Einen Spielstand wiederherstellen

  1. Entwerfen Sie eine Ladefunktion. Legen Sie ihre Parameter und Rückgabewerte fest. Bei einem Fehlschlag soll der übergebene Spielstand vollständig erhalten bleiben.
  2. Öffnen Sie die Datei zum Lesen. Lesen und prüfen Sie Kennzeichnung, Version, alle Daten und den Abschluss in einem eigenen neuen Spielstand. Nutzen Sie das vereinbarte Format und die Prüfregeln aus FORMAT.md.
  3. Bauen Sie das Inventar mit eigenen neuen Listeneinträgen auf. Erhalten Sie die gespeicherte Reihenfolge und berücksichtigen Sie fehlgeschlagene Speicheranforderungen.
  4. Schließen Sie die Datei und beenden Sie den Ladeversuch wie oben beschrieben. Bei Erfolg übernimmt der laufende Spielstand die neuen Daten, bei einem Fehler bleiben die bisherigen Daten erhalten.
  5. Ergänzen Sie in taste_gedrueckt den Fall SDLK_F9 zum Laden von spielstand.txt. Geben Sie im Terminal eine Meldung aus. Ein behandelter Ladefehler soll das Spiel nicht beenden. Laden verbraucht keinen Zug.
  6. Speichern Sie einen erkennbaren Zustand mit F5. Bewegen Sie die Figur anschließend, ohne erneut zu speichern. Drücken Sie F9. Position, Zugzahl und Inventar sollen wieder dem gespeicherten Zeitpunkt entsprechen. Die Änderungen seit F5 werden dabei verworfen.
  7. Beenden und starten Sie das Programm neu. Laden Sie dieselbe Datei erneut. Prüfen Sie, ob derselbe gespeicherte Fortschritt auch nach einem Neustart wiederhergestellt wird.
Hinweis: Reihenfolge beim Einfügen

Sie können die Namen zunächst in einem begrenzten Array sammeln und dann in umgekehrter Reihenfolge mit der vorhandenen Aufnahmefunktion einfügen. Oder Sie erweitern die Liste am Ende. Entscheidend ist die Reihenfolge der fertigen Liste.
