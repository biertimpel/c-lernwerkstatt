Eindimensionale Arrays

Mehrere Werte desselben Typs unter einem Namen speichern und mit Schleifen bearbeiten.

1. Viele Werte, ein Name

Sie möchten festhalten, wie viele Züge Ihre bisherigen Versuche beim Tresorraub gedauert haben. Mit einer eigenen Variablen pro Versuch wird das schnell unübersichtlich. Außerdem kann eine Schleife solche Variablen nicht der Reihe nach durchgehen.

Ein Array fasst mehrere Werte desselben Typs zusammen. Jeder Wert ist über seine Position erreichbar, den Index:

int zuege[5] = {41, 60, 37, 52, 61};

Bei der Deklaration steht in den eckigen Klammern die Anzahl der Elemente. Beim Zugriff steht dort der Index: zuege[0] ist das erste Element.

Vorhersagen und ausprobieren

Legen Sie dieses Array in der Funktion text_ausgeben in tresorraub.c an und starten Sie Ihr Programm mit ./programm --text. Notieren Sie vor jedem Schritt, was Sie erwarten. Führen Sie das Programm erst danach aus.

  1. Welchen Wert haben zuege[1] und zuege[4]?
  2. Geben Sie alle Elemente mit einer Schleife aus. Welche Werte nimmt die Schleifenvariable an?
  3. Weisen Sie zuege[2] einen neuen Wert zu und geben Sie das Array erneut aus.
  4. Deklarieren Sie int liste[6] = {1, 2};. Welche Werte haben die übrigen vier Elemente?
  5. Lassen Sie die Größe weg: int liste[] = {4, 8, 15};. Wie viele Elemente hat das Array jetzt?
  6. Deklarieren Sie in text_ausgeben ein Array ohne Initialisierung und geben Sie es aus. Was beobachten Sie? Was meldet der Compiler? Was folgt daraus für Ihre Programme?
Selbstkontrolle: Ihre Beobachtungen

Elemente ohne eigenen Initialwert erhalten den Wert 0, sobald mindestens ein Wert in geschweiften Klammern angegeben ist. Ohne Größenangabe zählt der Compiler die Initialwerte, hier also drei. Ein lokales Array ganz ohne Initialisierung enthält unbestimmte Werte. Diese können bei jedem Lauf anders aussehen oder zufällig 0 sein. Füllen Sie ein solches Array, bevor Sie daraus lesen.

2. Gültige Indizes

Ein Array mit n Elementen hat die Indizes 0 bis n − 1. C prüft beim Zugriff nicht, ob ein Index gültig ist. Ein Zugriff außerhalb ist undefiniertes Verhalten: Das Programm kann scheinbar richtig laufen, falsche Werte liefern oder abstürzen. Das Verhalten kann sich bei jeder kleinen Änderung am Programm ändern. Ein unauffälliger Testlauf beweist deshalb nichts.

Sehen Sie sich die Schleife aus Abschnitt 1 an. Wo steht die Grenze? Was würde passieren, wenn Sie < durch <= ersetzen? Beantworten Sie das durch Überlegen, nicht durch Ausprobieren.

Hinweis: Zugriffsfehler finden lassen

Mit den Compilern GCC und Clang können Sie zusätzlich mit -fsanitize=address übersetzen. Das Programm meldet dann viele Zugriffe außerhalb eines Arrays während der Ausführung. Das ersetzt aber keine eigene Prüfung der Grenzen und steht nicht auf allen Systemen zur Verfügung.

Gegeben ist int werte[4] = {3, 8};. Welche Aussagen stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die ersten beiden Aussagen stimmen. Ein Array mit vier Elementen endet bei Index 3. Weil zwei Initialwerte angegeben sind, erhalten die übrigen Elemente 0. Unbestimmt wären die Werte nur ganz ohne Initialisierung.

3. Die Länge eines Arrays

Auf der Seite Datentypen haben Sie gesehen, dass Werte im Speicher als Bits liegen. Acht Bits bilden ein Byte, wie das Muster 01001101 aus dieser Seite. Speichergrößen gibt man in Bytes an. Ein char belegt in C immer genau ein Byte. Wie viele Bytes andere Typen belegen, hängt vom System ab.

Mit dem Operator sizeof fragen Sie die Größe ab. Geben Sie sizeof(char), sizeof(int) und sizeof(double) aus und notieren Sie die Werte für Ihr System. Das Ergebnis von sizeof hat den Typ size_t, eine vorzeichenlose Ganzzahl für Größen. Mit printf geben Sie es über %zu aus.

Auch für Arrays liefert sizeof eine Größe in Bytes. sizeof(zuege) ist die Größe des ganzen Arrays, sizeof(zuege[0]) die Größe eines einzelnen Elements.

Aufgabe: Die Anzahl der Elemente berechnen

  1. Geben Sie sizeof(zuege) und sizeof(zuege[0]) aus. Passen die Werte zu Ihren Messungen von oben?
  2. Entwickeln Sie aus diesen beiden Werten einen Ausdruck, der die Anzahl der Elemente liefert. Er soll auch dann noch stimmen, wenn Sie das Array später verlängern oder den Elementtyp ändern.
  3. Prüfen Sie Ihren Ausdruck: Verlängern Sie das Array auf sieben Werte und ändern Sie den Typ in double. Liefert Ihr Ausdruck weiterhin die richtige Anzahl?
Gegeben ist int zuege[5];. Welche Ausdrücke liefern die Anzahl der Elemente?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die zweite und dritte Aussage stimmen, beide liefern 5. Die dritte ist aber an den Typ int gebunden: Ändern Sie den Elementtyp in double und vergessen, sizeof(int) anzupassen, stimmt das Ergebnis nicht mehr. Mit sizeof(zuege[0]) passt sich der Ausdruck von selbst an. sizeof(zuege) allein ist die Größe in Bytes, auf üblichen Systemen 20.

Diese Rechnung funktioniert nur dort, wo das Array deklariert ist. Eine Funktion, der Sie ein Array übergeben, kennt dessen Länge nicht. Geben Sie die Länge deshalb als eigenen Parameter mit. Ein Parameter für ein Array wird so geschrieben:

int summe(int werte[], size_t anzahl);

Warum eine Funktion die Länge nicht selbst bestimmen kann, klären Sie im Kapitel „Pointer und Datenaustausch“.

Wenn dieselbe Größe an mehreren Stellen vorkommt, geben Sie ihr einen Namen, zum Beispiel mit #define VERSUCHE 5. Dann ändern Sie sie später nur an einer Stelle. Wie #define genau funktioniert, lernen Sie auf Seite 3.

Gegeben ist double messung[6];. Welche Aussagen stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die zweite und dritte Aussage stimmen. Ein double belegt auf üblichen Systemen 8 Bytes. sizeof(messung) ist deshalb 48, nicht 6. Ein Zugriff außerhalb des Arrays ist undefiniertes Verhalten. Eine Fehlermeldung ist dabei nicht garantiert.

4. Aufgabe: Versuche auswerten

Ausgangslage

Eine Spielerin hat den Tresorraub fünfmal gespielt. Nach jedem Versuch hat sie notiert, wie viele Züge sie verbraucht hat. Das ist das Array aus Abschnitt 1:

int zuege[5] = {41, 60, 37, 52, 61};

Erlaubt sind höchstens 60 Züge. Der letzte Versuch mit 61 Zügen hat das Zuglimit also überschritten.

Wie die Teile zusammenhängen

Das Gerüst ruft bei ./programm --text Ihre Funktion text_ausgeben auf. Diese Funktion ist in tresorraub.h vorgegeben, damit das Gerüst sie findet. Alles andere entsteht in tresorraub.c:

  1. Sie legen das Array mit den Zugzahlen in text_ausgeben als lokale Variable an.
  2. Sie schreiben drei eigene Funktionen, die eine Reihe von Zugzahlen auswerten. Diese Funktionen stehen nicht in tresorraub.h, sondern nur in tresorraub.c, und zwar oberhalb von text_ausgeben.
  3. In text_ausgeben rufen Sie Ihre Funktionen auf, übergeben dabei das Array und seine Länge und geben die Ergebnisse aus.

Was Sie programmieren

Schreiben Sie drei Funktionen. Jede beantwortet eine Frage zu einer Reihe von Versuchen:

FunktionFrageErgebnis für die Beispieldaten
1Wie viele Versuche haben höchstens 60 Züge gebraucht?4 (genau 60 Züge sind noch erlaubt)
2Wie viele Züge hat der kürzeste Versuch gebraucht?37
3Wie viele Züge wurden im Durchschnitt gebraucht?50,2

Für alle drei Funktionen gilt:

  • Sie erhalten zwei Parameter: ein Array mit Zugzahlen und die Anzahl der Versuche. Wie ein Array-Parameter geschrieben wird, steht in Abschnitt 3. Beim Aufruf in text_ausgeben übergeben Sie Ihr Array und seine Länge.
  • Sie geben ihr Ergebnis mit return zurück. Die Ausgabe mit printf erfolgt nicht in der Funktion, sondern dort, wo Sie sie aufrufen.
  • Sie müssen für jede Anzahl von Versuchen funktionieren, nicht nur für fünf.
  • Den Namen und den Rückgabetyp wählen Sie selbst. Überlegen Sie beim Rückgabetyp: Welche Funktion liefert eine ganze Zahl, welche eine Zahl mit Nachkommastellen?

So gehen Sie vor

  1. Testfälle festlegen. Notieren Sie für jede Funktion, welches Ergebnis Sie bei welchen Daten erwarten. Nehmen Sie neben den Beispieldaten mindestens diese Fälle dazu: eine Reihe mit nur einem Versuch, eine Reihe, in der alle Versuche über 60 liegen, und eine Reihe, in der der kürzeste Versuch ganz vorne oder ganz hinten steht.
  2. Vertrag aufschreiben. Halten Sie für jede Funktion in zwei, drei Sätzen fest, was sie erwartet und was sie liefert. Das ist dieselbe Information, die Sie im Kapitel „Manpages“ für Bibliotheksfunktionen nachgeschlagen haben: Parameter, Rückgabewert und Sonderfälle.
  3. Den Sonderfall „keine Versuche“ entscheiden. Was soll jede Funktion liefern, wenn die Anzahl 0 ist? Bei der ersten Frage ist die Antwort klar. Beim kürzesten Versuch und beim Durchschnitt gibt es kein sinnvolles Ergebnis. Entscheiden Sie, was die Funktion dann zurückgibt, und schreiben Sie es in den Vertrag.
  4. Implementieren. Schreiben Sie die Funktionen in tresorraub.c oberhalb von text_ausgeben. Legen Sie für jeden Testfall in text_ausgeben ein eigenes Array an, rufen Sie Ihre Funktionen damit auf und geben Sie die Ergebnisse aus.
  5. Prüfen. Vergleichen Sie jedes Ergebnis mit Ihrer Erwartung aus Schritt 1 und notieren Sie Abweichungen.
Denkhilfe: Den kürzesten Versuch finden

Womit vergleichen Sie den ersten Wert? Ein fester Startwert wie 1000 funktioniert bei diesen Daten, setzt aber voraus, dass kein Versuch länger dauert. Welcher Startwert kommt ohne diese Annahme aus?

Selbstkontrolle: Durchschnitt 50 statt 50,2?

Wenn Sie zwei ganze Zahlen dividieren, rechnet C ohne Nachkommastellen: 251 / 5 ergibt 50. Sehen Sie sich an, welche Typen an Ihrer Division beteiligt sind. Den Unterschied zwischen Ganzzahldivision und Gleitkommadivision kennen Sie von der Seite Berechnungen.

Ihr Ergebnis: Drei Funktionen mit aufgeschriebenem Vertrag, Ihre Testfälle mit erwarteten und beobachteten Ergebnissen und Ihre Entscheidung für den Fall ohne Versuche.
