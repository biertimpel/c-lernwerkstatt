Strukturen

Werte unterschiedlicher Bedeutung zu einem eigenen Datentyp zusammenfassen.

1. Werte, die zusammengehören

Eine Position im Spielfeld besteht aus zwei Koordinaten. Mit zwei getrennten Variablen müssen Sie bei jeder Funktion zwei Parameter übergeben und darauf achten, dass x und y nicht vertauscht werden. Eine Funktion kann außerdem nur einen Wert zurückgeben, also keine ganze Position.

Eine Struktur fasst mehrere Werte zu einem neuen Datentyp zusammen. Die einzelnen Werte heißen Felder und dürfen unterschiedliche Typen haben. Ein Beispiel, das nichts mit dem Spiel zu tun hat:

typedef struct {
    int stunde;
    int minute;
} Uhrzeit;

Uhrzeit beginn = {8, 30};
Uhrzeit ende = {.stunde = 10, .minute = 0};
printf("%d:%02d\n", beginn.stunde, beginn.minute);

Mit typedef erhält der neue Typ den Namen Uhrzeit. Ein Feld erreichen Sie mit einem Punkt: beginn.minute. Bei der Initialisierung können Sie die Werte in der Reihenfolge der Felder angeben oder die Felder mit Namen ansprechen.

Mit und ohne typedef

Eine Struktur lässt sich auch ohne typedef definieren. Dann bekommt sie hinter dem Wort struct einen Namen, und der Typ heißt struct Uhrzeit, also zwei Wörter. Bei jeder Verwendung schreiben Sie struct mit:

struct Uhrzeit {
    int stunde;
    int minute;
};

struct Uhrzeit beginn = {8, 30};

Lassen Sie struct hier weg und schreiben nur Uhrzeit beginn, meldet der Compiler einen unbekannten Typnamen. typedef gibt dem Strukturtyp einen zusätzlichen Namen aus einem Wort. Danach schreiben Sie wie im Beispiel oben nur noch Uhrzeit beginn. Am Inhalt der Struktur und am Zugriff auf die Felder ändert sich dadurch nichts.

Beide Schreibweisen lassen sich auch verbinden: typedef struct Uhrzeit { … } Uhrzeit;. Dann funktionieren struct Uhrzeit und Uhrzeit. Diese Form brauchen Sie später im Kapitel „Dynamischer Speicher und Listen“, wenn eine Struktur auf eine Struktur desselben Typs verweisen soll. In diesem Kapitel können Sie frei wählen. Bleiben Sie aber innerhalb Ihres Programms bei einer Schreibweise.

Einen Typ für Positionen

Definieren Sie einen eigenen Strukturtyp für eine Position im Spielfeld. Legen Sie damit die Startposition der Spielfigur aus SPIELFELD.md an. Probieren Sie dann aus und notieren Sie jeweils vorher Ihre Erwartung:

  1. Weisen Sie eine Position einer zweiten Variablen zu und ändern Sie danach ein Feld der zweiten Variablen. Was passiert mit der ersten?
  2. Vergleichen Sie zwei Positionen mit ==. Was meldet der Compiler? Entfernen Sie den Vergleich danach wieder, damit sich Ihr Programm übersetzen lässt.
  3. Schreiben Sie eine Funktion, die eine Position als Parameter erhält und darin ein Feld ändert. Geben Sie die Position nach dem Aufruf aus. Was beobachten Sie?
Selbstkontrolle: Ihre Beobachtungen

Bei der Zuweisung werden alle Felder kopiert. Danach sind beide Variablen unabhängig voneinander. Strukturen lassen sich nicht mit == vergleichen, der Compiler bricht mit einem Fehler ab. Einen Vergleich schreiben Sie deshalb als eigene Funktion. Auch beim Aufruf einer Funktion wird kopiert: Die Funktion arbeitet mit einer Kopie, die Position des Aufrufers bleibt unverändert. Das kennen Sie schon von der Seite Funktionen: Parameter erhalten Kopien der übergebenen Werte. Für Strukturen gilt dasselbe wie für int. Wie eine Funktion das Original ändern kann, lernen Sie im Kapitel „Pointer und Datenaustausch“.

Gegeben ist Uhrzeit a = {8, 30}; Uhrzeit b = a; b.minute = 45;. Welche Aussagen stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die erste und dritte Aussage stimmen. Bei der Zuweisung entsteht eine unabhängige Kopie. Strukturen lassen sich nicht mit == vergleichen, der Ausdruck a == b wird gar nicht übersetzt.

2. Wächter beschreiben

Ein Wächter steht auf einem Feld und überwacht alle Felder bis zu einer bestimmten Reichweite. Im Spielfeld gibt es zwei Wächter mit unterschiedlicher Reichweite. Ihre Daten stehen in SPIELFELD.md.

  1. Definieren Sie einen Strukturtyp für einen Wächter. Eine Struktur darf als Feld auch eine andere Struktur enthalten.
  2. Legen Sie ein Array mit beiden Wächtern an. Wie greifen Sie auf die x-Koordinate des zweiten Wächters zu?
  3. Geben Sie alle Wächter mit einer Schleife aus.

Überlegen Sie: Welche Vorteile hat ein Array von Wächtern gegenüber zwei einzelnen Variablen? Was müssten Sie ändern, wenn ein dritter Wächter hinzukommt?

3. Aufgabe: Überwachte Felder

Für dieses Kapitel gilt folgende Regel: Der Rasterabstand zweier Felder ist die Summe aus waagerechtem und senkrechtem Abstand. Diagonale Abkürzungen gibt es nicht, genau wie bei der Bewegung der Spielfigur. Ein Feld ist überwacht, wenn sein Rasterabstand zu mindestens einem Wächter höchstens dessen Reichweite beträgt. Das Feld des Wächters selbst gehört dazu. Wände spielen dabei keine Rolle.

  1. Entwerfen Sie eine Funktion für den Rasterabstand zweier Positionen. Schlagen Sie nach, ob die C-Bibliothek eine Funktion für den Betrag einer ganzen Zahl anbietet, und in welchem Header sie steht.
  2. Entwerfen Sie eine Funktion, die für eine Position feststellt, ob sie überwacht ist. Welche Daten braucht sie als Parameter?
  3. Erweitern Sie Ihre Ausgaben des Grundrisses von Seite 3: Markieren Sie freie, überwachte Felder im Text mit einem eigenen Zeichen und im Fenster mit dem Piktogramm für Überwachung.

Notieren Sie Testfälle, bevor Sie implementieren. Denken Sie an Felder genau an der Grenze der Reichweite, an das Feld des Wächters selbst und daran, dass der Abstand von A nach B gleich dem von B nach A sein muss.

Denkhilfe: Testfälle an der Grenze

Ein Wächter mit Reichweite 2 steht auf (9, 5). Welche Felder in Zeile 5 sind überwacht? Welches ist das erste Feld rechts davon, das nicht mehr überwacht ist? Gibt es ein überwachtes Feld, das weder in derselben Zeile noch in derselben Spalte liegt?

Selbstkontrolle: Erwartete Ergebnisse

Der Rasterabstand von (1, 5) nach (3, 6) beträgt 3, ebenso in umgekehrter Richtung. Die Startposition (3, 7) ist nicht überwacht. (2, 5), (9, 7) und (11, 5) sind überwacht, (12, 5) nicht mehr. Insgesamt sind 17 freie Felder überwacht.

Ein Wächter hat die Felder position (eine Struktur mit x und y) und reichweite. Die Wächter stehen im Array waechter. Welche Aussagen stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die erste und dritte Aussage stimmen. Der Index gehört zum Array, die Feldnamen folgen danach. Der Rasterabstand von (9, 5) nach (11, 6) beträgt 2 + 1 = 3 und liegt damit außerhalb der Reichweite 2.

Ihr Ergebnis: Strukturtypen für Positionen und Wächter, ein Array mit beiden Wächtern, zwei getestete Funktionen und eine Ausgabe des Spielfelds mit markierten Überwachungsbereichen, im Text und im Fenster.
