Ein Spielstand als Datenstruktur

Arrays, Zeichenketten und Strukturen zu einem vollständigen Spielstand zusammensetzen.

1. Was ein Spielstand wissen muss

Laut Spielbeschreibung aus „Vom Problem zum Programm II“ enthält die Textausgabe des Spielstands die Position der Spielfigur, den Inhalt des Inventars, die verbrauchten Züge sowie die Zustände von Tür, Tresor und einsammelbaren Gegenständen. Alle Positionen finden Sie in SPIELFELD.md.

Entwerfen Sie einen Strukturtyp, der einen vollständigen Spielstand beschreibt. Halten Sie in Ihrer Projektnotiz fest, welche Felder er enthält und warum. Folgende Fragen helfen bei der Entscheidung:

  • Welche Daten ändern sich während des Spiels, welche bleiben immer gleich?
  • Tragen Sie Tür, Tresor und Gegenstände als Zeichen in den Grundriss ein, oder speichern Sie sie getrennt mit eigener Position und eigenem Zustand? Was ist einfacher, wenn die Figur den Schlüssel aufnimmt? Was ist einfacher bei der Ausgabe?
  • Wie stellen Sie das Inventar dar? Es kann höchstens Schlüssel, Beute und Münze enthalten.
  • Welche Typen aus den vorigen Seiten können Sie wiederverwenden?

Vergleichen Sie Ihren Entwurf mit Ihrem Plan aus „Vom Problem zum Programm II“. Was hat sich geändert, und warum?

Denkhilfe: Zwei Darstellungen abwägen

Spielen Sie für beide Varianten gedanklich durch, was beim Aufnehmen des Schlüssels geändert werden muss. Was passiert in jeder Variante mit dem Feld, auf dem der Schlüssel lag? Wie finden Sie heraus, ob die Tür offen ist? Es gibt keine allein richtige Lösung. Entscheidend ist, dass Sie Ihre Wahl begründen können.

Welche Aussagen zum Entwurf des Spielstands stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die erste und dritte Aussage stimmen. Das Zuglimit ist eine Regel, die für jedes Spiel gleich ist. Es kann als Konstante im Programm stehen. Den Grundriss dürfen Sie in die Struktur aufnehmen oder getrennt halten, beides ist vertretbar. Die Rangfolge der Zeichen legen Sie selbst fest. Sie muss nur dokumentiert und eindeutig sein.

2. Aufgabe: Startzustand und Ausgabe

  1. Entwerfen Sie eine Funktion, die einen Spielstand im Startzustand liefert.
  2. Entwerfen Sie eine Funktion, die für ein Feld das Zeichen für die Darstellung bestimmt. Auf einem Feld können mehrere Dinge zusammentreffen, zum Beispiel die Spielfigur und ein überwachtes Feld. Legen Sie eine Rangfolge fest und dokumentieren Sie sie zusammen mit Ihrer Zeichenlegende.
  3. Geben Sie das gesamte Spielfeld mit dieser Funktion als Text aus.
  4. Zeichnen Sie den Startzustand auch im Fenster, mit einem passenden Piktogramm für jedes Objekt. Ihre Funktion zeichne kann dafür in jedem Bild einen Spielstand im Startzustand anlegen.
  5. Geben Sie den Spielstand zusätzlich als Text aus. Verwenden Sie dafür Ihre Statuszeile von Seite 2 und ergänzen Sie Inventar und Zustände.

Notieren Sie, was die Ausgabe des Startzustands enthalten muss, bevor Sie sie zum ersten Mal ausführen. Prüfen Sie dann jedes Objekt aus SPIELFELD.md an seiner Position.

Hinweis: Objekte im Fenster

Die Piktogramme der Objekte haben transparente Zellen. Zeichnen Sie deshalb zuerst den Untergrund des Feldes und danach das Objekt darüber. Welche Rangfolge aus Ihrer Textdarstellung können Sie dafür wiederverwenden?

Selbstkontrolle: Der Startzustand

Die Spielfigur steht auf (3, 7). Es sind 0 von 60 Zügen verbraucht, das Inventar ist leer. Die Tür ist verschlossen, die Beute liegt im Tresor. Schlüssel und Münze liegen auf ihren Feldern. Die Startposition ist nicht überwacht. In Ihrer Darstellung müssen alle acht Einträge aus der Tabelle in SPIELFELD.md an der richtigen Stelle erscheinen.

Ihr Ergebnis: Ein begründeter Strukturtyp für den Spielstand, eine Funktion für den Startzustand, die Ausgabe des Spielfelds mit Legende, die Darstellung im Fenster und eine Textausgabe des Spielstands.

3. Eine Beobachtung für das nächste Kapitel

Schreiben Sie eine Funktion, die einen Spielstand als Parameter erhält und darin die Zahl der verbrauchten Züge um eins erhöht. Rufen Sie sie auf und geben Sie den Spielstand danach aus. Notieren Sie vorher Ihre Erwartung.

Erinnern Sie sich an zwei frühere Beobachtungen: Auf der Seite Funktionen haben Sie gelernt, dass Parameter Kopien der übergebenen Werte erhalten. Auf Seite 4 haben Sie ausprobiert, dass das auch für Strukturen gilt: Eine Funktion, die ein Feld einer übergebenen Position ändert, verändert die Position des Aufrufers nicht. Überlegen Sie jetzt: Was wird bei Ihrem Spielstand alles kopiert? Wie groß ist er laut sizeof? Ein Array lässt sich nicht mit = zuweisen. Wird ein Array, das Feld einer Struktur ist, beim Kopieren der Struktur mitkopiert?

Für die Bewegung der Spielfigur muss eine Funktion den Spielstand des Aufrufers verändern können. Wie das geht, lernen Sie im Kapitel „Pointer und Datenaustausch“. Bewahren Sie Ihr Programm dafür auf.

Selbstkontrolle: Kopie des Spielstands

Der Spielstand des Aufrufers bleibt unverändert, auch die Zahl der Züge. Beim Kopieren einer Struktur werden alle Felder kopiert, auch ein enthaltenes Array wie der Grundriss. Enthält Ihr Spielstand den Grundriss, sind das allein dafür 144 Bytes bei jedem Aufruf.

Welche Aussagen zum Kopieren stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die zweite und dritte Aussage stimmen. Eine Zuweisung an ein ganzes Array lehnt der Compiler ab. Eine Struktur wird dagegen immer vollständig kopiert, mit allen Feldern und den darin enthaltenen Arrays.
