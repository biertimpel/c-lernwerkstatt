Datenstrukturen

Mehrere zusammengehörige Werte speichern: Arrays, Zeichenketten und Strukturen.

Lernziele und Arbeitsweise

Bisher stand in Ihren Programmen für jeden Wert eine eigene Variable. Für den Tresorraub reicht das nicht mehr: Das Spielfeld besteht aus 135 Feldern, es gibt mehrere Wächter, eine Position besteht aus zwei Koordinaten, und der Spielstand soll als Text ausgegeben werden. In diesem Kapitel lernen Sie die Mittel kennen, mit denen C solche Daten zusammenfasst.

  • Ein- und zweidimensionale Arrays anlegen, initialisieren und mit Schleifen durchlaufen.
  • Gültige Indizes bestimmen und vor jedem Zugriff sicherstellen.
  • Zeichenketten als Zeichen-Arrays mit abschließendem '\0' verstehen und sizeof von strlen unterscheiden.
  • Zusammengehörige Werte in einer Struktur zusammenfassen.
  • Für ein Problem eine passende Datendarstellung entwerfen und die Entscheidung begründen.

Die Seiten erklären die Sprachmittel an kleinen Beispielen. Wie Sie damit die Daten des Tresorraubs darstellen, entscheiden Sie selbst. Die Seiten geben keinen fertigen Code für die Aufgaben vor: Funktionsnamen, Parameter und Aufbau Ihres Programms entwerfen Sie selbst.

Ihr durchgehendes Programm: Die Daten des Tresorraubs

Über alle Seiten hinweg entsteht ein Programm, das den Startzustand des Tresorraubs speichert, als Text ausgibt und im Fenster zeichnet: Spielfeld, Spielfigur, Wächter und Gegenstände. Bewegt wird noch nichts. Dafür brauchen Sie die Mittel aus dem nächsten Kapitel „Pointer und Datenaustausch“.

Grundriss, Positionen und Regeln für dieses Kapitel stehen in der Datei SPIELFELD.md. Das Startmaterial (ZIP) enthält diese Datei, das SDL2-Programmgerüst und die Piktogramme aus dem Kapitel „Manpages“ sowie ein Makefile. Ihr eigener Code entsteht in tresorraub.c: Textausgaben in der Funktion text_ausgeben, die Sie mit ./programm --text starten, und die Darstellung im Fenster in zeichne. Wie das zusammenspielt, steht in der README. Arbeiten Sie auf allen Seiten in derselben Datei weiter und sichern Sie getestete Zwischenstände.

So arbeiten Sie mit dem Kapitel

Viele Aufgaben beginnen mit einer Vorhersage: Notieren Sie, was Sie erwarten, bevor Sie das Programm ausführen. Weicht das Ergebnis ab, ist das kein Fehlschlag, sondern der interessanteste Teil der Aufgabe! Halten Sie fest, was Sie daraus gelernt haben.

Führen Sie wieder eine Projektnotiz: Datendarstellung, Funktionsverträge, Testfälle mit erwarteten Ergebnissen und offene Fragen. Notieren Sie Testfälle, bevor Sie eine Funktion implementieren.

Direkt in den Abschnitten prüfen Sie Ihr Verständnis mit Multiple-Choice-Fragen. Bei jeder Frage können eine oder mehrere Antworten richtig sein. Die aufklappbaren Hilfen enthalten Denkfragen und erwartete Ergebnisse, aber keinen fertigen Code.
