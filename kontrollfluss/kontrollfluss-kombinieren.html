Kontrollfluss kombinieren: Ein Parkhaustag

Ihr Parkhausprogramm trifft bereits Entscheidungen, wiederholt Abläufe und prüft die Schranke. Zum Abschluss erweitern Sie es selbstständig zu einem Tagesbetrieb mit Ein- und Ausfahrten.

Lernziele und Arbeitsweise

  • Bekannte Programmteile selbstständig zu einem vollständigen Betriebsablauf zusammenführen.
  • Eine Erweiterung planen und vorhandene Regeln und Bilanzprüfungen anpassen.
  • Eigene Testfälle entwickeln, Fehler eingrenzen und die Lösung begründen.

Sie benötigen die drei vorherigen Parkhausaufgaben. Nutzen Sie Ihre vorhandenen Lösungen als Bausteine, passen Sie deren Annahmen aber bewusst an. Hier bleibt kein Fahrzeug in einer Warteschlange: Ist die Einfahrt nicht möglich, wird es abgewiesen. Eine Ausfahrt aus einem leeren Parkhaus wird ebenfalls abgelehnt.

Entwickeln Sie Ihre bestehende programm.c aus „For-Schleifen“ weiter. Behalten Sie Ihr Makefile und sichern Sie vor dem Umbau eine Kopie des getesteten Stands. Sie benötigen keinen neuen Aufgabenordner und kein neues Gerüst. Speichern Sie Änderungen und verwenden Sie wie bisher make und ./programm.

Ihre Sensorprüfung bleibt Bestandteil jeder erfolgreichen Einfahrt. Für die normalen Tagesbilanzen wird der Sensor rechtzeitig frei; einen blockierten Sensor testen Sie separat als Abbruchfall.

1. Die Reihenfolge macht einen Unterschied

Das Parkhaus hat zwei Plätze und ist voll. Ein Fahrzeug möchte ausfahren, eines möchte einfahren. Bearbeiten Sie gedanklich beide Reihenfolgen. Notieren Sie jeweils die Endbelegung und ob die Einfahrt erfolgreich war.

Welche Aussagen stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

Die ersten beiden Aussagen stimmen. Die Einfahrtsentscheidung hängt von der Belegung in genau diesem Moment ab, nicht von einer späteren Ausfahrt. Deshalb legen wir die Reihenfolge für die Simulation ausdrücklich fest.

2. Abschlussaufgabe: Ein Parkhaustag

Erweitern Sie Ihre Stundenbilanz aus „For-Schleifen“ anhand der folgenden Anforderungen. Behalten Sie Ihre Startwertprüfung, Stundenschleife, Einfahrtsregel, Sensorprüfung und bisherigen Bilanzzähler bei und passen Sie sie dort an, wo die neuen Regeln es erfordern. Ihre bekannte Ausfahrtsregel kommt wieder hinzu. Planen Sie die Umsetzung selbst; eine bestimmte Schleifenform oder die Verwendung von switch ist nicht vorgeschrieben.

Verbindliche Regeln

  • Konfigurierbar sind Kapazität, Startbelegung, Anzahl der Stunden sowie Einfahrts- und Ausfahrtsversuche pro Stunde. Die beiden Versuchszahlen bleiben über den Tag konstant.
  • Zulässig sind 0 bis 100 Plätze, 0 bis 24 Stunden und jeweils 0 bis 100 Versuche pro Stunde. Die Startbelegung muss zwischen 0 und Kapazität liegen. Diese kleinen Grenzen halten die Simulation und ihre int-Zähler überschaubar. Ungültige Konfiguration: verständliche Meldung, Fehlerstatus 1, kein Simulationsbeginn.
  • In jeder Stunde werden zuerst alle Ausfahrtsversuche, danach alle Einfahrtsversuche verarbeitet. Jeder Versuch betrifft genau ein Fahrzeug.
  • Ausfahrt nur bei positiver Belegung; Einfahrt nur bei freiem Platz. Abgelehnte Versuche ändern die Belegung nicht. Die Belegung darf zu keinem Zeitpunkt negativ werden oder die Kapazität überschreiten.
  • Nach jeder erfolgreichen Einfahrt wird die vorhandene Sensorprüfung mit neuem Versuchszähler durchgeführt. Bei blockiertem Sensor: aktueller Zustand, Fehlermeldung und Fehlerstatus 1, keine weiteren Fahrzeugversuche. Die Einfahrt bleibt gezählt. Sensorparameter müssen mindestens 1 sein; reguläre Referenzfälle verwenden ein Limit von 3 Prüfungen und Freigabe ab Prüfung 2. Behalten Sie den von Ihnen gewählten sprechenden Namen für das Versuchslimit bei.
  • Zählen Sie erfolgreiche Einfahrten, erfolgreiche Ausfahrten, abgewiesene Einfahrten und erfolglose Ausfahrtsversuche getrennt für den gesamten Tag.
  • Geben Sie pro Stunde eine kurze Zustandsmeldung und am Ende die vier Tageszähler und die Endbelegung aus. Prüfen Sie die Tagesbilanz auf Widersprüche. Bei 0 Stunden bleibt der Startzustand unverändert; alle Ereigniszähler sind 0. Bei einem Sensorabbruch wird keine vollständige Tagesbilanz erwartet.

Vorgehen selbst planen

Schreiben Sie vor dem Programmieren auf, welche Zustandsgrößen und Zähler Sie benötigen und welche Werte vor beziehungsweise innerhalb einer Stunde initialisiert werden. Teilen Sie die Umsetzung in selbst gewählte, testbare Etappen. Bringen Sie zuerst einen kleinen Fall zum Laufen, bevor Sie die vollständige Tagesbilanz ergänzen.

Sie haben bereits eine Schleife innerhalb einer Schleife verwendet. Überlegen Sie jetzt: Welche Ihrer bisherigen Variablen gelten für den gesamten Betrieb, welche beginnen für jedes Fahrzeug neu? Was bedeutet das für die zusätzlichen Fahrzeugversuche pro Stunde?

3. Eigene Tests und Bilanzprüfung

Erstellen Sie vor der Umsetzung einen eigenen Testplan. Notieren Sie Konfiguration, erwartete Endbelegung, Ereigniszähler und Rückgabestatus. Decken Sie normalen Betrieb, volles und leeres Parkhaus, keine Betriebsstunden, Kapazität 0, keine Ankünfte, keine Ausfahrten sowie ungültige Werte ab. Prüfen Sie den blockierten Sensor separat, einschließlich der bereits gezählten Einfahrt.

Die bisherigen Bilanzformeln müssen sich ändern: Es gibt nun mehrere Einfahrtsversuche pro Stunde und erfolgreiche Ausfahrten. Kontrollieren Sie bei vollständig durchlaufenem Tag:

  • Endbelegung = Startbelegung + erfolgreiche Einfahrten − erfolgreiche Ausfahrten.
  • Erfolgreiche + abgewiesene Einfahrten = Anzahl der Stunden × Einfahrtsversuche pro Stunde.
  • Erfolgreiche + erfolglose Ausfahrten = Anzahl der Stunden × Ausfahrtsversuche pro Stunde.

Ein Bilanzfehler ist etwas anderes als eine normale Abweisung. Bei einem internen Widerspruch: Fehlermeldung und Fehlerstatus 1. Für gültige Abläufe ist der Status 0, auch wenn Fahrzeuge abgewiesen wurden. Unter Linux/macOS können Sie direkt nach ./programm mit echo $? den Status prüfen.

Wenn ein Test fehlschlägt, verkleinern Sie ihn auf eine Stunde und wenige Fahrzeuge. Geben Sie die Belegung vor und nach jedem Versuch aus und suchen Sie die erste Abweichung. Ändern Sie nicht gleichzeitig mehrere Bedingungen. Prüfen Sie nach der Korrektur auch Ihre bisherigen Tests erneut.

Überarbeiten Sie anschließend Ihren Code: sprechende Namen, einheitliche Einrückung, Klammern bei allen Blöcken und Kommentare zur Bedeutung der Regeln. Zeigen Sie der Betreuung Ihre Simulation, Ihren Testplan und einen gefundenen oder gezielt eingebauten Fehler samt Diagnose. Begründen Sie Ihre Schleifenwahl und Ihre Tests. Wiederkehrende Abläufe in eigene Funktionen auszulagern, folgt im nächsten Thema.

4. Hilfen und Selbstkontrolle

Nutzen Sie die Hinweise bei Bedarf. Vergleichen Sie Referenzergebnisse und Musterlösung erst nach einem eigenen Versuch.

Einstiegshilfe: Nur einen Betriebsabschnitt erweitern

Falls Ihnen der Einstieg schwerfällt, stellen Sie Kapazität 2, Belegung 2 und eine Betriebsstunde ein. Ergänzen Sie zuerst einen Ausfahrtsversuch und danach drei Einfahrtsversuche mit der vorhandenen Sensorprüfung. Erwarten Sie eine erfolgreiche Ausfahrt, eine erfolgreiche Einfahrt, zwei Abweisungen und Endbelegung 2. Passen Sie Ihre bisherige Bilanzprüfung an, bevor Sie diesen Test ausführen.

Erster Hinweis: Zustände und Zähler

Trennen Sie Konfiguration, veränderliche Belegung und aufsummierte Tageszähler. Merken Sie sich die Startbelegung für die Bilanz. Tageszähler werden nicht pro Stunde zurückgesetzt; Versuchszähler beginnen dagegen pro Stunde und der Sensorzähler pro erfolgreicher Einfahrt neu.

Zweiter Hinweis: Struktur

Eine mögliche Lösung hat eine äußere Stundenschleife und darin zwei aufeinanderfolgende Versuchsschleifen. Jede Versuchsschleife enthält die entsprechende Entscheidung. Andere Strukturen sind ebenfalls richtig, wenn sie dieselbe Ereignisreihenfolge und dieselben Regeln einhalten.

Selbstkontrolle: Referenzfälle

Hier bedeuten „Ein/Aus“ die erfolgreichen Vorgänge, „Abgew.“ die abgewiesenen Einfahrten und „Leer“ die erfolglosen Ausfahrtsversuche.

Nutzen Sie die Fälle erst nach eigenen Vorhersagen. Ergänzen Sie weitere Tests, statt nur diese vier Wertefolgen nachzubauen.

Eine mögliche Gesamtlösung — erst nach eigenem Versuch öffnen
#include <stdbool.h>
#include <stdio.h>

int main(void) {
    int kapazitaet = 10;
    int belegt = 7;
    int anzahl_stunden = 4;
    int ankuenfte_pro_stunde = 3;
    int ausfahrten_pro_stunde = 2;
    int max_sensorpruefungen = 3;
    int frei_ab = 2;

    if (kapazitaet < 0 || kapazitaet > 100
        || belegt < 0 || belegt > kapazitaet
        || anzahl_stunden < 0 || anzahl_stunden > 24
        || ankuenfte_pro_stunde < 0 || ankuenfte_pro_stunde > 100
        || ausfahrten_pro_stunde < 0 || ausfahrten_pro_stunde > 100
        || max_sensorpruefungen < 1 || frei_ab < 1) {
        printf("Ungueltige Konfiguration.\n");
        return 1;
    }
    int startbelegung = belegt;
    int eingefahren = 0;
    int ausgefahren = 0;
    int abgewiesen = 0;
    int erfolglose_ausfahrten = 0;

    for (int aktuelle_stunde = 1;
         aktuelle_stunde <= anzahl_stunden;
         aktuelle_stunde++) {
        for (int ausfahrtsversuch = 1;
             ausfahrtsversuch <= ausfahrten_pro_stunde;
             ausfahrtsversuch++) {
            if (belegt > 0) {
                belegt--;
                ausgefahren++;
            } else {
                erfolglose_ausfahrten++;
            }
        }
        for (int einfahrtsversuch = 1;
             einfahrtsversuch <= ankuenfte_pro_stunde;
             einfahrtsversuch++) {
            if (belegt < kapazitaet) {
                belegt++;
                eingefahren++;
                int pruefungen = 0;
                bool sensor_frei = false;
                do {
                    pruefungen++;
                    sensor_frei = (pruefungen >= frei_ab);
                    printf("Pruefung %d, frei: %d\n", pruefungen, sensor_frei);
                } while (!sensor_frei && pruefungen < max_sensorpruefungen);
                if (!sensor_frei) {
                    printf("Blockiert, Schranke bleibt offen.\n");
                    printf("Eingefahren: %d, belegt: %d\n", eingefahren, belegt);
                    return 1;
                }
                printf("Schliessen erlaubt.\n");
            } else {
                abgewiesen++;
            }
        }
        if (belegt < 0 || belegt > kapazitaet) {
            printf("Fehler: ungueltige Belegung.\n");
            return 1;
        }
        printf("Stunde %d: belegt %d\n", aktuelle_stunde, belegt);
    }
    printf("Eingefahren: %d\n", eingefahren);
    printf("Ausgefahren: %d\n", ausgefahren);
    printf("Abgewiesen: %d\n", abgewiesen);
    printf("Erfolglose Ausfahrten: %d\n", erfolglose_ausfahrten);
    printf("Endbelegung: %d\n", belegt);

    if (belegt != startbelegung + eingefahren - ausgefahren
        || eingefahren + abgewiesen != anzahl_stunden * ankuenfte_pro_stunde
        || ausgefahren + erfolglose_ausfahrten != anzahl_stunden * ausfahrten_pro_stunde) {
        printf("Fehler in der Tagesbilanz.\n");
        return 1;
    }
    return 0;
}

5. Freiwillige Erweiterungen

Die Pflichtaufgabe ist mit einem getesteten Tagesbetrieb und korrekter Bilanz abgeschlossen. Wenn Sie weiterarbeiten möchten, wählen Sie eine Erweiterung:

  • Höchste Belegung: Erfassen Sie den Höchstwert einschließlich der Startbelegung. Er muss mindestens so groß wie Start- und Endbelegung sein und darf die Kapazität nicht überschreiten.
  • Stunden ohne freien Platz: Zählen Sie Stunden, an deren Ende das Parkhaus voll ist. Bei Kapazität 0 zählt jede tatsächlich simulierte Stunde; bei 0 Stunden bleibt der Zähler 0.
  • Wechselnde Ankünfte: Lassen Sie die Zahl pro Stunde variieren, beispielsweise mit basis + ((aktuelle_stunde - 1) % 3). Bei Zählung ab 1 entsteht das Muster basis, basis + 1, basis + 2. Passen Sie die Versuchssummen an: Die Formel mit einer konstanten Rate gilt dann nicht mehr.

Ergänzen Sie passende Tests und dokumentieren Sie Ihre zusätzliche Regel. Entscheidend sind nachvollziehbare Anforderungen und begründete Tests, nicht die Übereinstimmung Ihrer Schleifenform mit der Musterlösung.
