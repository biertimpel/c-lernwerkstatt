While-Schleifen

Die Einfahrt funktioniert für ein Fahrzeug. Jetzt sollen mehrere wartende Fahrzeuge nacheinander verarbeitet werden.

Lernziele und Materialien

  • while- und do-while-Schleifen einschließlich ihrer Zustandsänderungen nachvollziehen.
  • Schleifen mit null oder mindestens einem Durchlauf unterscheiden und umformulieren.
  • Unbeabsichtigte Endlosschleifen erkennen und gewollten Dauerbetrieb einordnen.

Voraussetzung: Entscheidungen treffen. Die Parkhausregeln bleiben bestehen: Die Belegung liegt stets zwischen 0 und der Kapazität.

Arbeiten Sie in Ihrem bisherigen Parkhausordner mit Ihrer programm.c und demselben Makefile weiter. Sichern Sie vor größeren Änderungen eine Kopie Ihres funktionierenden Stands. Speichern Sie Änderungen, übersetzen Sie mit make und starten Sie mit ./programm. Beginnen Sie mit kleinen Testwerten. Auch die Sensorprüfung ergänzen Sie in dieser Datei; ein neues Gerüst ist nicht nötig.

1. Wiederholen, solange eine Bedingung gilt

while prüft seine Bedingung vor jedem Durchlauf. Ist sie falsch, wird der Schleifenrumpf übersprungen und das Programm läuft hinter der Schleife weiter. Anders als if prüft while nach dem Block erneut.

Ein einfaches Beispiel zählt von 3 herunter. Es zeigt die drei Bestandteile einer Schleife: Anfangszustand, Bedingung und Zustandsänderung.

int zahl = 3;

while (zahl > 0) {
    printf("%d\n", zahl);
    zahl = zahl - 1;
}
printf("Fertig.\n");

int zahl = 3; legt den Anfangszustand fest. zahl > 0 entscheidet vor jedem Durchlauf, ob es weitergeht. Die Zuweisung im Rumpf verringert den Wert um 1. Ohne passende Zustandsänderung endet eine Schleife möglicherweise nie. Nach ihrem Ende geht es mit der Ausgabe „Fertig.“ weiter.

Vorhersage: Welche vollständige Ausgabe entsteht? Erstellen Sie eine Tabelle mit den Spalten „zahl vor Prüfung“, „Bedingung wahr?“ und „zahl nach Durchlauf“. Wie oft wird die Bedingung geprüft, und wie oft läuft der Rumpf?

Erklärung anzeigen

Die ersten beiden Antworten stimmen: 0 und -1 sind nicht größer als 0. Bei Startwert 1 gibt es genau einen Durchlauf. „Fertig.“ erscheint in allen drei Fällen.

Programmieraufgabe: Eine Warteschlange abarbeiten

Erweitern Sie Ihre Ereignisverarbeitung aus „Entscheidungen treffen“. Der Code 1 soll jetzt eine ganze Warteschlange statt eines einzelnen Fahrzeugs verarbeiten. Die Fälle für Ausfahrt, Status und unbekannte Codes bleiben erhalten.

  1. Ergänzen Sie eine int-Variable wartende (initial auf 5) und einen Zähler für erfolgreiche Einfahrten. Erweitern Sie Ihre vorhandene Startwertprüfung: Auch negative Wartendenzahlen sind ungültig.
  2. Ersetzen Sie in case 1 die bisherige einzelne Einfahrtsentscheidung durch eine passende while-Schleife. Lassen Sie Fahrzeuge einfahren, solange Platz ist und Fahrzeuge warten. Formulieren Sie selbst die Bedingung und die nötigen Zustandsänderungen. Zählen Sie die erfolgreichen Einfahrten. Geben Sie nach jedem Durchlauf den Zustand und zum Schluss dieses Falls die Bilanz aus.
  3. Setzen Sie für Ihre Tests ereignis = 1. Testen Sie bei Kapazität 10 die Paare belegt/wartende: 7/5, 9/1, 10/3 und 0/0. Ergänzen Sie einen Fall, in dem die Warteschlange endet, obwohl noch Platz ist. Notieren Sie Erwartungen vor dem Ausführen. Prüfen Sie anschließend, ob die anderen Ereigniscodes weiterhin korrekt funktionieren.
Hinweis

Initialisieren Sie den Einfahrtszähler vor der Schleife mit 0. Erhöhen Sie ihn nur dann, wenn ein Fahrzeug wirklich einfährt. Eine verbleibende Warteschlange ist ein reguläres Ergebnis.

Drei Fahrzeuge fahren ein. Zwei warten weiter, weil das Parkhaus voll ist. Die Bedingung wird viermal geprüft, der Rumpf dreimal ausgeführt.

Mögliche Lösung
#include <stdio.h>

int main(void) {
    int kapazitaet = 10;
    int belegt = 7;
    int wartende = 5;
    int ereignis = 1;
    int eingefahren = 0;
    if (kapazitaet < 0 || belegt < 0 || belegt > kapazitaet || wartende < 0) {
        printf("Ungueltige Startwerte.\n");
        return 1;
    }
    switch (ereignis) {
        case 1:
            while ((wartende > 0) && (belegt < kapazitaet)) {
                belegt = belegt + 1;
                wartende = wartende - 1;
                eingefahren = eingefahren + 1;
                printf("Belegt: %d, wartend: %d\n", belegt, wartende);
            }
            printf("Eingefahren: %d, belegt: %d, wartend: %d\n",
                   eingefahren, belegt, wartende);
            break;
        case 2:
            if (belegt > 0) {
                belegt = belegt - 1;
                printf("Ausfahrt erlaubt.\n");
            } else {
                printf("Parkhaus leer.\n");
            }
            break;
        case 3:
            printf("Statusabfrage.\n");
            break;
        default:
            printf("Unbekannter Ereigniscode.\n");
            return 1;
    }
    printf("Belegt: %d\n", belegt);
    return 0;
}

Für die vorgegebenen Paare: 3, 1, 0 und 0 Einfahrten. Bei 7/2 fahren beide Fahrzeuge ein und ein Platz bleibt frei.

2. Mindestens einmal: do while

Vor dem Schließen der Schranke zum Parkhaus muss der Sicherheitsbereich mindestens einmal geprüft werden. Wir simulieren einen Sensor: Ab der zweiten Prüfung meldet er „frei“. Es werden höchstens drei Prüfungen durchgeführt. Es handelt sich um eine Simulation zu Demonstrationszwecken, nicht um eine echte Schrankensteuerung.

int pruefungen = 0;
int maximum = 3;
int frei_ab = 2;
bool sensor_frei = false;

do {
    pruefungen = pruefungen + 1;
    sensor_frei = (pruefungen >= frei_ab);
    printf("Pruefung %d, frei: %d\n", pruefungen, sensor_frei);
} while (!sensor_frei && pruefungen < maximum);

Für bool benötigen Sie weiterhin <stdbool.h>. Bei do while kommt die Prüfung nach dem Rumpf. Dieser läuft also mindestens einmal, selbst wenn die Bedingung danach sofort falsch ist. Das Semikolon hinter while (...); gehört hier zur Syntax.

Vorhersage: Wie viele Prüfungen erfolgen bei frei_ab = 1, 2 und 5 mit Maximum 3?

Selbstkontrolle

1, 2 und 3 Prüfungen. Im letzten Fall bleibt der Sensor blockiert. Das Erreichen des Versuchslimits ist keine Erfolgsmeldung: Die Schranke muss offen bleiben.

Programmieraufgabe: Prüfen mit Versuchslimit

Ergänzen Sie zwei Konfigurationsvariablen vom Datentyp int, die für alle Fahrzeuge gelten:

  • int maximum = 3;: Die maximale Anzahl der Sensorprüfungen pro Fahrzeug. Ist der Sicherheitsbereich danach noch blockiert, wird die Simulation mit einer Fehlermeldung beendet.
  • int frei_ab = 2;: Die Nummer der Prüfung, ab der der simulierte Sensor „frei“ meldet. Bei diesem Startwert meldet er bei der ersten Prüfung „blockiert“ und ab der zweiten „frei“. Die Prüfungen werden für jedes Fahrzeug neu ab 1 gezählt.

Beide Werte müssen mindestens 1 sein. frei_ab darf größer als maximum sein: Damit simulieren Sie, dass der Sensor innerhalb des Versuchslimits nicht frei wird.

Erweitern Sie Ihre aktuelle programm.c: Nach jeder erfolgreichen Einfahrt soll der Sicherheitsbereich geprüft werden, bevor das nächste Fahrzeug einfahren darf. Die Einfahrt ist zu diesem Zeitpunkt bereits erfolgt: Belegung und Einfahrtszähler sind erhöht. Eine abgewiesene Einfahrt löst keine Sensorprüfung aus.

  1. Ergänzen Sie <stdbool.h> und die Konfiguration maximum und frei_ab. Erweitern Sie die vorhandene Startwertprüfung: Beide Werte müssen mindestens 1 sein.
  2. Setzen Sie die Sensorprüfung als do-while-Schleife innerhalb Ihrer Warteschleife um, direkt nach der erfolgreichen Einfahrt. Initialisieren Sie pruefungen = 0 und sensor_frei = false für jedes Fahrzeug neu.
  3. Ist der Sensor frei, melden Sie „Schließen erlaubt“ und verarbeiten das nächste Fahrzeug. Bleibt er nach dem Versuchslimit blockiert, melden Sie „Blockiert, Schranke bleibt offen“, geben den aktuellen Zustand aus und beenden die Simulation mit return 1;. Nehmen Sie die bereits erfolgte Einfahrt nicht zurück.
  4. Testen Sie sofortigen Erfolg, Erfolg bei der letzten erlaubten Prüfung, erfolgloses Erreichen des Limits und ungültige Startwerte. Prüfen Sie mit mehreren Einfahrten, ob der Versuchszähler jeweils neu beginnt. Testen Sie auch eine volle Belegung: Ohne Einfahrt darf keine Sensorprüfung erfolgen.
Mögliche Lösung
#include <stdbool.h>
#include <stdio.h>

int main(void) {
    int kapazitaet = 10;
    int belegt = 7;
    int wartende = 5;
    int ereignis = 1;
    int eingefahren = 0;
    int maximum = 3;
    int frei_ab = 2;
    if (kapazitaet < 0 || belegt < 0 || belegt > kapazitaet
        || wartende < 0 || maximum < 1 || frei_ab < 1) {
        printf("Ungueltige Startwerte.\n");
        return 1;
    }
    switch (ereignis) {
        case 1:
            while ((wartende > 0) && (belegt < kapazitaet)) {
                belegt = belegt + 1;
                wartende = wartende - 1;
                eingefahren = eingefahren + 1;
                printf("Belegt: %d, wartend: %d\n", belegt, wartende);
                int pruefungen = 0;
                bool sensor_frei = false;
                do {
                    pruefungen = pruefungen + 1;
                    sensor_frei = (pruefungen >= frei_ab);
                    printf("Pruefung %d, frei: %d\n", pruefungen, sensor_frei);
                } while (!sensor_frei && pruefungen < maximum);
                if (!sensor_frei) {
                    printf("Blockiert, Schranke bleibt offen.\n");
                    printf("Eingefahren: %d, belegt: %d, wartend: %d\n",
                           eingefahren, belegt, wartende);
                    return 1;
                }
                printf("Schliessen erlaubt.\n");
            }
            printf("Eingefahren: %d, belegt: %d, wartend: %d\n",
                   eingefahren, belegt, wartende);
            break;
        case 2:
            if (belegt > 0) {
                belegt = belegt - 1;
                printf("Ausfahrt erlaubt.\n");
            } else {
                printf("Parkhaus leer.\n");
            }
            break;
        case 3:
            printf("Statusabfrage.\n");
            break;
        default:
            printf("Unbekannter Ereigniscode.\n");
            return 1;
    }
    printf("Belegt: %d\n", belegt);
    return 0;
}

Code verbessern: Sprechende Namen wählen. Der Name maximum verrät nicht, was begrenzt wird. Wählen Sie einen aussagekräftigeren Namen, der die maximale Anzahl der Sensorprüfungen beschreibt. Benennen Sie die Variable in Ihrer programm.c konsequent um — in der Deklaration, der Startwertprüfung und der Schleifenbedingung. Übersetzen Sie erneut und wiederholen Sie Ihre Tests: Die Umbenennung soll die Lesbarkeit verbessern, aber das Verhalten nicht verändern.

Mehrere Wege: dieselbe Aufgabe mit while

Die Sensorprüfung lässt sich auch mit einer while-Schleife umsetzen. Entwickeln Sie diese Variante selbst in Ihrer bisherigen programm.c. Sie soll für alle zulässigen Startwerte dieselben Prüfungen und Meldungen wie Ihre do-while-Version erzeugen.

  1. Sichern Sie Ihre funktionierende do-while-Version. Überlegen Sie vor dem Umbau: Welche Werte haben Versuchszähler und Sensorzustand unmittelbar vor der ersten Prüfung? Wie stellen Sie sicher, dass diese Prüfung auch bei while stattfindet?
  2. Ersetzen Sie ausschließlich die innere Sensorprüfung durch eine while-Schleife. Formulieren Sie deren Bedingung selbst. Behalten Sie Ihre sprechenden Variablennamen, die Initialisierung pro Fahrzeug, die äußere Warteschleife und die Fehlerbehandlung bei.
  3. Vergleichen Sie beide Versionen mit denselben Testfällen: sofort freier Sensor, Freigabe bei der letzten erlaubten Prüfung, blockierter Sensor und mehrere aufeinanderfolgende Einfahrten. Stimmen Anzahl und Reihenfolge der Prüfungen, Belegung und Rückgabestatus überein?
  4. Erklären Sie, warum die while-Version hier mindestens einmal prüft. Gilt Ihre Begründung auch für jede beliebige do-while-Schleife?
Hinweis

Bei while wird die Bedingung vor dem ersten Durchlauf ausgewertet. Prüfen Sie deshalb nicht nur den Schleifenrumpf, sondern auch, ob Ihre Anfangswerte die Bedingung bereits erfüllen.

Selbstkontrolle

Der Versuchszähler beginnt für jedes Fahrzeug bei 0, der Sensorzustand bei falsch. Das geprüfte Versuchslimit ist mindestens 1. Eine Bedingung, die einen noch blockierten Sensor und noch verfügbare Prüfversuche verlangt, ist deshalb vor dem ersten Durchlauf wahr. Nach jedem Durchlauf werden dieselben Werte wie in der do-while-Version geprüft. Das funktioniert wegen dieses Anfangszustands; bei einer anfangs falschen Bedingung würde while den Rumpf überspringen, do while dagegen nicht. Die Umformung ist deshalb keine allgemeine Regel für beliebige do-while-Schleifen.

3. Endlosschleifen: Fehler oder Absicht?

Wenn die Fortschaltung fehlt

while (wartende > 0) {
    printf("Es warten %d Fahrzeuge.\n", wartende);
}

Fehlersuche: Warum endet diese Schleife bei wartende = 2 nicht? Was fehlt neben der Änderung von wartende, damit unsere Parkhausregeln erhalten bleiben?

Erklärung anzeigen

Wartende wird nie verändert. Außerdem müssen freie Plätze geprüft und bei einer Einfahrt die Belegung erhöht werden. Nur einen Zähler zu ändern genügt nicht, wenn dadurch die Kapazität überschritten wird.

Weitere häufige Fehler: ein versehentliches Semikolon hinter while (...), ein Zähler in der falschen Richtung oder ein Zurücksetzen im Schleifenrumpf. Auch ODER statt UND kann den Abbruch verhindern. Fragen Sie: Welche Variable verändert die Bedingung, und wodurch wird sie irgendwann falsch?

Wenn das Parkhaus dauerhaft geöffnet ist

Eine echte Steuerung soll möglicherweise dauerhaft Ereignisse verarbeiten. Dann ist eine Schleife mit absichtlich immer wahrer Bedingung sinnvoll. Diese kleine Simulation verwendet trotzdem ein kontrolliertes Ende nach sechs Ereignissen:

#include <stdbool.h>
#include <stdio.h>

int main(void) {
    int verarbeitet = 0;
    while (true) {
        if (verarbeitet >= 6) {
            break; /* Simuliertes Abschaltsignal. */
        }
        printf("Ereignis %d verarbeiten.\n", verarbeitet + 1);
        verarbeitet = verarbeitet + 1;
    }
    printf("Geordnet beendet.\n");
    return 0;
}

Im echten Betrieb käme das Ende beispielsweise durch ein Abschaltsignal, und die Ereignisverarbeitung würde Ein- und Ausfahrten behandeln. Auf neue Ereignisse würde man warten, statt ohne Pause immer wieder denselben Zustand zu prüfen: Eine leere Dauerschleife kann einen Prozessorkern auslasten. Die dafür nötigen Betriebssystemwerkzeuge sind hier noch nicht Thema.

Zum Abbrechen eines versehentlich endlosen Terminalprogramms verwenden Sie Ctrl+C. Das ist kein geordnetes Programmende. Testen Sie zunächst mit begrenzten Durchläufen und Zustandsausgaben; entfernen Sie die Abbruchgrenze nicht unüberlegt.
