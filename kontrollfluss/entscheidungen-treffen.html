Entscheidungen treffen

Aus einer Bedingung wird eine Handlung: Wir beginnen eine Parkhaus-Simulation und entscheiden, ob ein Fahrzeug einfahren darf.

Lernziele und Ausgangspunkt

  • Mit if, else und else if zwischen Handlungen wählen.
  • Einzelne Werte mit switch und case unterscheiden.
  • Ungültige Zustände erkennen und gezielt Grenzfälle testen.

Im gesamten Kapitel erweitern Sie dasselbe Modell: kapazitaet ist die Anzahl der Plätze, belegt die aktuelle Anzahl der Fahrzeuge. Es soll immer 0 <= belegt und belegt <= kapazitaet gelten. Diese dauerhaft einzuhaltende Regel heißt Invariante. Wir verwenden kleine ganze Zahlen und fest eingetragene Startwerte, noch keine Tastatureingabe.

C-Gerüste und Makefiles herunterladen (ZIP). Entpacken Sie das Archiv und öffnen Sie ein Terminal im jeweiligen Aufgabenordner. Bearbeiten und speichern Sie programm.c, übersetzen Sie mit make und starten Sie mit ./programm. Nach Änderungen erneut übersetzen.

1. Eine Entscheidung mit if und else

if führt seinen Anweisungsblock in geschweiften Klammern aus, wenn die Bedingung in den runden Klammern zu wahr auswertet. Der optionale else-Block wird andernfalls ausgeführt. Genau einer der beiden Blöcke läuft, nach der Verzweigung geht es gemeinsam weiter.

Das folgende einfache Beispiel prüft, ob eine Zahl gleich null ist. Die Bedingung steht in runden Klammern, die zugehörigen Anweisungen stehen jeweils in einem Block aus geschweiften Klammern.

int zahl = 3;

if (zahl == 0) {
    printf("Die Zahl ist null.\n");
} else {
    printf("Die Zahl ist nicht null.\n");
}
printf("Pruefung beendet.\n");

Ohne else passiert bei falscher Bedingung in der Verzweigung nichts. Verwenden Sie auch bei nur einer Anweisung geschweifte Klammern und rücken Sie den Block ein. Das macht spätere Ergänzungen sicherer.

Welche Aussagen zum Beispiel stimmen?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

1, 3 und 4 stimmen. Bei zahl = 3 ist die Bedingung falsch und nur der else-Block läuft. Bei zahl = 0 ist sie wahr und nur der if-Block läuft. Danach erscheint in beiden Fällen „Pruefung beendet.“.

Programmieraufgabe: Eine Einfahrt verarbeiten

Gehen Sie zum Ordner entscheidungen-treffen/01-einfahrt. Dort finden Sie die Dateien programm.c und Makefile.

  1. Schreiben Sie die Entscheidung für genau ein ankommendes Fahrzeug selbst. Erstellen Sie eine Ausgabe, ob es einfahren darf ("Einfahrt erlaubt." oder "Parkhaus voll."), und geben Sie die neue Belegung aus.
  2. Notieren Sie erwartete Ergebnisse für die Startbelegungen 0, 9 und 10 bei Kapazität 10. Prüfen Sie alle drei Fälle.
  3. Ergänzen Sie vor der Einfahrt eine Prüfung: Negative Kapazität, negative Belegung oder Belegung über der Kapazität sind ungültig. Geben Sie eine Fehlermeldung aus und beenden Sie main mit return 1;. Testen Sie jeden Fehlerfall. Kapazität 0 ist gültig, erlaubt aber keine Einfahrt.

return 1; beendet das Programm an dieser Stelle mit einem Fehlerstatus; return 0; meldet weiterhin einen erfolgreichen Ablauf. Eine abgewiesene Einfahrt bei vollem Parkhaus ist ein normaler Fall, kein ungültiger Programmzustand.

Hinweis

Prüfen Sie die ungültigen Startwerte mit ODER. Beenden Sie das Programm, bevor Sie die Belegung verändern. Für die Einfahrt muss der Vergleich strikt kleiner sein.

Mögliche Lösung
#include <stdio.h>

int main(void) {
    int kapazitaet = 10;
    int belegt = 7;
    if (kapazitaet < 0 || belegt < 0 || belegt > kapazitaet) {
        printf("Ungueltige Startwerte.\n");
        return 1;
    }
    if (belegt < kapazitaet) {
        belegt = belegt + 1;
        printf("Einfahrt erlaubt.\n");
    } else {
        printf("Parkhaus voll.\n");
    }
    printf("Belegt: %d\n", belegt);
    return 0;
}

Für 0, 9 und 10 ergeben sich die Endbelegungen 1, 10 und 10. Nur im letzten Fall wird abgewiesen.

2. Mehrere Fälle mit else if

Die Parkhausanzeige soll „leer“, „Plätze frei“ oder „voll“ melden. Eine else if-Kette prüft von oben nach unten. Nur der erste zutreffende Block wird ausgeführt, else fängt den Rest auf.

if (belegt == 0) {
    printf("Leer.\n");
} else if (belegt < kapazitaet) {
    printf("Plaetze frei.\n");
} else {
    printf("Voll.\n");
}

Hier müssen die Startwerte bereits gültig sein. Bei Kapazität 0 und Belegung 0 gilt sowohl „leer“ als auch „voll“; unsere Anzeige priorisiert ausdrücklich „leer“. Solche Entscheidungen über Randfälle gehören zur Aufgabenbeschreibung.

Selbst ausprobieren: Ergänzen Sie die Anzeige nach der Einfahrt. Welche Startbelegung benötigen Sie, um nach der Einfahrt eines weiteren Autos „voll“ zu sehen? Wie unterscheidet sich die Anzeige, wenn Sie drei unabhängige if-Anweisungen statt einer Kette verwenden?

Mögliche Lösung

Startbelegung 9 führt nach der Einfahrt zu 10 und damit zu „voll“. Unabhängige if-Anweisungen können mehrere Meldungen erzeugen: Bei Belegung 0 und Kapazität 10 gelten beispielsweise sowohl belegt == 0 als auch belegt < kapazitaet. Die Kette wählt dagegen nur die erste Meldung.

3. Ereignisse mit switch-case auswählen

Für einzelne Ereigniscodes eignet sich switch: 1 bedeutet Einfahrt, 2 Ausfahrt und 3 Statusabfrage. Im Gegensatz zu einer if-Kette wird ein ganzzahliger Wert mit festen case-Werten verglichen, nicht mit beliebigen Bedingungen oder Wertebereichen. Auch char ist möglich, Gleitkommazahlen und Zeichenketten dagegen nicht.

int ereignis = 1;

switch (ereignis) {
    case 1:
        printf("Einfahrt angefordert.\n");
        break;
    case 2:
        printf("Ausfahrt angefordert.\n");
        break;
    case 3:
        printf("Belegt: %d\n", belegt);
        break;
    default:
        printf("Unbekannter Ereigniscode.\n");
        break;
}

break verlässt hier den switch-Block, nicht das Programm. Ohne break läuft die Ausführung in den nächsten Fall weiter, ohne dessen Wert erneut zu vergleichen. Das nennt sich Fall-through. Das kann gewollt sein, wäre hier aber ein Fehler. default verarbeitet unbekannte Codes. Ohne default würde bei einem unbekannten Code nichts im switch passieren.

Gute Programmierpraxis: Ergänzen Sie einen abschließenden default-Fall, um auch unerwartete Werte ausdrücklich zu behandeln. So werden unbekannte Ereigniscodes nicht stillschweigend ignoriert, sondern beispielsweise mit einer verständlichen Fehlermeldung sichtbar gemacht.

Was gilt für diesen switch?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

1 und 3 stimmen. case benötigt einen ganzzahligen konstanten Ausdruck; ein Vergleich veränderlicher Variablen gehört in if.

Programmieraufgabe: Ein Ereignis, drei mögliche Handlungen

Arbeiten Sie mit Ihrer bisherigen programm.c und dem vorhandenen Makefile weiter. Ihre Startwertprüfung und die Einfahrtsentscheidung bleiben erhalten. Ergänzen Sie die Variable ereignis und erweitern Sie das Programm so, dass es mit switch zwischen Einfahrt, Ausfahrt und Statusabfrage unterscheidet.

Implementieren Sie die Codes 1, 2 und 3. Bauen Sie Ihre bisherige Einfahrtsentscheidung in case 1 ein. Bei Ausfahrt prüfen Sie, ob überhaupt ein Fahrzeug im Parkhaus ist. Unbekannte Codes sollen eine Fehlermeldung und Fehlerstatus 1 ergeben, ohne die Belegung zu ändern. Geben Sie nach gültigen Ereignissen die Belegung aus.

Planen Sie vor dem Programmieren Tests für Einfahrt bei voller Belegung, Ausfahrt bei leerem Parkhaus, normale Ein- und Ausfahrt, Statusabfrage und einen unbekannten Code. Schreiben Sie erwartete Meldung, Endbelegung und Rückgabestatus auf.

Mögliche Lösung
#include <stdio.h>

int main(void) {
    int kapazitaet = 10;
    int belegt = 7;
    int ereignis = 1;
    if (kapazitaet < 0 || belegt < 0 || belegt > kapazitaet) {
        printf("Ungueltige Startwerte.\n");
        return 1;
    }
    switch (ereignis) {
        case 1:
            if (belegt < kapazitaet) {
                belegt = belegt + 1;
                printf("Einfahrt erlaubt.\n");
            } else {
                printf("Parkhaus voll.\n");
            }
            break;
        case 2:
            if (belegt > 0) {
                belegt = belegt - 1;
                printf("Ausfahrt erlaubt.\n");
            } else {
                printf("Parkhaus leer.\n");
            }
            break;
        case 3:
            printf("Statusabfrage.\n");
            break;
        default:
            printf("Unbekannter Ereigniscode.\n");
            return 1;
    }
    printf("Belegt: %d\n", belegt);
    return 0;
}

4. Fehler suchen und Entscheidungen lesbar halten

Fehler gehören zum Programmieren dazu — auch erfahrenen Programmierer*innen passieren sie. Wichtig ist, sie systematisch zu finden und zu verstehen. Üben Sie die Fehlersuche deshalb von Anfang an: Vergleichen Sie Ihre Erwartungen mit dem tatsächlichen Verhalten und untersuchen Sie gezielt, wo die erste Abweichung entsteht.

Finden Sie die Fehler: Hier soll nur bei freien Plätzen eine Einfahrt stattfinden.

if (belegt <= kapazitaet);
{
    belegt = belegt + 1;
}
Auflösung

Das Semikolon beendet die if-Anweisung mit einer leeren Anweisung. Der folgende Block läuft immer. Außerdem erlaubt <= eine Einfahrt auch bei voller Belegung. Entfernen Sie das Semikolon und verwenden Sie <. Testen Sie insbesondere die volle Belegung.

Achten Sie auch auf = statt ==: Eine Zuweisung in einer Bedingung verändert einen Wert und wird von C häufig akzeptiert. Lesen Sie Compilerwarnungen, verwenden Sie aussagekräftige Namen und geben Sie bei der Fehlersuche Zustand vor und nach der Entscheidung aus. Die bereitgestellten Makefiles aktivieren -Wall -Wextra.

Es gibt mehrere richtige Strukturen: Die Ereigniscodes können Sie auch mit einer if-else-if-Kette behandeln. switch ist für feste Einzelwerte übersichtlich, if ist für Bereiche und zusammengesetzte Bedingungen flexibler. Entscheidend sind korrekte Regeln und verständlicher Code.
