For-Schleifen

Jetzt beobachten wir das Parkhaus über eine festgelegte Anzahl von Betriebsstunden. Dafür bietet sich eine Zählschleife an.

Lernziele und Materialien

  • Initialisierung, Bedingung und Fortschaltung einer for-Schleife erklären.
  • Zählabläufe und Bilanzen implementieren und typische Grenzfehler finden.
  • for- und while-Schleifen ineinander überführen.

Arbeiten Sie an Ihrer bisherigen Parkhausdatei programm.c einschließlich der integrierten Sensorprüfung mit dem vorhandenen Makefile weiter. Sichern Sie den funktionierenden Stand vor dem Umbau. Verwenden Sie nach dem Speichern wie bisher make und ./programm. Ein neues Gerüst ist nicht nötig.

1. Einen Zählablauf übersichtlich schreiben

Bei einer for-Schleife stehen drei Teile im Schleifenkopf: for (Initialisierung; Bedingung; Fortschaltung). Die Initialisierung passiert einmal. Vor jedem Durchlauf wird die Bedingung geprüft; nach jedem vollständig ausgeführten Rumpf folgt die Fortschaltung.

int anzahl_stunden = 4;

for (int aktuelle_stunde = 1;
     aktuelle_stunde <= anzahl_stunden;
     aktuelle_stunde++) {
    printf("Betriebsstunde %d\n", aktuelle_stunde);
}

anzahl_stunden legt fest, wie viele Stunden verarbeitet werden. aktuelle_stunde zählt von 1 bis einschließlich 4 und wird direkt ausgegeben. Die unterschiedlichen Namen machen die Rollen sichtbar. aktuelle_stunde++ erhöht den Zähler um 1, wie die eigenständige Anweisung aktuelle_stunde = aktuelle_stunde + 1;. Entsprechend verringert aktuelle_stunde-- ihn um 1. Die im Schleifenkopf deklarierte Variable ist nur innerhalb dieser Schleife sichtbar. Die Zeilenumbrüche im Schleifenkopf dienen lediglich der Lesbarkeit.

Die Reihenfolge ist also: Initialisierung → Prüfung → Rumpf → Fortschaltung → erneute Prüfung. Ist die Bedingung anfangs falsch, gibt es wie bei while keinen Durchlauf.

Was gilt für das Beispiel?

Eine oder mehrere Antworten können richtig sein.

Erklärung anzeigen

1 und 3 stimmen. Mit <= werden die Werte 1 bis 4 verarbeitet, mit < nur 1 bis 3. Bei 0 Stunden ist bereits die erste Prüfung 1 <= 0 falsch. Die Initialisierung findet nur einmal statt.

Dieselbe Anzahl von Durchläufen ab 0 zählen

Alternativ kann ein Index bei 0 beginnen. Dann verwenden wir eine strikt kleinere Grenze und rechnen nur für die Anzeige 1 hinzu:

int anzahl_stunden = 4;

for (int stunden_index = 0;
     stunden_index < anzahl_stunden;
     stunden_index++) {
    printf("Betriebsstunde %d\n", stunden_index + 1);
}

Der Index durchläuft 0, 1, 2 und 3; angezeigt werden wieder 1 bis 4. Beide Zählweisen sind richtig. Entscheidend ist, dass Anfangswert, Vergleich und Ausgabe zusammenpassen. In der folgenden Parkhausaufgabe verwenden wir die Zählung ab 1.

Schrittweite und Richtung

Nicht jeder Ablauf zählt in Einerschritten aufwärts. Dieses Beispiel prüft absteigend die geraden Platznummern. Die Zählschritte ändern hier keine tatsächliche Belegung:

for (int platz = 10; platz >= 2; platz = platz - 2) {
    printf("Platz %d pruefen.\n", platz);
}

Selbstkontrolle: Welche Nummern erscheinen? Was ändert platz > 2?

Antwort anzeigen

10, 8, 6, 4 und 2. Mit > 2 entfällt die letzte Ausgabe 2. Richtung, Schrittweite und Grenze müssen zusammenpassen.

2. Programmieraufgabe: Eine Bilanz über mehrere Stunden

Wir erweitern die bisherige Einfahrt: Pro Betriebsstunde kommt genau ein Fahrzeug an. Es fährt ein, wenn Platz vorhanden ist; andernfalls wird es abgewiesen. Anders als bei der Warteschlangenaufgabe warten abgewiesene Fahrzeuge hier nicht weiter. Es gibt in dieser Teilaufgabe keine Ausfahrten.

Bauen Sie Ihren bisherigen Stand um: Statt einmal einen Ereigniscode auszuwählen, verarbeitet das Programm nun einen festen Stundenplan. Ersetzen Sie dazu die bisherige switch-Auswahl samt Warteschleife durch eine Stundenschleife. Verwenden Sie Ihre vorhandene Einfahrtsregel und den Einfahrtszähler weiter. Entfernen Sie die hier nicht mehr benötigten Variablen ereignis und wartende sowie deren Prüfungen.

Behalten Sie die Sensorprüfung direkt nach jeder erfolgreichen Einfahrt bei, einschließlich der Initialisierung pro Fahrzeug und des Fehlerabbruchs bei blockierter Schranke. Verwenden Sie für die regulären Bilanztests maximum = 3 und frei_ab = 2. Testen Sie den Sensorfehler zusätzlich getrennt; nach einem solchen Abbruch wird keine vollständige Stundenbilanz erwartet.

  1. Ergänzen Sie anzahl_stunden und erweitern Sie Ihre vorhandene Startwertprüfung. Zulässig sind eine nichtnegative Kapazität, eine passende Belegung und 0 bis 24 Betriebsstunden. Bei ungültigen Werten: Meldung und return 1;.
  2. Verarbeiten Sie mit for pro Stunde einen Einfahrtsversuch. Zählen Sie erfolgreiche und abgewiesene Einfahrten getrennt. Geben Sie pro Stunde die Entscheidung und die Belegung aus.
  3. Erweitern Sie Ihre Abschlussbilanz und testen Sie selbst gewählte Fälle: keine Stunden, genau eine Stunde, mehr Ankünfte als freie Plätze und von Beginn an volles Parkhaus.

Prüfen Sie zusätzlich zwei Zusammenhänge: eingefahren + abgewiesen == anzahl_stunden und belegt == startbelegung + eingefahren. Das sind stärkere Kontrollen als nur ein plausibel aussehender Endwert.

Hinweis

Initialisieren Sie die Bilanzzähler einmal vor der Schleife. Die Entscheidung aus „Entscheidungen treffen“ gehört in den Rumpf. Ändern Sie den Stundenzähler nicht zusätzlich im Rumpf.

Mögliche Lösung
#include <stdbool.h>
#include <stdio.h>

int main(void) {
    int kapazitaet = 10;
    int belegt = 7;
    int anzahl_stunden = 5;
    int maximum = 3;
    int frei_ab = 2;
    int eingefahren = 0;
    int abgewiesen = 0;
    int startbelegung = belegt;
    if (kapazitaet < 0 || belegt < 0 || belegt > kapazitaet
        || anzahl_stunden < 0 || anzahl_stunden > 24 || maximum < 1 || frei_ab < 1) {
        printf("Ungueltige Startwerte.\n");
        return 1;
    }
    for (int aktuelle_stunde = 1;
         aktuelle_stunde <= anzahl_stunden;
         aktuelle_stunde++) {
        if (belegt < kapazitaet) {
            belegt = belegt + 1;
            eingefahren = eingefahren + 1;
            printf("Stunde %d: Einfahrt erlaubt.\n", aktuelle_stunde);
            int pruefungen = 0;
            bool sensor_frei = false;
            do {
                pruefungen++;
                sensor_frei = (pruefungen >= frei_ab);
                printf("Pruefung %d, frei: %d\n", pruefungen, sensor_frei);
            } while (!sensor_frei && pruefungen < maximum);
            if (!sensor_frei) {
                printf("Blockiert, Schranke bleibt offen.\n");
                printf("Eingefahren: %d, belegt: %d\n", eingefahren, belegt);
                return 1;
            }
            printf("Schliessen erlaubt.\n");
        } else {
            abgewiesen = abgewiesen + 1;
            printf("Stunde %d: abgewiesen.\n", aktuelle_stunde);
        }
        printf("Belegt: %d\n", belegt);
    }
    printf("Bilanz: eingefahren %d, abgewiesen %d, belegt %d\n",
           eingefahren, abgewiesen, belegt);
    if (eingefahren + abgewiesen != anzahl_stunden
        || belegt != startbelegung + eingefahren) {
        printf("Fehler in der Bilanz.\n");
        return 1;
    }
    return 0;
}

Mit den Startwerten fahren drei Fahrzeuge ein, zwei werden abgewiesen, am Ende sind zehn Plätze belegt. Bei null Stunden bleiben alle Bilanzzähler 0 und die Startbelegung unverändert.

3. Mehrere Wege: for als while schreiben

Die Stundenübersicht vom Anfang kann genauso mit while formuliert werden. Initialisierung und Fortschaltung stehen dann an anderen Stellen:

int aktuelle_stunde = 1;
while (aktuelle_stunde <= anzahl_stunden) {
    printf("Betriebsstunde %d\n", aktuelle_stunde);
    aktuelle_stunde++;
}

Ändern Sie in Ihrer aktuellen programm.c nur die Stundenschleife von for zu while; Startwertprüfung, Einfahrtsentscheidung und Bilanz bleiben erhalten. Verwenden Sie dieselben Tests und vergleichen Sie Meldungen, Bilanz und Endbelegung. Lassen Sie die Fortschaltung dabei nicht versehentlich weg.

Selbstkontrolle

Beide Varianten verarbeiten dieselben Stunden, wenn Startwert, Prüfung, Rumpf und Fortschaltung gleich bleiben. Bei for bleibt der Zählablauf kompakt zusammen; while eignet sich oft gut für Abläufe, deren Ende vom Zustand abhängt. Das ist eine Lesbarkeitsentscheidung, keine strikte Grenze der Möglichkeiten.

Die einfache Umformung gilt hier ohne continue. Dieser zusätzliche Schleifenbefehl überspringt den Rest des Rumpfs: Bei for folgt dann noch die Fortschaltung im Kopf, bei while würde eine Fortschaltung am Rumpfende übersprungen. Wir verwenden continue in diesen Aufgaben nicht.

Finden Sie den Fehler: Drei Einfahrtsversuche sollen verarbeitet werden. Wie viele sind es hier?

for (int versuch = 0; versuch <= 3; versuch++) {
    printf("Versuch %d\n", versuch);
}
Auflösung

Es sind vier: 0, 1, 2 und 3. Verwenden Sie entweder Start 0 mit versuch < 3 oder Start 1 mit versuch <= 3. Beide Wege sind richtig, wenn Zählweise und Ausgabe zusammenpassen.

Schleifen mit falscher Zählrichtung sollten Sie nicht bis zum Überlauf laufen lassen: Überlauf vorzeichenbehafteter Ganzzahlen ist in C undefiniertes Verhalten. Stoppen Sie einen festhängenden Lauf mit Ctrl+C. Verwenden Sie kleine Werte, lesen Sie Warnungen und verfolgen Sie die erste Abweichung statt nur den Endwert.

Auch for (;;) ist möglich: Die ausgelassene Bedingung gilt als wahr. Das ist eine weitere Schreibweise für gewollten Dauerbetrieb, ersetzt aber weder eine Ereignisverarbeitung noch eine geplante Abschaltmöglichkeit.
